# BeakSight 入力の行がいくつもある登録の画面を試せるようにする（DEF-234）設計書

- 日付: 2026-11-09
- 状態: ユーザーの指示「DEF-234、DEF-235も修正対象として。入力の行がいくつもある登録の画面は普通にある。」（2026-11-09）。方式は設計者の判断（調査の推奨）
- 関係する文書: `2026-11-08-beaksight-api-array-keys-design.md`（DEF-226。この設計書はその 3.3・3.4 を広げる）
- 調査: INV-234（2026-11-09。仮のサイト、2 つの Chromium、操作さがし → 自動の下書き → 承認 → 書き込みの段まで流した。案は試作の関数で比べた）

## 1. 今の動き（INV-234 の事実）

- 押す前に BeakSight は、見えていて入れられる欄すべて（行ごとの欄も）に印を入れる。
- 1 つの一覧の鍵に欄の印が 1 つで、ほかの要素が空の行（`""`）のとき、要素の数が 1 でないので `SCENARIO_API_ARRAY_ELEMENT_COUNT_MISMATCH` で拒む（実環境の形 1）。
- **穴:** 1 つの一覧に欄の印が 2 つ以上あると、欄に対応づかず「ページが決める一覧」として承認される。書き込みの段では欄に何も入れず、`["",""]` が届く（欄は試されない）。ページが値を別の文字に変えても届く。欄から来た値をページが決めた値として扱う分類の誤り。
- 要素が object の一覧は `SCENARIO_API_ARRAY_NESTED` で拒む。object の中の印は記録されない（実環境の形 3）。

## 2. 採用する設計（案 A を基に、C まで 3 段で）

### 2.1 対応の道（共通）

一覧の要素の位置と欄の対応を、道 `key[i]`（object の一覧は `key[i].name`）で表す。道の作り方・読み方は 1 か所の部品にし、型の記録・承認・digest・照合・データの規則で共用する。

### 2.2 段 A1: 欄が 1 つと空の位置（実環境の形 1）

1. 型の記録: 一覧の鍵に、位置ごとの「印の番号・空の値か・型」を任意の項目で足す（値は残さない。I22）。
2. 欄の対応: 印のある位置を、その欄に対応づける。印のない位置は、空の値（`""` か `null`）のときだけ受け、「空の位置」として承認に入れる。空でないページが決める値が欄の一覧に混ざる形は拒む。
3. **穴を閉じる:** 欄の印が 2 つ以上ある一覧を、ページが決める一覧として受けない。段 A2 までは、対応できない形として拒む（理由は新しい値。下の 2.5）。
4. 送る前の照合: 位置ごとに、欄の位置は生成した値と完全一致、空の位置は承認した空の値と一致、要素の数は承認と同じ。足す・減らす・順を変える・空の位置を埋める・入れ子にする → 送らない。
5. digest: 一覧の中に印がある鍵で要素が 2 以上のときだけ位置の情報を入れる。一覧のない型と、DEF-226 で承認した形（要素 1・印のない一覧）の digest は変えない。

### 2.3 段 A2: 1 つの一覧に欄がいくつも入る（実環境の形 2）

1. 欄ごとに値を作る（データの規則・開始の指定・入力の指定・画面の欄の表示を、道 `key[i]` ごとに）。
2. 照合は 2.2 の 4 と同じ（位置ごとの完全一致）。

### 2.4 段 C: object の一覧を 1 段まで（実環境の形 3）

1. 型の記録で、object の要素の中の鍵と印を、道 `key[i].name` で記録する。中の鍵の名前は今の伏せ方（`safeNameOf`）で扱う。
2. 中の鍵の名前に、秘密に見える名前・状態の語・伏せた名前があれば、その鍵ごと拒む（最上位の鍵と同じ検査を共用）。
3. 中の欄でない値は空の値だけを受ける。照合では、中の鍵の集合が承認と完全に一致することを求める。
4. 2 段より深い入れ子、object と scalar の混ざりは、今のとおり拒む。
5. 上限（`api-request-shape.ts` の 1 か所に置く）: 行の数は 20（`MAX_API_ARRAY_ELEMENTS`）、葉の文字は 200、1 行の中の鍵は 16、葉の合計は 32（`MAX_API_SHAPE_MARKERS` と同じ）。

### 2.5 理由の値

新しい拒みの理由は、名前を実装で決め、理由の閉じた一覧・schema・表示のカタログ・画面の理由の対応に登録する（画面の文は今の「入力のしかたを扱えない」を使う）。

## 3. 変えないもの

- 更新（UPDATE）の一覧の鍵は拒む。
- 印のない一覧（ページが決めるだけの一覧）は、DEF-226 のとおり型と数を固定し、値は照らさない。
- 安全の守り（DELETE・危険な語・資格情報・承認の外の Origin、1 回だけの送信、送る前の照合）。

## 4. サイトへの負荷

変わらない。要求の数と読み込みの回数は同じ（入れる欄が増えるだけ）。

## 5. 限界

1. 欄を入れると同じ親の前の位置に行が足される画面は、操作さがしで押せない（`PRESS_FAILED`）。別の不具合 DEF-237 として扱う。
2. 「追加」を押して行を増やしてから入れる形は、今のとおり 1 行で試す。

## 6. テスト

- 仮のサイト（INV-234 の形を一般の文言で: 資格の 2 行で空の行を送る・送らない、後ろに空の行、入れると空の行が足される、4 つの欄、「追加」、object の一覧）。段ごとに、操作さがし → 自動の下書き → 承認 → 書き込みで POST が 1 回届き、本文が期待どおり（サーバの記録）。崩した形（足す・減らす・順・別の値・空の位置を埋める・深くする・中の鍵を足す）は届いた数 0。
- digest: 一覧のない型・DEF-226 で承認した形が変わらない（固定の値）。
- 2 つの Chromium。DEF-226 の既存のテストが通る（穴を閉じた所の期待の変更は、理由を報告に書く）。
