# 見るだけの確かめを「検索の確かめ」に作り替える（追補設計書、2026-11-18）

## 1. 目的
- ユーザーの指摘（2026-11-18）: 人が期待（READ の定義）を作る画面がなく、何を期待にするかの誘導も要る。フォームだけ用意すればよいものでもない。→ 期待を自動で作れるかの調べ（RCX）→ ユーザーの判断「『検索の欄に自動で値を入れて送る』案に作り替える。進み具合についても独自に計測するよう注意して」。
- 実環境の記録（数だけ。名前は伏せる）: 操作さがしの候補 5,241 のうち、送れる GET の検索フォームは 0。検索はスクリプトで動く（入力・ボタン・選択肢の変更で、画面が裏で GET の API を呼ぶ）。→ ユーザーの判断「入力で動く検索も調べる点と、検索ボタンもフォームではなくスクリプトで動作する可能性もある」「作り替えを進めてよい」。
- 同じ記録（11-16 の操作さがし）: 凍結の後に通った読み取り 1,748 回（33 画面）、目印を運んだ読み取り 10 回（1 画面）、選択肢の欄 18・選択肢 71・選んだもの 68。どれも応答の状態を記録していない。
- この設計書は、`2026-11-09-beaksight-read-check-record-id-fill-design.md`（DEF-235。段で `{id}` の型の詳細を読む）の段の部分を置き換える。

## 2. 決まり
### 2.1 操作さがしで、自分が起こした読み取りの応答を記録する（読み込みは増えない）
- 押下・選択肢の選択・入力のたびに、凍結の Guard と `isFrozenReadAdmissible` が通した GET について、形（path の型、query の名前、目印を運んだ query の名前。今の型の作り手で伏せる）と応答の状態の番号を、押下ごとの任意の項目に残す。値・本文は残さない。
- 5xx は「検索の誤り」の材料にする。4xx は誤りにしない（記録だけ）。
- 打つだけで動く検索: 凍結の段で、候補に属さない見える文字の欄（password・file・hidden・checkbox は除く）に目印を入れ、押下と同じ静まりの待ちをする。目印を運ぶ GET が出れば「入力で動く検索」として記録する。

- **RCA-1〜4 の後の判断（2026-11-18）**: 打つだけの欄に目印を入れるのは、その文書の押下を全部終えた後に画面ごとに 1 回（段の始めに入れると、ページの JS が値を覚えて開き手の移り先の URL に乗せ、目印がサーバへ届いた。開き手は目印を入れる前の文書で押す決まり COV-2c を守る）。応答の状態は page の response・requestfailed で集め、凍結の段では Guard が通した読み取りだけ。きっかけの記録は画面の記録の `searchTriggers` に置く。

### 2.2 見るだけの確かめの段（検索の確かめ）
- 対象（組）: 最新の操作さがしの記録から始める前に作る。(1) 目印を運ぶ GET が出たトリガー（押下か入力）× 文字の値 3 通り（空・半角の目印・全角の仮名の目印）、(2) GET の検索フォーム（READ の候補）× 自動の値（空、選択肢を 1 つずつ、文字の欄は空・半角の目印・全角の仮名の目印、1 つずつ変える）。選択肢は操作さがしで全部試し済みなので、スクリプトのトリガーでは繰り返さない。同じ形のフォーム・トリガーはまとめる（構造で。数では切らない）。
- 確かめ方: 凍結した Context で画面を開き、押下の部品（操作さがしと共有）で値を入れて同じ押下か入力をし、出た GET の状態を見る。新しい送り方は作らない。危険な語・秘密の名前・送れない欄・削除の語のボタンの守りは今どおり。守りに当たる組は始める前に除く（M は正確）。
- 判定: 主の文書か、トリガーが出した GET が 500・501・505〜599 → 誤り。429・502・503・504・応答なしは DEF-136 のとおり待って 1 回確かめ直し、まだならフォームの画面を 1 回読み、画面は開けて検索だけ開けなければ誤り（開けない）、画面も開けなければ `SITE_UNAVAILABLE` で止める。ログインの画面へ戻されたら、ログインし直し（DEF-200）の後にその組を 1 回だけやり直し、また戻されたら誤り。4xx は誤りにしない。BeakSight が止めた移動は判定できない。hidden の欄を送らないフォームで基準の組が 5xx のときは判定できない（偽の警告を避ける）。誤りがあっても Run の状態は `COMPLETE`。
- DEF-235 の段の読み込み（`{id}` の型の照合の専用でない定義、番号を埋める所）はやめる。書き込みの答え合わせ（照合の専用）は変えない。人が作った定義（型でないもの）は今どおり読む（画面は増やさない）。
- 段を行うか: 「人の定義の数 + 組の数」が 1 以上。チェックした画面だけの点検（WSO）では行わない（今どおり）。

- **RCA-7 の Blocker の判断（2026-11-18）**: スクリプトの組（押下・入力）を見るだけの確かめの段で押すため、組があるときはこの段のジョブの Context を操作さがしと同じ押す口（`submissionProbeRun: true`。凍結・守り 2〜8・押す時点の確かめ・削除の判定は操作さがしと同じ）にする。押下の部品に「決まった値を入れて押す」「決まった値を打つ」口を足す（今の押下の守りを通る）。記録した priorPresses を押下の部品のたどり直しの形へ移し、たどり直せなければ `STATE_NOT_REBUILT`。押下の部品の安全の独立レビュー（REV-DQF）の後に作る。

- **REV-RCA の後の判断（2026-11-18）**: 文字の値は「a」「あ」をやめ、空・半角の英数字の目印（操作さがしの目印の作り手と同じ）・全角の仮名の目印にする（1 文字の値を目印として観察の口に渡すと token の更新などを広く止めるため）。2 つの目印は観察の口に渡し、非 GET が運べば押下で出た送信として止める。hidden の欄を送らないフォームはどの組の 5xx も判定できない。空の値で読み取りが出ないのは「空では検索しない」で問題なし（入力のきっかけは打ってから消す）。表示の文字が危険な語の選択肢は組から除く。2 回目のログインの戻しは、戻された組の鍵を親が渡し、ワーカーがその組を最初に流して判定する。操作さがしで記録した 5xx は別の 1 行・別の数。M には人の定義を含め、読まない URL の組は始める前に除く。

### 2.3 進み具合（この段で独自に測る）
- この段のワーカーが、ログインの後・最初の組の前に `0 / M` を、組を終えるたびに `N / M` を送る（`PROGRESS` の `pagesFinished` = 確かめた組、`pagesDiscovered` = M）。点検・操作さがしの数は使わない。M は始める前に決まり、増えない。
- 見積もりは DPROG の `progressRemainingMs`（そのワーカーの実行の最初の進みを基準）。語は「確かめた検索 N / 全部 M。あと 約 X 分」（増えないので「延びます」は付けない）。ログインし直しで続けるときは、残りの組だけを渡す。

### 2.4 見せ方
- プロファイルの詳細の要点に 1 行（例「検索を 24 通りためしました。2 通りで画面が開けませんでした。」誤りが 0 なら「問題はありませんでした」）。見るだけの確かめの作業の画面の要点に同じ 1 行と誤りの一覧（画面の名前 + どう試したか + 起きたこと。欄の名前・URL・値は出さない）。操作さがしで記録した 5xx も同じ一覧に出す。
- 点検のレポートへの追記は 1 版目では作らない。

### 2.5 版
- `discovery.json`: 任意の項目を足すだけ（版は今のまま。識別の digest には入れない）。
- `read-evidence.json`: 1.3（`searchChecks`）。ワーカーのプロトコル: 10（READ の段の `START`・`NEXT_STAGE` に組の一覧）。管理データ: 変えない。

## 3. 負荷
- 操作さがしの記録: 読み込み 0 回増。打つだけの欄は、欄の数 × 静まりの待ちだけ時間が増える。
- 検索の確かめ: 組ごとに画面の読み込み 1 回（同じ画面の組が続くときもたどり直しのため 1 回）+ トリガーが出す GET。組の間は `crawl.minNavigationIntervalMs`（今の実環境の設定 10 秒）を守る。時間の上限 `crawl.maxRuntimeMs` を守る。
- 実環境の見込み: 目印を運んだトリガーは 1 画面（数通り）、GET フォームは 0 → 組は数個〜十数個、数分。選択肢がとても多い select は数で切らずに全部送り、値の形の違うものを先に並べる。

## 5. 限界
- 検索が GET でなく POST・GraphQL で動くサイトは、凍結が止めるので確かめられない。
- 型のある欄（email・number・date など）は 1 版目は空だけ。
- 監査の段の押下で出た 5xx は `RESOURCE_5XX` で拾えている可能性があるが確かめていない。
