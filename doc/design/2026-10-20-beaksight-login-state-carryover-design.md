# 設計書 — ログインの状態の引き継ぎを、普通のブラウザに近づける（DEF-139）

状態: ユーザーの確かめによる（2026-10-20）。実装中。
作成: 2026-10-20（設計者）

## 1. 経緯

実テスト環境の監査で、2 ページ目（`/test/`）の読み込みが、ページが何も送る前にログインの画面（`/auth?mode&redirect`）へ移された。DEF-138 の記録の内容は次のとおり。

- 移り方は、監査の対象の Origin の中の文書の移動（`/test/` → `/test` → `/auth`）。
- その読み込みで Guard が止めた要求は 0 件。
- ローカル ストレージと Cookie の鍵の名前は、読み込みの前と後で変わらない。

送信の扱いを「削除のほかは通す」にしても、同じだった。

ユーザーの確かめでは、いつものブラウザでは、同じアカウントで `/test/` を表示できた。新しいタブに URL を貼って開いても表示できた。そのため、タブごとのセッション ストレージは原因ではない。BeakSight が引き継いでいない、次のどちらかが足りないと見る。

- 許可 Origin・承認したサービスの Origin の host と完全には一致しない Cookie（親ドメインの Cookie など）。今の `filterAuthenticatedState` は、host が完全に一致する Cookie だけを残す（T25g-3）。
- IndexedDB。今は `storageState()` を IndexedDB なしで読んでいる。

午前（サイトの更新の前）は表示できたので、サイトの更新で `/test` がこのどちらかを見るようになった可能性がある。

## 2. 設計

### 2.1 記録（原因を記録で確かめるため）

ログインの段の終わり（手動・自動のどちらも）に、ログインの後のブラウザの状態の**名前だけ**を記録する。値は記録しない。

- Cookie: ドメイン、path、名前、host だけかどうか。それぞれを引き継いだか、外したか（外した理由: 許可の外のドメイン）。
- ローカル ストレージ: Origin と鍵の名前。それぞれを引き継いだか、外したか。
- IndexedDB: Origin とデータベースの名前。それぞれを引き継いだか、外したか。
- 上限は名前つきの定数。超えた分は数だけを残す。
- 置き場所: ジョブのログインの段の要約（`login_stage_summary`）と、ジョブの画面の「ログインの段」の欄。
- 名前の扱い: 秘密に見える名前の今の部品があれば、それに合わせる。

DEF-138 のセッションの切れの証拠の `storageKeyChange` にも、IndexedDB の名前の違いを足す。

### 2.2 引き継ぎ（普通のブラウザに近づける）

- **Cookie**: ブラウザが許可 Origin か承認したサービスの Origin へ送る Cookie は、引き継ぐ。つまり、ドメインがその host にドメインとして一致するもの（RFC 6265 の domain-match。親ドメインの Cookie を含む）。
  - 引き継ぐときは、今の T25g-3 と同じく、一致した許可の host だけの Cookie に直す。ほかのサブドメインへは送らない。
  - 公開のサフィックス（`co.jp` など）そのものへのドメインの Cookie は、ブラウザも受けないので、扱わない。
- **IndexedDB**: 許可 Origin と承認したサービスの Origin の IndexedDB を引き継ぐ。
  - Playwright の `storageState({ indexedDB: true })` で読み、`newContext({ storageState })` で入れる。
  - ログインの段の終わり、T25c の Context を閉じるときの読み出し、checkpoint を作らないメモリの中の状態の、すべてで同じにする。
- 値はメモリの中だけに持つ。checkpoint・成果物・IPC・管理データ・ログに書かない（今の決まり）。
- 当てる段: ログインの後の監査・発見・READ の確かめ・書き込みのすべて（引き継ぐ状態の owner は 1 つ）。

### 2.3 安全

- 新しい送信は足さない。引き継ぐ状態を、普通のブラウザがそのページに持つものに近づけるだけ。
- 値が記録・IPC・管理データ・成果物に出ないことを、目印の値で確かめる。

## 3. 受け入れ条件

1. fixture: ログインの後に、親ドメインの Cookie（または IndexedDB）を見て、なければログインの画面へ移すページ。今の作りでは 2 ページ目で切れること（RED）、直した後は監査できること（GREEN）。
   - 親ドメインの Cookie の試験は、127.0.0.1 では作れない。`*.localhost` の名前など、ドメインの Cookie を作れる形にする。作れなければ、単体テストで domain-match を確かめる。
2. ログインの段の名前の記録が、ジョブの画面に出る。値（Cookie の値、ローカル ストレージの値、IndexedDB の中身）は、記録・IPC・管理データ（WAL を含む）・成果物・画面に出ない。
3. 今のログインと引き継ぎのテスト（T25c、T25g-3、T37a、DEF-138）が通る。T25g-3 の期待のうち、意図して変わるもの（親ドメインの Cookie を引き継ぐ）は、理由を書いて直す。
