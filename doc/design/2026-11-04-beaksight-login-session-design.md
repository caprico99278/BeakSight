# 長い点検でログインが切れる不具合と、ログインの段の送信の扱い（DEF-191・DEF-193・DEF-194）

> 2026-11-16 の置き換え: 3.2（DEF-193 の除くもの）と 3.3（DEF-194 の行の理由 `AUTOMATED_LOGIN_RULE_BLOCKED`）のうち、ログインの段でページ自身の通信を削除・危険な語で止める部分は、`2026-11-16-beaksight-action-based-delete-guard-design.md` で置き換えた。理由の値は前の記録を読むために残す。資格情報の守り（守り 3）は変わらない。

状態: 設計者の既定（2026-11-04）。ユーザーの判断「その順で進めて」（DEF-198 → DEF-191・193 → 書き込みも試す点検）による。調べ `DEF-191-193-research`（作業記録の scratchpad `def191\`）の結果を受けて書いた。

## 1. 目的

- 1 時間を超える点検でも、ログインが続くようにする（DEF-191）。
- 自動ログインの段でも、「サイトが自動で送る通信は、削除のほかは止めない」（`PASS_EXCEPT_DELETE`）を当てる（DEF-193）。
- 人に「行を選んで登録してください」と判断を求める表示を、ログインに要らない送信では出さない（DEF-194）。

## 2. 調べで分かったこと

### 2.1 DEF-191

- 監査は 1 ページに 5 回の読み込みをする（Desktop の最初の読み込み D、幅の走査 S320・S768・S1024、Mobile M）。D の Context を開いたまま S を作るので、S は作った時点の D の状態（同じ更新の鍵）を受け継ぐ。
- 期限が近いと、D と S の両方が同じ更新の鍵で token の更新を送る。鍵を回すサーバは 2 回目を使い回しとみなし、セッションを取り消すことがある。取り消されると、サイトのスクリプトが鍵を消してログインの画面へ移る。
- 仮のサイト（鍵を回し、使い回しで取り消す）で再現した。幅の走査をなくすと、同じサーバでも切れなかった。
- 受け継ぎの欠陥も重なる。D の後の状態は、S より世代が古いので捨てられる（`src/browser/context-factory.ts:2166`）。S が D から写したのは作った時点（`:2060-2078`）なので、D がその後に更新すると、更新の前の鍵が次のページへ渡る。
- 実テスト環境の操作さがしの 36 分の切れ方も、token の鍵 3 つが消されていた（画面の作りによる移りではない）。原因は未確認。

### 2.2 DEF-193・DEF-194

- 自動ログインの段の判定（`src/safety/request-policy.ts:1374-1418` の `classifyPassiveRequest`）は、登録のない読み取りでない要求を `UNREGISTERED_NON_READ` で止める。手動のログインには、通す分岐（ML-a の `manualPassThroughOf`）がある。
- 資格情報の守り（`credentialCheckedDecision`、`passive-request-guard.ts:5108-5125`）は、通した後に全部の口で当たる。
- 中継は本文とヘッダを見ないので、Guard が通しても、そのままでは中継が通さない。書き込みの段の `EgressSendAdmissions` と同じく、Guard が通した要求の写しを中継へ渡す必要がある。
- 通した行も止めた行も同じ理由 `UNREGISTERED_NON_READ` で記録されるので、登録の案と「行を選んで登録してください」が残る（`apps/local-ui/src/server/audit-job-functions.ts:1118-1120`、`src/control/login-observation-draft.ts:40`・`61-73`）。

## 3. 採用する設計

### 3.1 DEF-191: サービスの Origin へ送れる Context を、同時に 1 つにする（案 A）

1. 監査の 1 ページの中で、幅の走査（S）は、D の Context を閉じた後に回す（Mobile の前）。D と S が同時に生きない。
2. 受け継ぎの決め方は「最後に閉じた Context の状態を次へ渡す」にそろえる（作った順の世代でなく、閉じた順）。`context-factory.ts` に決め方を明記し、テストで固定する。
3. 操作さがし・READ の確かめでも、認証つきの Passive の Context が同時に 2 つ生きる所がないかを確かめる。あれば同じ決まりにそろえる（なければ、ないことをテストか注記で示す）。
4. 止める要求は足さない（「削除のほかは止めない」と両立する）。サイトへの要求の数は増えない（重なっていた更新が減る）。
5. 監査の結果の中身は変えない。Evidence の記録の時機が変わって ID の順がずれるなら、golden の見直しで受け入れる（中身が同じことを確かめる）。

### 3.2 DEF-193: 自動ログインの段でも、削除のほかを通す

1. `classifyPassiveRequest` に、自動ログインの段の分岐を足す（`manualPassThroughOf` と並べる）。条件: スクリプトのログインの段で、手動のログインの通し方でない。判定が `UNREGISTERED_NON_READ`。ナビゲーションでない。
2. 除くもの（止めたまま）: DELETE と DELETE の上書き（`isDeleteMethodOverride`）、危険な語・読まないパス（`isAuditSendDangerous` を共用）。資格情報を含む要求は、今の `credentialCheckedDecision` が止める。
3. 通した要求は、ログインの送信の回数に数えない印にする（BeakSight 自身のログインの送信の上限の意味を保つ）。
4. サイトのスクリプトの token の更新（ログインの送信と同じ送り先で、query が違う。`TOKEN_REQUEST_QUERY_MISMATCH`）も、資格情報を含まなければ、同じ分岐で通す（回数に数えない）。資格情報を含めば、今のとおり止める。
5. 中継へは、Guard が通した要求の写しを渡す（書き込みの段の `EgressSendAdmissions` と同じ部品を使い、別の比べ方を作らない）。ログインの段と `auditSend` を一緒に渡すと `TypeError` になる所（`context-factory.ts:1661-1663`）は、ログインの段の指定の印で扱う。
6. 監査・操作さがし・書き込みの段の判定は変えない。

### 3.3 DEF-194: 通した行と、決まりで止めた行を登録の対象から外す

1. 自動ログインの段で通した行と、DELETE・危険な語で止めた行に、別の理由を付ける（理由の閉じた一覧・schema の enum・表示カタログに足す）。
2. 登録の案（`loginStageRegistrationOf`）と「行を選んで登録してください」の判定（`hasRegistrableLoginStageRow`）は、これらの行を数えない。今の形なら、ログインが成功している点検では表示が出ない。
3. 通した行は、記録（作業の画面の「詳しい内容」の通した送信の表）には残す。

### 3.4 DEF-200: ログインが切れたら、自動でログインし直して続ける（2026-11-04 ユーザー「DEF-200として足して進めて」）

ユーザーの問い「ログインが切れたら、再ログインすればいいのでは？」への設計者の案（3.1 の直しに加えて入れる。代わりにはしない）を、ユーザーが認めた。

1. **対象。** 自動ログインのプロファイルの、見るだけの点検（監査）・操作さがし・READ の確かめの段。手動のログインのプロファイルは、今のまま止める（人のログインを待てないため）。
2. **流れ。** セッションの切れ（`AUTH_SESSION_LOST`）を検知したら、今のとおり、そのページは読み終えずに残す（切れた後の結果を採らない）。続けて、今の自動ログインの部品で 1 回ログインし直し、ログインの終わりの判定が成功なら、同じ Run の残り（切れたページを含む）を続ける。今の「続きから再開」と同じ再開の仕組み（checkpoint）を使い、別の仕組みを作らない。
3. **回数と間隔。** ログインし直すのは、段ごとに 2 回まで（2026-11-04 ユーザー「回数の上限は点検と操作さがしで共有せず、操作さがしの段階で上限2回にカウントをリセットすること」）。見るだけの点検の段で最大 2 回、操作さがしの段に入ったら数を 0 に戻して最大 2 回。READ の確かめは操作さがしの段の数に含める（設計者の既定）。今の自動ログインの上限（間隔 5 分以上、24 時間に 10 回まで）を必ず守る。間隔の中なら、間隔が明けるまで待ってから行う（待つ間はサイトに要求を送らない）。上限に当たる・ログインに失敗する・ログインし直した後に 1 ページも読まずにまた切れる、のどれかなら、くり返さずに今のとおり止める（PARTIAL）。
4. **書き込みの段。** 書き込みのジョブの途中で切れたときは、ログインし直さない。その書き込みは今のとおり止め（送ったかがあいまいなら `UNKNOWN`、送っていなければ送らない）、送り直さない。
5. **記録。** 切れたこと（時機・ページ）と、ログインし直したこと（回数・結果）は、作業の記録（`run.json` の実行の記録、ジョブの記録、自動ログインの試みの記録）に残す。画面には、ふだんは出さない（止まったときだけ、今の止まり方の文）。ログインし直すたびに 1 回の実行として数え、実行の終わり方は、ログインし直して続けたことが分かる理由にする。
6. **サイトへの負荷。** 増えるのは、1 回の点検でログインの送信が最大 2 回（ログインの段の読み込みを含む）。読み込みの間隔は変えない。
8. **作り（DEF-200 の Blocker の後の設計者の判断）。** 1 つのジョブで自動ログインの試しは 1 回だけ（管理データの `auto_login_attempts.job_id` が UNIQUE）なので、ログインし直すたびに、親が新しいジョブを作る。監査は `startNew: false` で checkpoint の続きから始める。READ の確かめは、その段を最初からやり直す（読む数が少ない）。操作さがしは、続きから始める仕組みを今作る（2026-11-04 ユーザーの判断「続きから再開する仕組みを今作る」。下の 9）。切れた実行は `STOPPED_BY_AUTH_SESSION_LOST` のまま残す。監査と操作さがしの新しいジョブは、同じ `run_id`・`start_new = 0` で前のジョブと結ぶ。ログインし直したことは、run.json（操作さがしは同じ Run）の実行の記録の任意の項目（ログインし直して自動で始めた印と、その時点の回数）に残す。READ の確かめのやり直しは、連鎖のメモリの中で結ぶ。新しい列挙値は足さない。管理データの版と `job-store.ts` は変えない。
9. **操作さがしの続きからの再開。** 操作さがしも、ページを読み終えるごとに、続きに要るもの（読んだページの記録と候補・probe の結果、待ち行列、先に読む登録の画面と移った先の編集の画面の読んだ数、同じ型を読んだかの印）を Run の checkpoint に書く。監査の checkpoint の部品（`src/orchestration/run-checkpoint.ts` の書き方・読み方・ロック）を使い、別の仕組みを作らない。ログインし直した新しいジョブは、同じ Run のディレクトリで、読み終えたページを読み直さずに残りから続け、終わりに 1 つの `discovery.json` にまとめる。ページの上限・`MAX_CHAINED_CREATE_PAGE_READS`・`MAX_OPENED_EDIT_PAGE_READS`・読み込みの間隔は、前の実行と合わせて数える（再開で増やさない）。設定（プロファイルの改訂）が変わっていたら、続きからにせず新しく始める（監査と同じ決まり）。切れたページは読み終えていないので、続きで読み直す。
7. **安全。** ログインの段の守り（資格情報、送信の数の上限）は、今の自動ログインのまま。切れた後のページの結果は採らない。ログインし直した後の Context は、新しいログインの状態から作る（切れる前の状態を混ぜない）。

## 4. 対象外・既知の限界

- 資格情報の守りは、利用者の ID を、読み取りでない要求のときだけ比べる（今までの決まり）。ID だけを含む読み取り（GET。`Authorization: Basic base64(ID)` を含む）は止めない（SREV-1104-2 の M1）。パスワードは、どの要求でも比べる。
- base64 を 2 重にかけた形、hex などほかの符号化、別の値とつないでから base64 にした形の資格情報は、見分けない（`Basic` の値は解いて比べる）。

- 書き込みのジョブは、ページが書く localStorage をジョブの始まりの値に固定する（LU-SFIX5、`context-factory.ts:1062-1082`）。ジョブの途中で token が更新されると、次の Context が使い終えた鍵を送り、同じ切れ方が起きうる。書き込みのジョブは数分で終わるので、まず実テスト環境で起きるかを見る（コードを読んだ推論で、実験はしていない）。
- 操作さがしの 36 分の切れ方は、原因が未確認。3.1 の 3 で直らなければ、実テスト環境の記録で調べ直す。
- 本来のサイトのサーバの使い回しの扱いは、知りえない。仮のサイトで「すぐ取り消す」「親の鍵の再使用を許す」の 2 つの形で確かめる。

## 5. テスト

- DEF-191: 鍵を回し使い回しで取り消す仮のサイト（調べの `rotating-site.ts` を tests/helpers に写す）、token の期限をテストの値（数秒）に縮めて、監査の長さが期限を越える数のページを切れずに COMPLETED。期限を越えたこと（Run の長さ > 期限）と、更新が起きたことを期待で確かめる（2026-11-13 TEST-TIME-B で 14 ページから改めた）。直す前は切れる（RED）。2 つの Chromium。受け継ぎの決め方の単体。
- DEF-193: 自動ログインの段で、サイトの 3 種の送信が届く。資格情報を含む要求・DELETE・DELETE の上書き・危険な語の path・2 回目のログインの送信は届かない（サーバの記録で数える）。token の更新が通り、回数に数えない。2 つの Chromium。
- DEF-194: 通した行と決まりで止めた行では、登録の案と表示が出ない。ほかの止めた行（登録が要る形）では、今のとおり出る。画面のテスト。
- 既存のログイン・監査・操作さがし・書き込みの段のテストが PASS。
- 端末の負荷の決まり（1 ファイルずつ・`--maxWorkers 1`・ブラウザは同時に 1 つ・chrome-headless-shell が 0 に戻る）。verify:all は流さない（ユーザーの指示）。
