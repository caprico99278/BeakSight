# BeakSight 作業の画面の「できたファイル」をまとめてダウンロードする（DLALL）

- 日付: 2026-11-24
- 状態: ユーザーの判断を得た（2026-11-24「できたファイルの一括出力ボタンと機能も配置してほしい。一つの zip にまとめる必要はない」）
- 拡張する文書: PL-2（作業の画面の「できたファイル」`JobArtifacts`）、AUD-1d（分けたまとめファイル）、UI の SSOT 設計書（文言は messages の 1 か所）

## 1. 背景

- 作業の画面の「できたファイル」には、run.json・audit.json と、分けた ChatGPT 用のまとめファイル（多いと十数個）が 1 行ずつ並ぶ。利用者は 1 つずつ押してダウンロードしている。

## 2. 決めたこと

- 「できたファイル」の見出しの下（一覧の上）に、ボタン「まとめてダウンロードする」を 1 つ置く。一覧に 2 つ以上のファイルがあるときだけ出す。
- 押すと、その一覧に出ているファイルを、一覧の順に、1 つずつ別のファイルとしてダウンロードする（1 つの ZIP にまとめない。サーバに新しい口を作らない。今の各ファイルの `href` を使う）。
- 1 つずつ順に行い、前のファイルの取り出しが終わってから次へ進む（決まった秒数の待ちを置かない。同時に全部を取りに行かない）。
- 押している間はボタンを押せなくし、「ダウンロードしています（n / 全 m）」と出す。取り出せなかったファイルがあれば、残りは続け、最後に「k 個のファイルをダウンロードできませんでした。1 つずつのリンクから試してください。」と出す。
- 文言は UI の messages の 1 か所に置く。技術の語を出さない。
- 作業が動いている間（ファイルがまだそろっていない間）は、今の一覧の出し方に従う（新しい条件を足さない）。

## 3. 受け入れ

- UI の単体（今の作業の画面のテストの形）で: 2 つ以上でボタンが出る・1 つでは出ない、押すと一覧の全部の `href` を一覧の順に 1 回ずつ取りに行く、1 つが失敗しても残りを取りに行き失敗の数を出す。
- tsc（root と `apps/local-ui`）0。UI Gate。関係する UI のテスト。

## 4. 速さと負荷

- 取りに行く先は利用者の PC の中の BeakSight の画面（127.0.0.1）だけ。監査の対象のサイトへの通信はない。

## 設計変更履歴

- 2026-11-24 新規（ユーザーの判断に基づく）。
- 2026-11-24 architecture の Gate（DEF-099 の (e)。`apps/local-ui/src/**` で大域の `fetch(` を使えるのは閉じた一覧のファイルだけ）に当たった。守りの Gate に例外を足さず、取りに行く処理をやめる: ボタンは、一覧の各ファイルの今のリンク（`a[href][download]` と同じ `href`）を、一覧の順に押す形にする（ブラウザのダウンロードの仕組みが 1 つずつ保存する。秒の待ちを置かない）。そのため、取り出せなかった数は画面で数えない（ブラウザのダウンロードの一覧に出る）。進み具合の表示は「n 個のファイルのダウンロードを始めました」の 1 行にする。
