# 設計書 — 発見と READ の確かめのジョブの、サイトの不調とエラーの画面の扱い（DEF-136）

状態: ユーザーの指示による（2026-10-18「明日の前に直して」。設計者の提案 2 つ: 不調の判定を共有する、エラーの画面から候補を拾わない）
作成: 2026-10-18（設計者）

## 1. 目的

発見のジョブと READ の確かめのジョブが、サイトの不調（応答しない、接続できない、429・502・503・504）のときに、止まらずに次の画面を読み込みに行かないようにする。発見のジョブが、4xx・5xx のエラーの画面から候補とリンクを拾わないようにする。

## 2. 今の振る舞い（2026-10-18 に設計者がコードと仕様書で確かめた事実）

- 読み取りの監査（`src/orchestration/run-coordinator.ts`）は、`src/orchestration/site-availability.ts` の `siteUnavailabilityOf` で不調を見分ける。不調なら、そのページを捨てて、60 秒・2 分・4 分・8 分待って確かめ直し、4 回とも不調なら Run を止める（`doc/spec/site-unavailability.md`）。500 と 429 以外の 4xx は、そのページの失敗として記録して次のページへ進む。
- 発見のジョブ（`src/worker/discovery-run.ts`）は、読み込みが `OK` でなければ `NAVIGATION_FAILED` として次の画面へ進む。不調で止まる仕組みはない。HTTP の状態が 4xx・5xx でも、読み込みが `OK` なら「読めた画面」として候補とリンクを拾う。
- READ の確かめのジョブ（`src/worker/read-check-run.ts`）は、対象の画面が 4xx・5xx なら、その定義を `UNDETERMINED` にして次の定義へ進む。不調で止まる仕組みはない。

## 3. 設計

### 3.1 不調の判定を共有する

- 発見と READ の確かめのジョブは、BeakSight が始める画面の読み込みごとに、読み取りの監査と同じ判定（`siteUnavailabilityOf`。owner は `site-availability.ts`。複製しない）をかける。
- 不調を見分けたら、その画面の結果を捨てる。読み取りの監査の最初の待ち（60 秒。同じ名前つきの定数を使う）だけ待って、同じ画面を 1 回だけ確かめ直す。
  - ジョブは利用者が画面から始めるもので、長く黙って待つと、何が起きているか分からないため。読み取りの監査の 4 段の待ちは使わない。
  - 待つ間は、ジョブの監査の段の印に、待っていることを出す（今のジョブの印の作りを使う）。
- 確かめ直しでも不調なら、ジョブを止める。
  - 残りの画面・定義は、理由 `SITE_UNAVAILABLE` で、読まなかった・実行しなかったとする。
  - ジョブの終わりの理由も `SITE_UNAVAILABLE` とし、結果は一部未完了（`PARTIAL`）にする。
  - サイトが戻ってから、利用者がジョブを始め直す。
- 確かめ直しで通ったら、その画面の結果を残して続ける。確かめ直しの後の読み込みの間隔は、読み取りの監査と同じく 2 倍にする（上限も同じ定数）。
- 止める印、上限、間隔、読み込み直しなしの決まりは、今のまま守る。待つ間に止める印が来たら、確かめ直さずに止める。

### 3.2 エラーの画面から拾わない（発見のジョブ）

- 画面の文書の応答が 4xx・5xx なら、その画面からは候補もリンクも拾わない。読まなかった画面として、理由 `HTTP_ERROR_STATUS`（新しい理由。閉じた一覧に足す）にする。
- 429・502・503・504 は、3.1 の不調として扱う。
- セッションの切れ（ログインの画面へ戻された、など）の今の判定は変えない。判定の順は、セッションの切れ、不調、エラーの状態の順にする。
- READ の確かめのジョブの 4xx・5xx は、今どおり `UNDETERMINED` にする（不調の 4 つの状態は 3.1）。

### 3.3 記録と画面

- 新しい理由（`SITE_UNAVAILABLE` の終わりと読まなかった理由、`HTTP_ERROR_STATUS`）を、発見と READ の確かめの成果物の閉じた一覧と Schema、表示のカタログに足す。
- 管理データの列の CHECK に終わりの理由の一覧がある場合は、版を上げずに済む形を先に探す。版を上げる必要があれば、版 14 の写しを固定してから版 15 にする。
- 画面のジョブの結果に、止まった理由と、次にすること（サイトが戻ってから始め直す）を出す。

## 4. 安全と負荷

- 止まりかけのサイトに、次の画面を読み込みに行かない（今の読み取りの監査と同じ方針）。
- 1 回のジョブで、不調による読み込みは、元の 1 回と確かめ直しの 1 回の、2 回まで増える。
- Guard と書き込みの流れは変えない。

## 5. 受け入れ条件

1. fixture で、発見のジョブの 2 つ目の画面が 503 を返すとき:
   - 確かめ直しを 1 回だけ行い、まだ 503 ならジョブを止める。
   - 3 つ目の画面は読み込まない（サーバの記録で数える）。
   - 確かめ直しで 200 なら、続ける。
2. 接続の拒否と、応答のない時間切れでも、同じく止まる。
3. 500・404 の画面からは、候補とリンクを拾わず、`HTTP_ERROR_STATUS` になる。次の画面へ進む。
4. READ の確かめのジョブでも、1 と 2 が同じく成り立つ。
5. 回帰: 発見と READ の確かめの関係するテスト（重いテストの全体と `verify:all` は、ロードマップの最後）。
