# BeakSight 押せる物のない画面を操作さがしで読まない・測りのための記録の共通部品

- 日付: 2026-11-20
- 状態: ユーザーの判断を得た（2026-11-20「1 を入れて進めて。時間計測用のログ設置が他にも必要であれば追加してよい。I/O 負担がかかるため、デバッグ測定目的のログは共通部品化し、いつでも OFF にして実行できるようにしておくこと」）
- 拡張する文書: `2026-11-19-beaksight-discovery-seed-from-audit-design.md`（DSEED）、DTIME（`src/discovery/page-time-breakdown.ts`）

## 1. 背景（設計者が実環境の操作さがしの記録 RUN-20261120035728 で数えた事実）

- 読んだ 88 画面のうち、候補が 0 の画面が 10（初めての型 4、同じ型の 2 枚目以降 6）。送信の形は 0。
- 同じ型の 2 枚目以降 37 のうち 6 画面から新しい送信の形が 16（全 81 の約 2 割）。型だけで外すと取りこぼすので、外さない（PSKIP の押し直しの省きで足りる）。
- 押さなかった理由の最多は `TARGET_NOT_VISIBLE` 3226、`COVERED_BY_OTHER` 695（PSKIP で即決にした）。時間の内訳は、次の実 Run の記録で数える。

## 2. 決めたこと

### 2.1 押せる物のない画面を読まない（SKIP-1）

- 監査の段の画面（DSEED の種）のうち、監査の段の証拠で**押せる物がない**と分かる画面は、操作さがしで読み込まない。
- 「押せる物がない」は、操作さがしの候補の作り（`src/discovery/classify.ts` などの今の 1 か所）が候補にしうる要素（button・入力欄・form・role の button・リンクのボタン・click の受け手の付いた要素など）が、監査の段の Desktop と Mobile の両方の証拠で 0 のときだけ。証拠が欠けている・読めない画面は外さない（読む側に倒す）。判定は 1 か所の部品にし、操作さがしの候補の判定と同じ意味の値を使う（写しを作らない）。今の監査の段の証拠で判定できなければ、止まって報告する（証拠を足すかは設計者が決める）。
- 外した画面は記録に残す（今の `NOT_READ` と理由の置き場を使う。理由の値は 1 つ足す。表示は今の「読まなかった画面」の数え方に従う。技術の語を出さない）。
- 巡回で後から見つかった画面（監査の段にない画面）は、今どおり読む。

### 2.2 測りのための記録の共通部品（DBG-1）

- デバッグ・測りのための記録（時間の内訳など）は、1 つの共通部品（例: `src/core/debug-timing.ts`）だけを通して書く。部品は:
  - 入切の 1 か所: 既定は切。入れるのは Git の管理の外の設定ファイル `local/debug-settings.json` の `{ "debugTiming": true }`（読むのは `debugTimingSwitchOf` の 1 か所。CLI とワーカーの入口が読む口を作って依存の注入で下へ渡し、Run（段）の始めに 1 回読む）。環境変数は使わない（2026-11-21 ユーザーの判断）。利用者の画面に入切の口は作らない。
  - 切のときは、ファイルの読み書きをしない。時刻の取得も記録の組み立てもしない（呼ぶ側の負担がほぼ 0）。
  - 入のときは、Run のフォルダの 1 つのファイル（例: `debug-timing.jsonl`）へ、まとめて書く（行ごとに開かない。段の終わりと Run の終わりに flush）。ChatGPT 用のバンドルと報告には入れない。
  - 記録に URL の query の値・入力した値・秘密を書かない。画面は `pageId`・`stateId` か data を除いた path の digest で書く。
- 今の DTIME の `timeBreakdown`（checkpoint の中の測りの値）も、この部品の下に移す（切なら記録しない）。checkpoint の schema の扱い（省略可にする）で版の判断が要るなら止まって報告する。
- 足す測りの点（今の DTIME で見えない所）:
  - 監査の段の 1 画面: 読み込み・落ち着き・axe・幅の走査（幅ごと）・撮影・開いた状態の確かめ・Mobile。
  - 操作さがしの 1 押下: 準備の確かめ・押下・押した後の見届けの窓・状態の作り直し・読み直し。
  - 段の間の待ち（間隔の待ち `pacingWait` など）。

## 3. 受け入れ

- SKIP-1: 単体で、両方の幅の証拠で押せる物が 0 → 読まない（理由つき）。片方にボタン → 読む。証拠が欠ける → 読む。DSEED の今の結合（あれば）が通る。
- DBG-1: 単体で、切ならファイルを作らず記録の関数が何もしない、入なら 1 つのファイルに行が書かれ query の値が入らない。DTIME の今のテストは入のときの場面に直す。architecture に「設定ファイルの名前を書くのは部品だけ、`debugTimingSwitchOf` を呼ぶのは入口だけ、環境変数の入切が src にない」の検査を足す（速い fs の検査）。入切の単体は、ファイルなし・`true`・壊れた JSON・`false`。
- tsc（root と `apps/local-ui`）0。関係する単体・architecture・UI Gate。

## 4. 速さと負荷

- 読み込みの回数は減るだけ（押せる物のない画面の分）。間隔は変えない。
- 測りの記録は既定で切。入にしても、書き込みは段の終わりのまとめ書き。

## 設計変更履歴

- 2026-11-20 新規（ユーザーの判断に基づく）。
- 2026-11-20 SKDBG の Blocker（今の監査の段の証拠では、form の外の input のボタンと、Interaction を行わない画面の button が数えられない）に対応: 操作さがしの候補の選び方を probe と監査の段の DOM の数えの共通の 1 か所にし、DOM の Evidence に候補の数を深さにかかわらず入れる（page の schema に省略可で足し、版は上げない）。外すのは Desktop と Mobile の両方が 0 のときだけ（Mobile が SAME なら Desktop の値を使う。値がなければ読む）。checkpoint の `timeBreakdown` は省略可にし、版は上げない。
