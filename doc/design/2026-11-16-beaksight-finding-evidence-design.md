# 指摘の証拠を、対象の写った同じ状態で集めきる（追補設計書、2026-11-16）

## 1. 目的と、上位の文書との関係
- 実環境の監査の Run で、615 件の指摘のうち 299 件が、利用者への支障を判断する証拠が足りず確認待ちになった（利用者の側の分析。名前は伏せる）。ユーザー「監査時点の指摘点の約半数に不足が認められる模様」。
- 調べ（INV-EVID、2026-11-16。実験は作業記録の外の scratchpad）で分かったこと:
  - 重なり・固定の枠の覆い・フォーカスの指摘（約 289 件）は、判定も撮影も文書の先頭の 1 か所で行い、対象まで動かしていない。画像に対象が写るかを確かめていない。
  - 誤った指摘を生む判定の穴が 3 つある（実機で確かめた）: 内側の領域がスクロールする画面で「スクロールすれば見える」をいつも偽にする、`preventScroll` のフォーカスで横のスクロールの中の要素を必ず画面の外とする、フォーカスの指摘の画像の幅がいつも空になる。
  - 複数行のリンクは、外接矩形では重なっても行ごとの矩形では重ならない例がある。
  - 読み込み中の表示を見分ける所がない。性能はスクロールの後に測っている。
- この設計書は、証拠の集め方・判定・出力を改める。方針: 証拠は欠かさず集めきる（欠けに印を付けて済ませない）、数で網羅を決めない、サイトへの読み込みを増やさない、断定の強さを証拠に合わせる、操作は読み取りだけ（値を変えない）。

## 2. ユーザーの判断（2026-11-16）
- 表示の速さは、測り直さない。スクロールの前に測った値で判定し、文は「1 回の測定で基準を超えた」のままにする。読み込み直しはしない。
- 時間切れで止まった点検を続けるときは、途中の画面（一部だけ終わった画面と、証拠の足りない指摘の確かめ）を先に片付け、その後にまだ見ていない画面へ進む。

## 3. 決まり
### 3.1 読み込みを増やさない判定の直し（EV-1）
- 固定の枠の覆い（`FIXED_ELEMENT_OCCLUSION`）: 「スクロールすれば見える」を、文書の量だけでなく、覆われる要素のいちばん近いスクロールの祖先の動かせる量でも判定する。
- フォーカス（`FOCUSED_CONTROL_HIDDEN`）: `preventScroll` をやめ、ブラウザのフォーカスのスクロールに任せる。前と後の位置（文書と祖先）を記録して、確かめの後に元へ戻す。hit-test は複数の点にする。操作の方法（直接のフォーカス）を記録する。指摘の画像の幅が空になる誤りを直す。
- 重なり（`ELEMENT_OVERLAP`）: 行ごとの矩形（`getClientRects`）の重なりと、重なりの点の hit-test で判定する。外接矩形だけの重なりは指摘にしない。
- 表示の速さ（`POOR_LCP`）: スクロールの段の前の LCP で判定する。
- コントラスト: axe の版と、前景と背景の色から計算した丸める前の比を記録し、文に「4.49（基準 4.5）」の形で出す。基準に届かない値は、境目に近くても基準未達のまま残す。
- 読み込み中の表示（aria-busy・role=progressbar・値のない progress など、見えているもの）を、その状態の記録に残す（EV-3 で使う）。

### 3.2 対象まで動かして同じ状態で撮る共通の部品（EV-2）
- 1 つの部品（仮の名前 `revealAndCapture`）: 対象を位置で引き直す → 文書とスクロールの祖先の今の位置を記録 → 祖先ごとに対象が画面の中に入るまで動かす → 落ち着きを待つ（今のスクロールの待ちの値）→ 測り直す（矩形・行ごとの矩形・祖先による切り取り・複数の点の hit-test）→ 先頭へ戻さずに viewport を撮る → 撮った画像の範囲に対象が入ったか（INSIDE・PARTIAL・OUTSIDE）を機械で決める → 元の位置へ戻す。
- 対象が viewport より大きいときは分けて撮り、全部が入るまで続ける（終わりは構造の事実）。同じ帯に入る複数の対象は 1 枚にまとめる。幅の走査の指摘は、その幅のセッションを閉じる前に行う。
- 使う所: 重なり、固定の枠の覆い（枠の外まで動かした位置と、末尾まで動かした位置の両方で測る。「初めの位置だけ」「スクロールで避けられる」「末尾でも隠れる」に分ける）、フォーカス、横のスクロールの領域、文字の見切れ。
- 固定の枠の覆いの文: 確かめた結果に合わせる。見出しなど読む対象の重なりから「押せません」を作らない。押す対象は、hit-test と有効の状態を見た結果だけで「押せません」と言う。
- 出力: 状態 ID・前と後の位置・後の矩形と点・画像の ID・入ったかを、指摘から辿れる記録にする。画像に対象が入らなかった（取れなかった）指摘は、保留の理由の閉じた一覧（例: `TARGET_NOT_IN_IMAGE`・`PAGE_NOT_READY`・`NOT_OPERATED`）の値を付けて出す。画面と報告は、利用者向けに 1 文だけ。
- 追加の項目は任意の項目として足し、schema の版は上げない（前の判断と同じ）。

### 3.3 準備の状態（EV-3）
- 落ち着きの条件に、見える読み込み中の表示が消えたことを足す。終わりは今の進みの見張り（進みが止まったら終える）で決め、回数で決めない。消えないまま終えたときは、内容に関わる規則（見出しなど）の指摘を「画面の準備が終わっていない」の保留の理由で出し、完成した後の欠落と分ける。確かめ直しでも同じ条件で準備の状態を更新し、「初めだけ」「完成した後も続く」「準備が終わらない」を分ける。
- 進みが止まったの具体の形（EV-3、2026-11-16）: 読み込み中の表示が残ったまま、高さ・作り・表示の数・データの通信のどれも動かない状態が、観察の窓の一式の今の値（`pageSettle.openDataRequestQuietMs`）続いたら終える。段の見張りの反応なしで終えると、残りの段が止まり記録が残らないため、落ち着きの待ちの中で終える。新しい秒や回数は足さない。

### 3.4 横のスクロールの領域と、文字の見切れ（EV-4）
- 横のスクロールの領域: 共通の部品で領域まで動かし、Tab で届くか、矢印のキーで動くかを試し、前と後の位置を記録して元へ戻す。静的な判定は残し、実操作の結果を別に記録する。
- 文字の見切れ: 要素の種類（tagName・role）と表示の値を記録し、共通の部品で撮る。選択の部品を開く確かめは、今の「操作で開いた状態の監査」で開ける候補だけにし、値は変えない。

### 3.5 件数の出力と再開の列（EV-5）
- 表示用のモデルの件数に、保留の理由ごとの数、対象が写った画像の割合、確かめ直しで消えた数を足す。
- 再開: 追加の証拠は同じ読み込みの中で取りきる。一部だけ終わった画面と、証拠の足りない指摘の確かめを、再開の列の先に置き、その後にまだ見ていない画面へ進む（2 章の判断）。読み込みの数は今の移動の間隔の守りの中で数える。

### 3.6 限界（2026-11-16 の独立レビューで測った）
- 横のスクロールの領域でキーを押す間の止めは、最後のキーから約 0.2 秒で終わる。その後に遅れて起きる、キーをきっかけにしたページの移動（handler の中のタイマー）は止めず、遅れたポップアップは安全の違反として記録され、その Context は閉じる。どちらもまれな形として直さない。

## 4. サイトへの負荷
- EV-1〜EV-5 のどれも、画面の読み込み（文書の読み込み・読み込み直し・移動）を増やさない（同じ読み込みの中のスクロール・撮影・キーの操作だけ）。表示の速さの測り直しはしない。
- ページの中の読み込みは、対象まで動かすことで少し増える（ユーザーの判断「このまま許す」、2026-11-16）。fixture の 1 ページ（Desktop・Mobile・幅の走査 2 幅）の測り: 下まで行くと続きを読む通信 +6（覆う部品ごとに末尾まで動かすのは 1 回）、遅れて読む画像 +12〜20（全部が幅の走査の Context）、時間 +7.5 秒。どれも利用者がその画面を下まで見たときと同じ種類の読み込みで、移動の間隔の守りは今どおり。
- 1 対象あたりの追加の時間は、ローカルの測りで中央値 50ms、固定の待ちを足して約 0.3 秒（実サイトは未測定。EV-2 の後に測って記録する）。
