# 削除の守りを「BeakSight の操作の前の判定」に移す（追補設計書、2026-11-16）

## 1. 目的と、上位の文書との関係
- ユーザーの判断（2026-11-16）: 「サイトが自分で出す通信は止めないで。BeakSight が自律的に出す通信で削除に関するアクションに関するものは止めて」「監査時にボタンを押したりフォームを入力したりするはずだ。そのアクション次第」「何を削除とみなすかは君の提案通りでよい。問題はその提案に従っていない仕様の方」。
- きっかけ: 実環境の確かめで、ページが開くと作り、閉じる時と読み込みの途中に片付ける、ページ自身の試しの表示のセッションの DELETE を、監査の段とログインの段の Guard が止めていた。
- この設計書は、`2026-11-15-beaksight-test-rebuild-design.md` 2 章 9 の守り 1「削除を止める」を置き換える。次の文書の、サイト自身の通信を削除・危険な語・ログアウトの語・閉じる時で止めると書いた節も置き換える: `2026-10-19-beaksight-audit-send-policy-design.md` 2.2・3 章、`2026-11-04-beaksight-login-session-design.md` 3.2・3.3、`2026-11-09-beaksight-remove-limits-design.md` 3 章 1・6.2、`2026-10-27-beaksight-one-pass-flow-design.md` 4.1.7・4.1.8、`2026-11-06-beaksight-notification-overlay-design.md` 3.2、`2026-11-09-beaksight-visible-pacing-wait-design.md` 3.1・7 章、`2026-10-21-beaksight-task-44-efficiency-precision-usability-design.md` P1-2。`2026-10-23-beaksight-bundle-beaksight-block-noise-design.md` 3.0（危険な語は BeakSight 自身の移動と操作を防ぐ決まり）は、この設計の根拠として残る。

## 2. 決まり
### 2.1 守り 1 の新しい形
- BeakSight は、削除に関する操作をしない。判定は操作の前（押す前・入れて送る前・移る前）に行う。
- サイトのページが自分で出す通信は、削除の method・method の上書き・危険な語・ログアウトの語を含んでいても止めない。
- ほかの守り（2 押した後の凍結、3 資格情報の送り先、4 自分の移動の間隔、5 自動ログインの間隔と回数、6 伏せ字、7 人が選んだ READ_ONLY、8 外のアプリを起こさない）は変えない。凍結の中で通す読み取り・token の更新から危険な語を除く決まりは、守り 2 の一部として残す。ログインの段の WebSocket の止めは守り 3 として残す。

### 2.2 「削除に関する操作」の定義
- 入れる意味: データを消す（一括・ゴミ箱を空にするを含む）、取り消す（予約・注文・申し込み・送信）、契約やアカウントを終える（退会・解約・利用停止）、初期化・リセット・クリア、無効にする・止める・取り下げる、状態で消す（アーカイブ・非表示・削除の印・ゴミ箱へ移動）、ログアウト（BeakSight の操作として）。
- 入れない: 閉じる・×（枠を閉じるもの）・Dismiss・最小化・戻る。
- 手がかり: 名前（見える文字・aria-label・title・input の value・画像の alt）、form（method・`_method` の隠し欄・`formmethod`・action の path と query）、href の path と query、`data-method`・`hx-delete`、祖先の行（`tr`・`li`・カード）の中にあるか。
- 語の一覧の置き場所は 1 か所（`src/discovery/classification-words.ts` の `DISCOVERY_DESTRUCTIVE_WORDS`）。足りない語（ゴミ箱・空にする・クリア・clear・trash・初期化・取り下げ・sign_out・log_out など）を足す。URL の判定は、同じ一覧を当てる口を通す（既定の除外の語の digest は変えない）。
- 「キャンセル」: 枠（dialog・region）の閉じる場所にあり、枠の名前が予約・注文などの目的語でないときだけ、枠を閉じる操作とみなす。ほかは削除に関する操作。
- 「×」: 行の中にあるときは削除に関する操作。枠の閉じる場所にあるときは閉じる操作。
- 押した後に dialog・alertdialog が出て、その文に削除の語があれば、その枠の中のボタンは押さない。`window.confirm` などの既定の確かめは、今どおり拒む（Playwright の既定）。

### 2.3 操作ごとの判定
| 操作 | 今 | 直し |
| --- | --- | --- |
| 巡回の移動（リンク・読み込み） | 認証つきだけ、URL の英語の語 | 公開監査にも当てる。リンクの文字も見る。2.2 の一覧 |
| 知らせの枠を閉じる押下 | 名前・削除の語・目的語・form・移るリンク | 2.2 の一覧と「キャンセル」「×」の決まり |
| Interaction の押下 | 語を見ない | 2.2 の判定を足す |
| 発見の押下 | 3 段の判定（手厚い） | 2.2 の一覧に寄せる。select・radio の選択肢の語も見る |
| 押した後の確かめの枠 | 見ない | 2.2 の最後の決まり |
| 書き込みの段 | 承認した送信だけ | 変えない（利用者が承認した操作） |
| 自動ログイン | 設定のセレクタ | 変えない |

- 押さなかった記録の理由のコードを 1 つ足す（`DESTRUCTIVE_ACTION_SKIPPED`。表示の文は「消す・取り消すなどのボタンなので、押しませんでした」）。

### 2.4 通信の層から外すもの
- 監査の段の送信の扱いの削除・危険な語の止め、自動ログインの段の `AUTOMATED_LOGIN_RULE_BLOCKED`、書き込みの段の押した後の削除・危険な語の止め（BeakSight が送る書き込みの照合は残す）、登録した読み取りの呼び出しの削除・危険な語の止め、GET・HEAD の DELETE のヘッダの上書きの止め、WebSocket（Worker の中を含む）の危険な語の止め、Interaction の Context の資源の読み取りの危険な語の止め、通信の層だけの語 `AUDIT_SEND_EXTRA_DANGEROUS_TERMS`。
- サイト自身の移動（script の移動・子の frame・先読み）に当てる危険な語と読まないパス・読む範囲の止めも外す。BeakSight 自身の移動は 2.3 の判定で止める。サイト自身の移動で点検の範囲の外へ出た画面は、点検しない（今の、移った画面を点検しない扱いと同じ）。許可 Origin の外への main frame の移動も、サイト自身のものは止めず、点検しない。
- 閉じる途中の止め（method を問わず全部の要求を止める）: ページを離れる手順（about:blank へ移ってから閉じる）を、全部の Context に広げ、閉じる時の後始末の通信が届くようにする。広げられない Context は、限界として 3 章に書く。
- main frame の文書の移動（SD-2 の途中の判断、2026-11-16）: 要求の層では BeakSight の移動とページの script の移動を見分けないので、見分けずに、main frame の移動を危険な語・読まないパス・読む範囲・許可 Origin の外を理由に止めない。BeakSight 自身の移動は、移る前に 2.3 の判定（巡回のリンクの選び方と除外）で止めてあるので、要求の層で重ねて止めない。サーバのリダイレクトはサイトのものとして通す。移った先が点検の範囲の外（読まないパス・読む範囲の外・危険な語・許可 Origin の外）なら、その画面は点検しない（読まなかった理由を記録する。今の理由のコードの値を使い、表示の文は「止めました」から「点検の範囲の外へ移ったので点検しませんでした」の意味に改める。schema の版は上げない）。資格情報を含む要求の守り（守り 3）は、移る先でも今どおり働く。ただし、ログインの段（自動・手動）では、許可 Origin の外への main frame の移動を今どおり止める。人と自動ログインが入れた値を別の Origin の画面へ運ばせないためで、守り 3 の一部とする。範囲の外へ移った画面の理由のコードは `BLOCKED_EXTERNAL_REDIRECT` の値を同じ Origin の範囲の外にも使い、表示の文は「外のサイト」と言わずに「点検の範囲の外へ移った」の意味にする。
- 理由 `AUTOMATED_LOGIN_RULE_BLOCKED` の値と文は、前の記録を読むために一覧に残す。新しい記録には出ない。

## 3. 限界
- 押す前に見えない削除（見た目が「閉じる」のボタンの裏で、ページの JS が DELETE を送る）は、止めない。調べの実機で、両方の Chromium で 5/5 届くことを確かめた。ユーザーの判断「そのアクション次第」により、BeakSight の操作の手がかりで判定する。
- 名前のない「×」で、行の外にあるものは閉じる操作とみなす。
- 閉じる前にページを離れる手順は、凍結の段の Context（操作さがしの押した後・最初から凍結した Context・Interaction の押した後）と人が選んだ READ_ONLY の Context には当てない。前者は離れても後始末の送信が凍結で止まり（守り 2）、後者は読み取りでない送信を通さない（守り 7）ため。
- ページが毎回自分でログアウトする画面では、自動ログインのやり直し（段の組ごとに 2 回まで）の後に止まる。

## 4. 段
| 段 | 中身 | 受け入れ条件 |
| --- | --- | --- |
| SD-1 | 操作の前の判定（2.2・2.3）。語の一覧の 1 か所、巡回の移動・知らせの枠・Interaction・発見・確かめの枠、理由のコードと文 | 削除の語のボタン・form・href・行の ×・予約のキャンセル・削除の確かめの枠を、各操作が操作しない（両方の Chromium の代表と単体）。枠を閉じるキャンセル・閉じる・× は押す |
| SD-2 | 通信の層から外す（2.4）。閉じる時の手順を広げる | ページ自身の DELETE・`_method`・削除の語の path・ログアウトの語・WebSocket・Worker・閉じる時と読み込みの途中の後始末の DELETE が、監査・ログイン・発見の押す前・READ の確かめで届く（両方の Chromium の代表）。守り 2・3・7・8 の代表が通る |
| SD-3 | 文書（`doc/spec/` と、1 章の設計書の該当の節への置き換えの印）、表示 | 秘密の語の検査、UI の表示のテスト |

- SD-1 を先に終え、SD-2 を後にする（操作の前の判定がない間に通信の層を外さない）。SD-1 と SD-2 の後に独立のレビュー（実機）を受ける。
