# BeakSight 操作さがしの入力の確かめを、同じ欄で 1 回にする（ISKIP）

- 日付: 2026-11-24
- 状態: ユーザーの判断を得た（2026-11-24「このまま流して、その間に直しを作って」。前提の報告: 同じ型の画面と共通の枠の検索欄で、目印を入れて待つのを毎回やり直している）
- 拡張する文書: PSKIP（押した組を data を除いた path で数える `locationPressKeysOf`）、RCA-3（form の外の文字の欄に目印を入れる `typeLoneFieldsOnce`）、COV-3（選択肢の確かめ `surveyOptionChoices`・`isFirstSurvey`）、DEF-208-4 / SLK-1（共通の枠の見分け）

## 1. 背景（設計者が実環境の操作さがしの途中の保存 RUN-20261124040509 で数えた事実）

- 読み終えた 92 画面の時間は計 242 分。同じ型の 2 枚目以降の 30 画面は計 49 分で、そのうち入力の確かめ（`inputChecksMs`）が 38 分（77%）。
- 同じ型の 26 画面（data を除いた path が同じ）で、入力の確かめが 1 画面 84〜86 秒ずつかかり、選択肢の記録も入力で動く検索の記録も 0 だった。
- 原因: 入力の確かめを 1 回にする鍵が、画面の path そのもの（`OPTION_PAGE_FORMAT` の `pageKey`）。path の中の ID だけが違う同じ型の画面と、どの画面にもある共通の枠（左のメニューの検索欄など）の欄で、毎回目印を入れて落ち着きを待っている。押下は PSKIP で data を除いた path で省いているが、入力の確かめには及んでいない。

## 2. 決めたこと

- 入力の確かめ（form の外の文字の欄に目印を入れる・選択肢を選ぶ）を、**欄ごと**に、次の鍵で操作さがし全体で 1 回にする（今の押した組の記録 `pressRegistry` を使い、新しい記録の置き場を作らない。途中の保存と再開もそのまま効く）。
  1. 共通の枠の中の欄: 共通の枠の見分け（SLK-1 の枠の部分の構造の鍵と、DEF-208-4 の識別の digest の作り方）で、画面の path を入れない鍵。1 つの Run で 1 回。
  2. それ以外の欄: data を除いた path（`dataFreePathOfUrl`。PSKIP の `locationPressKeysOf` と同じ作り。写しを作らない）と、欄の識別（種類・`name`・順番。選択肢は今の `optionSurveyDigestOf` の選択肢の digest の並びを含む）の鍵。
- data を除いた path が求まらない画面は、今どおり画面の path で数える（読む側に倒す）。
- 欄の識別が前と違う欄（選択肢の並びが違う、新しい欄が出た）は、今どおり確かめる。見えた違いは残らず確かめる（数で打ち切らない）。
- 省いた欄は記録しない（今の「1 回目だけ記録」と同じ扱い）。凍結・守り・押す時点の確かめ・削除の判定は変えない。
- 測り（DBG-1 が入のとき）: 省いた欄の数を、今の DTIME の記録の口で数えられるなら数える。新しい schema の項目は足さない。

## 3. 受け入れ

- 単体（偽の port）で:
  - ID だけが違う 2 つの画面で、同じ欄は 2 枚目で目印を入れない・選び直さない。
  - 2 枚目に新しい欄（または選択肢の並びが違う欄）があれば、その欄だけ確かめる。
  - 共通の枠の中の欄は、path の違う画面（型も違う）でも 2 回目は入れない。
  - data を除いた path が求まらない画面は今どおり。
- 今の RCA-3・COV-3・PSKIP のテストが通る（期待の書き換えは、鍵の変化に伴う所だけ）。
- tsc（root と `apps/local-ui`）0。関係する単体・architecture。ブラウザの結合は、変えた所を import するものだけを 1 本ずつ。

## 4. 速さと負荷

- サイトへの読み込みの回数は変えない（入力の確かめはページの中の操作。目印を入れたときにページが出す読み取りが減るだけ）。間隔は変えない。
- 見込み: すでに読んだ 30 画面で 38 分の確かめのほとんどが省ける（2 枚目以降 1 画面の平均 98 秒 → 約 23 秒）。共通の枠の欄は、各画面の 1 回目の確かめからも省ける。効き目は次の実 Run の DTIME で確かめる。
