# BeakSight 通知の枠を閉じてから点検する（DEF-210・DEF-204）設計書

- 状態: ユーザー承認済み（2026-11-05。閉じ方・CSS で隠す条件・汎用の仕様・順番）
- 関係する文書: `2026-11-05-beaksight-discovery-coverage-design.md`（操作さがしの押す決まり、PASS_EXCEPT_DELETE）、`2026-09-23-beaksight-ui-ssot-design.md`（Rule の文言と表示）

## 1. 目的

ページを開くたびに出る通知の枠（案内・お知らせのモーダルや、隅に出る小さなダイアログ）が、点検の間ずっと画面を覆っている。そのため、次のことが起きる。

- 画面の写しが、枠の下の本文を写さない。
- 配置・覆い・見切れの判定が、枠に当たる。
- 操作さがしで、枠のボタンに押す数を使う。

同時に、枠を包む全面の透明な入れ物（`position: fixed`、背景も枠線も影もない、`pointer-events: none`）を、「画面の 100% を覆う固定の要素」と誤って数えている（DEF-204。11/4 は 899 件）。

この設計で、通知の枠を、どのサイトにも当てはまる条件で見分け、閉じてから点検する。閉じられない枠は不具合として報告し、そのときだけ CSS で隠す。

## 2. ユーザーの判断（言葉どおり）

「隠し方は「×」あるいは閉じるを押していい。それが出来ない場合も不具合検知対象になるからだ。そして不具合の場合だけCSSで隠して。また（通知の枠）は監査対象サイト固有の通知モーダルのため、設計実装時には汎用的に使える仕様に落とし込むこと。設計書や実装にサイト固有の文言が紛れないように注意して。修正順序は提案通りでいい。」

## 3. 採用する設計

### 3.1 通知の枠の見分け方（汎用。サイトの文言を使わない）

見分ける対象は、ページの読み込みが落ち着いた後に見えている要素のうち、次の条件をすべて満たすものとする。

1. `position: fixed` か `sticky` である。または、`role="dialog"`・`role="alertdialog"`・`aria-modal="true"`・`<dialog open>`・`[popover]` の表示中の要素である。
2. ヘッダ・ナビ・フッタの landmark（`header`・`nav`・`footer`・`role="banner"`・`role="navigation"`・`role="contentinfo"`）ではなく、その中にもない。
3. 閉じるボタンを中に持つ。閉じるボタンの見分けは、次のどれかに当たる、押せる要素（button・`role="button"`・a）とする。
   - 名前（見える文字か `aria-label`・`title`）が、閉じる語の閉じた一覧に当たる。一覧は `src/discovery/classification-words.ts` に置く。日本語の「閉じる」「×」と、英語の「close」「dismiss」の類。サイトの文言は入れない。
   - 文字が `×`・`✕`・`✖` だけである。
4. 描く面の大きさの閾値（名前つきの定数。既定 60%）は、閉じるボタンのない枠を 3.4 の不具合に数えるかの判断だけに使う。閉じるボタンのある全面のモーダル（閾値を超えるもの）も、ほかの枠と同じく閉じるボタンを押す。押しても残れば、3.4 の不具合の扱いに入る（2026-11-06 改訂。ユーザーの「× か閉じるを押していい」に合わせた）。

入れ子の場合は、閉じるボタンを持ついちばん内側の要素を枠とする。

### 3.2 閉じ方（見るだけの点検と操作さがしの両方）

- 落ち着いた後、Collector の測定の前に、見つけた枠の閉じるボタンを押す。
- 1 ページで押すのは、枠ごとに 1 回、全部で名前つきの上限（既定 3 回）まで。
- 押した後に出るサイトの送信は、監査の段の判定で扱う（PASS_EXCEPT_DELETE。削除・危険な語・読まないパス・資格情報の守りは今のまま）。
- 押した後に、名前つきの時間（既定 1 秒）まで、枠が消えるのを待つ。
- 押したことで画面が移った場合は、押さなかったものとして読み込み直さない。移ったことを記録して、そのページの点検をそのまま続ける（今の Interaction の移動の扱いに合わせる）。→ 2026-11-06 の SREV-1106 で 3.2.1 に改訂。

#### 3.2.1 閉じる押下の守り（SREV-1106 を受けた改訂）

閉じる押下は BeakSight が押す操作なので、ページが自分で出す送信（AS-c）より狭く扱う（ユーザーの AS-c のときの言葉「BeakSight が押す時は意図をもって制御」）。

1. **押す期間:** 押す直前から、消えるのを待つ時間の終わりまで。
2. **見るだけの点検の押す期間の送信:** PASS_EXCEPT_DELETE に加えて、送り先を許可の Origin と承認したサービスの Origin に限る。URL に資格情報（userinfo、資格情報の名前の query）を持つ要求も止める。止めたものは記録する。
3. **操作さがしの押す期間の送信:** 操作さがしの決まり（押して出た送信は届けない）に合わせる。押す期間は凍結の決まりで扱い、読み取り（凍結中の読み取りの決まり、DEF-208-1）だけを通す。
4. **押す期間の main frame の移動:** 届けない（止めて記録する）。移動を試みたビューポートは、閉じられない枠として扱わず、そのビューポートを PARTIAL（理由 `NOTIFICATION_DISMISSAL_NAVIGATION_BLOCKED`）にして、誤りの画面を測らない。読み込み直しはしない。
5. **閉じるボタンにしない要素:** 次は候補から外す。
   - `a` のうち、`href` が空・`#` だけ・`#` で始まるもの以外（文書の移動、外部スキーム、`download`、`target` が `_self` 以外を含む）。外部スキームの判定は、操作さがしの `pointsToExternalScheme` を共通の部品にして使う。
   - 名前が、閉じる語か閉じる記号だけでないもの。ただし「〈目的語〉を閉じる」「Close 〈目的語〉」の形で、目的語が次のどれかなら当てる。
     - 枠そのものの名前（`aria-label`・`aria-labelledby`・枠の中の最初の見出しの文字）と一致する。
     - 汎用の目的語の閉じた一覧（通知・お知らせ・案内・ダイアログ・メニュー・パネル・ウィンドウ・バナー・メッセージ、notification・notice・dialog・modal・popup・banner・panel・message・menu・window）に当たる。一覧は `classification-words.ts` に置き、サイトの文言は入れない。
   - 危険な語の一覧に、ログオフ・サインアウト・sign off を足す。
6. **枠を押すたびに読み直す:** 前の押下で DOM が変わっても、後の枠を正しく押す。時間の上限で打ち切ったときも、押した数と押した枠を記録に残す。

#### 3.2.2 再レビュー（SREV-1106 の 2 回目）を受けた改訂

1. **押す期間の終わり:** 見るだけの点検では、そのビューポートで最初に閉じる押下か隠しをした時から、そのビューポートの収集の終わり（Context を閉じるまで）を押す期間とする。操作さがしは、今のとおり凍結まで。理由: 押した後に遅れて出る、許可の外への送信と移動を止めるため。
2. **隠しも押す期間に入れる:** CSS で隠す処理も、押す期間の中で行う（見るだけの点検と操作さがしの両方）。
3. **枠の名前を目的語として当てるときの条件:** 次のすべてを満たすときだけ当てる。
   - ボタンに見える文字がない（アイコンだけか、閉じる記号だけ）。名前は `aria-label`・`title` から来る。
   - 目的語が、壊す操作の目的語の閉じた一覧（アカウント・口座・契約・会員・チケット・注文・申込・予約、account・subscription・membership・ticket・order・booking・contract・plan など）に当たらない。一覧は `classification-words.ts` に置く。
   汎用の目的語の一覧に当たる場合は、今のとおり当てる。
4. **押す期間に止めた移動とポップアップを、違反にしない:** 押す期間に止めた main frame の移動は、Guard が止めたもの（予期した失敗）として登録する。押す期間に開いたポップアップは、Guard が止めたポップアップとして扱う。どちらも、そのビューポートは PARTIAL（`NOTIFICATION_DISMISSAL_NAVIGATION_BLOCKED`）にし、Run は止めない。操作さがしでは、その画面の発見を続ける。
5. **同じ文書の中の移動（`#` の変更、`pushState`）は、移動と数えない。**
6. **`<form method="dialog">` の中のボタン:** ネットワークへ送らないので、閉じるボタンの候補にしてよい。
7. **限界:** ページが自分で付けた `Authorization` ヘッダの、同じ Origin への送信は、押す期間でも PASS_EXCEPT_DELETE で通す（BeakSight の資格情報ではない）。

#### 3.2.3 3 回目のレビュー（SREV-1106 の 3 回目）を受けた改訂

1. **セッションの切れ（N-I1）:** 押す期間に止めた main frame の文書の移動の先が、セッションの切れの画面（`sessionLostPathPrefix`）なら、今の止めた転送（`BLOCKED_REDIRECT`）と同じく、セッションの切れと判定する。
2. **枠の名前を目的語にする経路（N-I2）:** 許しの一覧の形（枠の名前が汎用の目的語の一覧に当たるときだけ）にはしない。本来の枠の題はサイトごとの語で、汎用の一覧に入らないため、その形では本来の目的（どのサイトの通知の枠も閉じる）が果たせない。代わりに次のとおりにする。
   - 壊す操作の目的語の一覧は、日本語と英語を対にして持ち、対が揃うことをテストで確かめる（「プラン」を足す。ワークスペース・プロジェクト・案件・ルーム・チャンネル、workspace・project・case・room・channel も足す）。
   - 残る経路は限界とする: 見える文字のない、枠の名前と同じ目的語の閉じるボタンが、一覧にない語で壊す操作をする場合は押す。そのときも、DELETE・危険な語・読まないパス・許可の外の Origin・資格情報つきの URL への送信と、画面の移動は届かない（3.2.1・3.2.2）。
3. **操作さがしで移動を止めた画面（N-I3）:** 閉じる押下か隠しの押す期間に、移動かポップアップを止めた画面は、候補 0 件の READ にしない。理由つきで読めなかった画面（理由 `NOTIFICATION_DISMISSAL_NAVIGATION_BLOCKED`）として記録する。読み込み直しはしない。
4. **限界（N-M1）:** 見るだけの点検で、隠しを見たページの、同じ Origin への読み取りでない送信（削除のほか）は通す（PASS_EXCEPT_DELETE）。

#### 3.2.4 4 回目のレビュー（SREV-1106 の 4 回目）を受けた改訂

1. **dialog の form の送信ボタン（F4-I1）:** `<form method="dialog">` の中でも、`formmethod` が `dialog` でないボタン、`formaction` のあるボタン、`form` 属性のあるボタンは、form の送信ボタンとして扱い、閉じるボタンにしない。
2. **セッションの切れの拾い口（F4-M2）:** 押す期間に止めた移動からセッションの切れを拾うのは、許可の Origin への移動だけにする（前からの止めた転送の経路と揃える）。
3. **限界（F4-M3）:** 操作さがしで、押す期間に移動を止めた画面からは、リンクを拾わない。その画面からしか行けない画面は読まない。続きでも、読んだ画面として扱い、読み直さない。
4. **限界（F4-M1）:** 3.2.3 の 2 のとおり。一覧にない目的語の閉じるボタンは押し、同じ Origin への普通の送信は届く。
5. **ワーカーのセッションの切れ:** 操作さがしと書き込みの段の呼び出しには、許可の Origin を渡さない。操作さがしは移動を止めた画面を理由つきで記録し、書き込みの段では通知の枠を閉じないため。

#### 3.2.5 押せなかった枠（fix round 6）

- 押下を試した枠は、枠の要素の番号で覚え、そのビューポートでは二度と選ばない。
- 押せなかった枠（押下が例外で終わった、合図が合わなかった）は、押した数に数えず、`NOT_DISMISSED` として隠し、`NOTIFICATION_NOT_DISMISSIBLE` を出す。
- 限界: 少し待てば押せる枠も、閉じられない枠として報告して隠す。

### 3.3 最初の 1 回の覆いの指摘

- 枠が最初に出たページでは、閉じる前の状態で、覆いの規則（`FIXED_ELEMENT_OCCLUSION` など）を 1 回だけ評価して残す。ユーザーが言う「画面の領域を狭めている」不具合を、報告に残すためである。
- 同じ枠（同じ識別。祖先の目印の形と閉じるボタンの名前で決め、path と値は入れない）が 2 ページ目から出たときは、閉じた後の状態だけを評価する。

### 3.4 閉じられない枠（不具合）

次のどれかに当たる枠は、新しい Finding（Rule の id の例: `NOTIFICATION_NOT_DISMISSIBLE`、category `LAYOUT`、severity `WARN`）を出す。

- 閉じるボタンがない（3.1 の 1・2 を満たし、描く面がビューポートの閾値の面積を覆う）。
- 押しても、待つ時間の後に残っている。
- 閉じるボタンが押せない（disabled）。

そのときだけ、その枠を CSS で隠す（`visibility: hidden` と `pointer-events: none` を、その要素に付ける）。隠した枠は Evidence に残す（識別と、隠した理由）。

### 3.5 透明な入れ物を、固定の要素の面積に数えない（DEF-204）

- 固定の要素の収集（`fixedElements`）に、要素そのものが描く面があるかを足す。描く面は、背景の色が透明でない、背景の画像がある、枠線がある、影がある、自分の文字がある、のどれか。あわせて `pointer-events` も足す。
- `OVERSIZED_FIXED_ELEMENT` と `FIXED_ELEMENT_OCCLUSION` は、描く面がなく、かつ `pointer-events: none` の要素を数えない。中の固定の子は、今のとおり数える。

### 3.6 記録と表示

- Evidence: ページごとに、見つけた枠、押した閉じるボタン、閉じられたか、隠したかを残す。識別は digest だけで、値と URL は残さない。
- 報告: 閉じた枠があったページ、または隠した枠があったページには、「通知の枠を閉じて（隠して）点検しました」を出す。文言は `src/presentation/messages.ts` に置く。表示面のコードを変えずに出すため、INFO の Rule `NOTIFICATION_HANDLED_BEFORE_AUDIT`（ビューポートごとに 1 件）の Finding として出す。
- 見た枠の digest は、Run の続き（checkpoint）では引き継がない。再開の後の最初のページで、同じ枠の覆いの指摘がもう 1 回出ることがある（多めに出る側で、見落としはない）。

### 3.7 既知の限界（NO-2 の時点）

- ページのスクリプトは、CSS の隠しを見て戻せる（SREV-1106 M-1）。守りは効く。戻されたときは、配置の指摘が残る。

- 消えたかは、閉じるボタンが見えなくなったかで見る。ボタンだけが消えて枠が残る作りでは、消えたと取り違える。
- Interaction の段の隔離した Context と、shadow root の中の枠では、閉じる処理をしない。
- 操作さがしでは、閉じたことを記録に残さない。画面ごとに、落ち着きの待ちが 1 回増える（約 1 秒。要求は増えない）。
- 英語の閉じる語は、ハイフンでつないだ複合の語（`close-up` など）の中では当てない。日本語の閉じる語は、名前の終わりにあるときだけ当てる（「〜を閉じる」に当たり、「〜を最小化」「閉じたタブを開く」には当たらない）。
- landmark は ARIA の決まりで見分ける。`header`・`footer` は、区分の要素（`article`・`aside`・`main`・`nav`・`section`）の中では landmark にしない。操作さがしの共通の枠の読み取り（`readLayoutLandmarksInPage`）も同じ決まりにした。

## 4. 変えないもの

- 削除・危険な語・読まないパス・資格情報の守り、送信の扱いの既定。
- 読み込みの間隔、ページの上限、押す数の上限（操作さがしの 1 画面 3 回は、閉じる押下と別に数える）。

## 5. サイトへの負荷

- 閉じる押下は 1 ページ最大 3 回で、ページの読み込みは増えない。
- 押した後の送信（「閉じた」の記録など）は、サイトの普通の動き。

## 6. テスト

- 仮のサイト（一般の文言）で、次の枠を作る。
  - 隅の通知の枠（× ボタン）。
  - 全面の透明な入れ物の中の小さな枠。
  - 閉じるボタンのない枠。
  - 押しても消えない枠。
  - 閉じると POST を出す枠と、閉じると DELETE を出す枠。
- 確かめること:
  - 閉じた後の写しと配置の判定に、枠が入らない。
  - 最初のページだけ覆いの指摘が出る。
  - 閉じられない枠で `NOTIFICATION_NOT_DISMISSIBLE` と CSS の隠しが働く。
  - DEF-204 の誤検出が出ない。
  - DELETE は届かない。
- 既存の配置・覆いの規則のテストが通る。
- 2 つの Chromium で確かめる。
- 1 ファイルずつ、`--maxWorkers 1` で流す。verify:all は流さない。
- 設計書・実装・テストに、本来の監査対象のサイトの文言や名前を入れない。秘密の語の走査で確かめる。

## 7. 実装の分け方

1. NO-1: 3.5（DEF-204）と、3.1 の見分け方の部品（純粋な関数と、ページの中の読み取り）。
2. NO-2: 3.2・3.3・3.4・3.6（閉じる、最初の 1 回、閉じられない枠、記録と表示）。見るだけの点検と操作さがしに当てる。
3. 安全のレビュー。
