# BeakSight 点検の段で、窓を閉じた後のフォーカスの戻り先を確かめる（FRET）

- 日付: 2026-11-24
- 状態: ユーザーの判断を得た（2026-11-24「案 A で進めて」。案 A = 点検の段で、窓を開くボタンと作りで分かる物だけを押して確かめ、結果を今のまとめファイルに入れる）
- 前提: ChatGPT 用のまとめファイルは点検の結果だけから作る（操作さがしの結果は入らない）。そのため点検の段で確かめる。
- 使う部品: RVP-0 の前面の窓の判定（`2026-11-24-beaksight-review-pending-evidence-design.md` 2.1）。RVP の後に行う。

## 1. 決めたこと

### 1.1 押す物（窓を開くボタンと作りで分かる物だけ）
- 主の読み込みの Desktop と Mobile の画面で（幅の走査の幅ではしない）、見えていてフォーカスできる要素のうち、次のどれかのもの:
  - `aria-haspopup="dialog"`
  - `aria-controls` の参照先が前面の窓の判定（RVP-0）に当たる、または `role="dialog"`・`role="alertdialog"` の要素
- 押さない物: form の送信の要素（`type="submit"` と、form の中の type のない button）、リンク（`a[href]` で別の場所へ移るもの）、危ない語（今の Guard の `hitsDangerousTermIn`）に当たる名前、無効の物。
- 同じ物は Run で 1 回: 共通の枠の中の物は枠の鍵、ほかは data を除いた path と識別の鍵（ISKIP・PSKIP と同じ作り。写しを作らない）。
- 数で打ち切らない。

### 1.2 確かめの手順（1 つの押す物ごと）
1. 押す物にフォーカスを当て、キーボード（Enter）で押す（キーボードの利用者の道）。
2. 落ち着きを待つ（今の落ち着きの待ち。新しい秒の値を足さない）。前面の窓が出なければ「窓が出なかった」と記録して次へ。
3. 窓が出たら、フォーカスが窓の中に移ったかを記録する。
4. Esc で閉じる。閉じなければ、窓の中の「閉じる」の名前のボタン（今の通知の枠の閉じるボタンの見分けを使う）を押す。それでも閉じなければ「閉じられなかった」と記録し、その画面の残りの押す物は確かめない。
5. 閉じたら、フォーカスのある要素が押す物か（押す物が消えていれば「押す物が消えた」）を記録する。違えば、その要素の selector と、body に落ちたかを記録する。
- 画面が移った（URL の path が変わった・文書が変わった）ら、記録して、その画面の確かめを終える。
- 確かめは、その viewport の点検の最後に行う（画像・axe・フォーカスの確かめなどの後。窓を開けた状態が他の証拠に混ざらないため）。

### 1.3 守りと負荷
- サイトへの読み込みを足さない（ページの中の操作だけ）。点検の段の送信の扱い（削除のほかは通す。BeakSight が起こした削除は止める）は変えない。押した後に読み取りでない送信が出たら、その事実を記録に残す。
- ポップアップ・別の窓・ダウンロード・外部の起動は、今の Guard の決まりのまま止める。

### 1.4 証拠と指摘
- 新しい証拠（例: `dialogFocus`。schema は新しい型を省略可で足す。版の判断が要るなら止まって報告）: 押す物の selector・名前・鍵の digest、窓が出たか、窓の中へフォーカスが移ったか、閉じ方（Esc・閉じるボタン・閉じられない）、閉じた後のフォーカスの先（押す物・ほかの要素の selector・body・押す物が消えた）、押す前と閉じた後の画像（今の撮影の部品）。
- 指摘:
  - `DIALOG_FOCUS_NOT_RETURNED`（WARN・ACCESSIBILITY）: 閉じた後、押す物が残っているのに、フォーカスが押す物に戻らない。
  - `DIALOG_FOCUS_NOT_MOVED`（WARN・ACCESSIBILITY）: 窓が出たのに、フォーカスが窓の中へ移らない。
  - `DIALOG_NOT_CLOSABLE_BY_KEYBOARD`（WARN）: Esc でも閉じるボタンでも閉じられない。閉じるボタンでは閉じたが Esc では閉じない場合は、文に事実を足す（指摘にしない）。
- 文言は messages の 1 か所。Rule Catalog に登録し、表示面のコードを変えない。押す物がない画面は、記録に「押す物なし」を残す（バンドルの数に出す）。

## 2. 受け入れ
- fixture（127.0.0.1）で: 戻る窓・body に落ちる窓・中へ移らない窓・Esc で閉じない窓・閉じられない窓・押す物が消える窓・`aria-haspopup="menu"` の物（押さない）・submit の物（押さない）・危ない語の物（押さない）・押すと path が変わる物。
- 同じ型の 2 枚目の画面で同じ押す物を押さない。
- **時間を測って報告する**: fixture で、押す物 1 つあたりの時間（窓が出る・閉じる の場合と、出ない場合）。
- tsc（root と `apps/local-ui`）0。関係する単体・architecture・UI Gate。ブラウザの結合は、変えた所を import するものだけを 1 本ずつ。

## 3. 速さと負荷
- 読み込みの回数は変えない。押す物のある画面だけ、押す物 1 つあたり、落ち着きの待ち 2 回程度の時間が増える（実測で確かめる）。同じ物は Run で 1 回。

## 設計変更履歴
- 2026-11-24 新規（ユーザーの判断に基づく）。

- 2026-11-25 独立の安全レビューの Critical 3 件・Important 3 件に対応（設計者の誤り: 1.1 で押す前の判定を `hitsDangerousTermIn` の英語の語だけにし、SD-1 の判定の 1 か所を指定しなかった）:
  - 押す物の判定は、SD-1 の操作の前の判定 `isDestructiveAction`（`R.destructiveActionFactsOf` の事実を全部渡す）と AIW の `isAiAction` の 1 か所を通す。`hitsDangerousTermIn` だけの判定は使わない。
  - 窓の中の閉じるボタンは、通知の枠の閉じるボタンの判定 `isCloseButton`（送信ボタンを除く・押すと移る物を除く・削除の物を閉じる物を除く・`isDestructiveAction`）と同じ 1 か所で選ぶ。削除の確かめの窓の中のボタンは押さない（その窓は閉じられないとして記録し、その画面の残りを確かめない）。
  - **押す期間（Enter を押してから、閉じて落ち着くまで）は、BeakSight の押下が原因の送信とみなし、読み取りでない要求をすべて止めて記録する（main frame と子の frame の両方。移動・ポップアップは今どおり止める）。** 点検の段の送信の扱い（サイトの自動の送信は削除のほか通す）は、押す期間の外では変えない。操作さがしの凍結と同じ考え方で、FRET の押下で削除・ログアウト・保存がサイトに届く経路をなくす。
  - 押す期間に読み取りでない要求を止める決まりは、2026-11-25 にユーザーが承認した（「それでよい」）。
  - 2026-11-25 fix round 1 の判断（遅れて出る要求。押して 1.5 秒後の form の送信が、押す期間の後に届き、記録にも残らなかった）: FRET はその viewport の点検の最後の段なので、**その viewport で FRET が 1 つでも押したら、押す期間の止めを、その viewport の page を閉じるまで（または BeakSight 自身の次の読み込みの前まで）続ける**。その後に点検の証拠を集める段はないので、点検の結果は変わらない。止めた要求は Guard の Ledger に残る。`lateNonReadRequestCount` は、確かめの終わりから page を閉じるまでに止めた数にする（記録を書く時点の後の分は Ledger で数える）。止めた数の口（`blocked()`）が main frame の fetch の止めを拾わない食い違いも直す。
  - （下の fix round 1 の判断で置き換えた）押す期間の後に遅れて出た要求は、止めて、Guard の記録に残す。
  - Gate (q) は、`pressDialogCheckKey` を import するファイルを `dialog-focus-check.ts` に限る。`reveal-and-capture.ts` の説明の「Enter は押さない」を直す。鍵の `accept` は、フォーカスが当たって確かめた後にする。危ない物の試験に、日本語の語・`hx-delete`・`data-method`・削除の確かめの窓の閉じるボタン・AI の名前の場面を足す。
- 2026-11-26 2 回目の独立の安全レビュー（a〜o は全部止まった。新しい経路で Critical 1・Important 3）に対応（fix round 3）:
  - 押す期間と止めの続き（hold）の間は、新しく開いた WebSocket の接続を止める（その間に開いた接続の送る frame も届けない）。押す前から開いていた接続は、サイト自身の通信として今どおり通す。止めたことは Guard の記録に残す。
  - 押す期間と hold の間は、読み取りの method でも、危険な語・ログアウトの語の path（巡回の判定の 1 か所。写しを作らない）に当たる要求を止める。
  - hold は、閉じる前の離れる手順（`#leavePagesBeforeClose`）の前に外す（SD-2 2.4 の閉じる時の後始末の送信を届けるため）。FRET の後から離れる手順までの間（読み込みの間隔の待ち）は hold を続ける（点検の証拠はもう集めないので結果は変わらない。押下の遅れて出る送信を止めるため。2026-11-25 にユーザーへ「その画面を閉じるまで止めたまま」と伝えた範囲の中）。
  - FRET の記録の数（`nonReadRequestCount`・`lateNonReadRequestCount`）は、押下が原因とは限らない（サイトの自動の送信を含む）ことを型の説明・バンドルの説明の文に書く。
  - 通知の枠と FRET が共有する送信ボタンの見分けは、属性の selector でなく IDL の `type` と `form` で判定する（`<button type="x">` は送信ボタン。`discoveryCandidateElementOf` と同じ形）。
  - 限界（Minor）: `announceOwnMainFrameNavigation` で hold を外してから新しい文書が来るまでに、押下が原因の送り直しが届きうる。今の PageAuditor は viewport ごとに Context を閉じ、FRET の後に同じ page で BeakSight の読み込みをしないので、今の画面の道では届かない。同じ page で次の読み込みをする作りにするときは、この所を見直す。
- 2026-11-26 3 回目の独立の安全レビュー（2 回目の指摘は直った。止めすぎも直った）に対応（fix round 4）:

  - 押す期間に、押す前から開いていた WebSocket が送った frame の数を、FRET の記録に残す（止めない。設計どおり通す）。
  - 限界として受け入れる（設計者の判断。SD-2 の設計書 3 章の限界「押す前に見えない削除は止めない」と同じ形）: 押下のときにページが pagehide・unload に登録した送信（keepalive の DELETE・sendBeacon）は、閉じる前の離れる手順で、サイト自身の後始末と見分けられずに届く。hold を離れる手順まで続けると、サイト自身の後始末まで止める（2 回目の止めすぎ）。代わりに、FRET が押した page で、離れる手順の間に通した読み取りでない要求の数を、Guard の記録に残す（後から分かるようにする）。窓を開くボタンが閉じる時の削除を登録する作りは、実際の画面では考えにくい（推測）。
