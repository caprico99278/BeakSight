# 操作さがしの押下で操作をせずに待つ時間と、押す対象を見失う形（DEF-295。追補設計書、2026-11-19）

## 1. 目的と事実
- ユーザーの指摘（2026-11-19）: 操作さがしでページの操作をしないまま待つ時間が想定より長い。
- 実環境の途中の記録（数だけ）: 97 画面のうち 39 画面が `STAGE_NEVER_QUIET`、押下の結果 `STAGE_NEVER_QUIET` 349（1 画面で最大 46）、`TARGET_NOT_FOUND` 3952 / 11010（36%）。
- 調べ（DQW。127.0.0.1 の fixture で測った）:
  - 見張りは 1 画面に 1 つ（`discovery-run.ts` の `watchDiscoveryScreen`）。Playwright の 1 手は期限なし（`NO_STEP_TIMEOUT = 0`）。
  - 返らないのは `locator.click`（と hover）。止まらない・覆われる・見えない対象で、準備ができるのを待ち続ける。読み取り・落ち着きの待ちは返る。
  - 形 (A): 押している所の外（選択肢の確かめ `chooseOption` の radio の click・作り直しの押下 `replayStep`・段の読み直し・`typeLoneFields`）で止まると、止めた手が特定されず、残りの対象の全部が `STAGE_NEVER_QUIET`（1 回の止まりで 6 件全部）。
  - 形 (B): 押すたびに止まり、読み込み直しのたびに 180 秒待つ（6 件で読み込み 6 回・6 × 180 秒）。
  - 押さずに確かめる呼び出し `click({ trial: true })` は、pointerdown・mousedown・click を出さない（scroll と hover の事象だけ。今の押下と同じ）。準備ができていなければ窓の長さで判定、できていれば約 40 ミリ秒。
  - `TARGET_NOT_FOUND` の発生元: 見えない対象を押す前に除く（狭い画面用の複製・閉じたメニュー）、押下の後に祖先の並びが変わって見分けの鍵が合わない（同じボタンが新しい候補として足され二重に数えられる）、作り直しの押下が再現できないときに残りの全部に付く、押す直前の読み直しで見つからない。id 属性は鍵に入らないので、描画の順で替わる id は原因でない。

## 2. 決まり
1. **押す前の準備の確かめ（案 2）**: 押す所の全部（`pressOne`・`chooseOption` の radio・作り直しの押下）で、本当の押下の前に `click({ trial: true })` で準備を確かめる。待ちは今の名前つきの値 `pageSettle.openDataRequestQuietMs`（「進みが止まった」とみなす長さ。DEF-283 の C と同じ意味）で切る。だめなら理由を付けて、同じ文書のまま次の対象へ進む（読み込み直さない）。本当の押下は今のまま期限なし（押すのに時間のかかる押下を切らない）。見張りは残る経路の受け皿のまま。
   - 動き続ける対象は、今の DEF-289 の案 2（止まっていない対象を、無効でないと確かめてから力で押す）を確かめの前に通す（順を逆にすると今押せている押下を失う）。
   - 理由は、確かめの結果ごとに分ける（止まらない・覆われた・見えない）。今ある理由（`COVERED_BY_OTHER` など）に合うものはそれを使い、足すなら閉じた一覧に値を足す（版は今のまま）。
2. **覆いの確かめと置き直し（案 1 の一部）**: 欄に入れた後・radio の選択・作り直しの押下でも、hit-test（`submitterHitOf`）と置き直し（AUD-2 の `reachTargetOf`。`end`・`center`・`start`）を使う。`reachTargetOf` を見るだけの点検と操作さがしの共通の部品へ移す（書き写さない）。
3. **止めた手を特定する（案 3′）**: 押している所の外で見張りが段を終えたときも、そのとき動いていた手（選択肢の確かめ・作り直し・段の読み直し・打つだけの欄）を記録し、その対象だけに理由を付け、残りは今の DEF-289 の案 3 のとおり読み込み直して押す（まとめて全部に理由を付けない）。
4. **見えないので除いた対象（T-1）**: 押す前に見えないので除いた対象は、`TARGET_NOT_FOUND` と分けた理由（例 `TARGET_NOT_VISIBLE`）にする。数の意味を正しくし、次の実 Run で発生元の内訳を数える（T-2 の結び直し・T-3 の作り直しの失敗の扱いは、内訳を見てから決める）。
5. **作り直しの失敗（T-3）**: 作り直しの押下が再現できないとき、残りの全部に `TARGET_NOT_FOUND` を付ける形は、まず理由を分けて（例 `STATE_NOT_REBUILT`。今ある値に合えばそれ）数えるだけにする。押し方は変えない（内訳を見てから決める）。

## 3. 負荷と安全
- 読み込みは増えない（形 (B) では減る）。サイトへの要求は増えない（確かめの呼び出しは押す事象を出さない）。
- 凍結・守り 2〜8・押す時点の確かめ・削除の判定は変えない。押下の部品を変えるので、独立レビュー（実機の実験、両方の Chromium）を受ける。
- 見込み（部品の測りから計算。全体での測りは実装の後）: 覆われた 6 件の画面で、本番の 18 分 → 約 30 秒・読み込み 1 回。
