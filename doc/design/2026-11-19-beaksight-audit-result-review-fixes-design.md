## 4. AUD-1 の決まり
### 4.1 S-01a 文字の二重
- 可視の文字の節の収集（`src/evidence/accessibility-ax.ts` の `labelSegmentsOf` の周り）で、たどった AX の節を覚え、同じ節は 2 回数えない。`display: contents` の入れ物で同じ節を 2 回たどる形が原因（fixture で `["保存","保存"]` を確かめた）。
- 別の節（別の操作要素）で同じ文字なら、今どおり両方数える。

### 4.2 S-03a 「隠しました」の文と数
- 指摘の文の「その枠を隠しました」は、実際に隠した（`hidden=true`）ときだけ付ける。隠せなかった・期限切れ・移動の後は付けない（`src/rules/layout-rules.ts` の周り）。
- 主状態の記録に、幅の走査（stress）で隠した数を、主の読み込みの数と分けて任意の項目で足す（`page-auditor.ts` の `hiddenCount` の周り）。

### 4.3 S-12 集計を分ける
- 点検のための操作の記録（今の `NOTIFICATION_HANDLED_BEFORE_AUDIT` の INFO）は、指摘の総数・重さごとの数・確かめ待ちの数に入れない。Finding の記録は残し、規則の一覧（Rule Catalog）で「操作の記録」の種類を 1 か所で持ち、表示用モデル（`view-model.ts`）がその種類で別に数える。表示面では作り直さない。
- 読み込みに失敗したページを、見なかったページ（SKIPPED）と分けて数える（`failedPageCount` の類）。今の `uncollectedPageCount` の意味は変えず、失敗の数を別に出す。
- 利用者に見せる語は短く（「通知を閉じるなどの操作の記録 N 件」「読み込めなかった画面 N」など。語は messages の 1 か所）。

### 4.4 S-06 文字切れの場所
- 行の切れの判定（`src/evidence/layout-collector.ts` の行の判定の周り）で、文字と外枠の間にスクロールできる祖先があるときは、その祖先の箱で判定する。
  - 祖先の箱が外枠に収まる → 内側のスクロールで見えるので、外枠の文字切れにしない。
  - 祖先の箱が外枠からはみ出す → 「内側のスクロール領域の端が外枠で切れる」形として、その祖先を対象に指摘する（本当の問題なので残す）。
- 固定の覆いの `SCROLL_AVOIDABLE`・`INITIAL_ONLY` を、確信度を下げる条件に足す（`finding-groups.ts` の確信度の条件の周り）。重さは変えない。

## 5. AUD-2 の決まり（S-03b・開いた状態の点検）
### 5.1 操作用の小窓は隠さない
- 前回の Run で、操作用の小窓（予約の詳細など、`aria-modal`・`dialog` の showModal・role=dialog で背景を塞ぐもの）を「閉じるボタンのない通知」とみなして隠し、背景の暗転だけが残った画像になった。
- 決まり: モーダルの小窓（`aria-modal="true"`、`dialog` の modal で開いたもの、role=dialog で背景を覆う暗転の要素を伴うもの）は、閉じる語がなくても隠さない。「開いたまま点検した状態」として記録し、そのまま点検する。
  - 通知（role=dialog でも、モーダルでなく、背景を塞がない帯・吹き出しの類）の扱いは今のまま。
  - 閉じるボタンの有無は、文字のボタンに加えて、名前（aria-label・title・画像の alt）が閉じる語のアイコンだけのボタンも見てから決める（今の語の一覧と境目の決まりを使う。新しい語の一覧は作らない）。
- 背景が操作できないのは通常のモーダルとして指摘にしない。小窓の中の操作要素が別の要素に塞がれる形だけを指摘にする（今の重なり・覆いの Rule が小窓の中で働く）。
- Esc は押さない（小窓を隠さないので要らない。Passive の Context の操作を増やさない）。

### 5.2 隠したときの記録
- 本当に隠した（`hidden=true`）枠は、隠した対象・幅・スクロール・結果を Evidence に残す（今の記録に足りない項目だけ任意で足す）。隠す前の画面の画像は、隠したときだけ 1 枚（新しい読み込みはしない）。
- 前処理で状態を変えたページの指摘には、その旨の印を付ける（今の文の印を、AUD-1 の決まり＝隠したときだけ、で使う）。

### 5.3 押して小窓が開いたことも開いた状態の根拠にする
- 今は、押した要素そのものの属性（aria-expanded など）が変わったときだけ `VERIFIED` で、開いた状態を点検する。属性の変わらないボタンで小窓が開く形は `NO_OBSERVABLE_CHANGE` になり、前回の Run で開いた状態の点検は 0 件だった。
- 決まり: 押した後に、押す前になかったモーダルの小窓・dialog が見えるようになった事実も `VERIFIED` の根拠にする。小窓の判定は 5.1 と同じ部品（1 か所）を使う。読むだけで、要求は増えない。
- 負荷: 開いた状態の点検の入れ子の押下 1 回ごとに、使い捨ての Context の読み込みが 1 回増える（REV-AUD2 の M-1）。上限は今の `maxInteractionsPerPage`（1 ページ 20 回）の中で、読み込みの間隔の決まりも今のまま。
- REV-AUD2 の後の判断（2026-11-19）:
  - 開いた状態がモーダルのときは、入れ子の候補を小窓の中に限る（背景は aria-modal の意味で操作できない）。覆われた対象は押さずに理由を残す（DEF-294）。
  - 暗転の要素は、全面の fixed で、小窓の外に見える文字・操作要素を持たないものに限る（全面の固定のアプリの殻を暗転とみなさない。I-2）。
  - 最初の読み込みの閉じるボタンのない全面のモーダル（同意など）は隠さず、その状態をページの本当の姿として点検する（背景の点検は狭くなる。限界として spec に書く。I-3）。閉じる語のボタン（アイコンを含む）のある小窓は、今どおり閉じて背景を点検する。

### 5.4 レビュー

## 6. AUD-3 の決まり（S-05 キーボードの移動）
### 6.1 今の形と問題
- フォーカスの確かめ（AUD-4d・EV-1。`src/evidence/focus-check-collector.ts`）は、画面の外か 1px 以下のフォーカスできる要素に、直に `focus()` を当てて、現れるか・押せるかを読む。方法は `DIRECT_FOCUS` だけ。
- 前回の Run で、フォーカスの罠の端に置く 0×0 の守りの要素（循環用の span）と本物のボタンが同じ重さで指摘になった（117 件）。指摘と項目の対応は selector の最初の一致で引いていて、別の項目を根拠にしうる。直の focus が、通常の Tab の移動でも同じとは限らない。

### 6.2 決まり
1. **項目の種別**: 項目ごとに種別を記録する。`GUARD`（循環の守り: 幅か高さが 1px 以下、名前がなく、role も押せる要素の型もない `[tabindex]` で、小窓・フォーカスの罠の始めか終わりにあるもの）・`CONTROL`（押せる要素の型か role を持つもの）・`UNKNOWN`（どちらとも決められないもの）。判定はブラウザの中の 1 か所の読み取りで、根拠（大きさ・名前の有無・型・位置）も記録する。
2. **指摘の扱い**: 指摘は消さない。`GUARD` の項目の指摘は確信度を下げ、文で「循環用の守りの部品の可能性」と分ける（重さは今のまま）。`UNKNOWN` は今のまま。
3. **1 対 1**: 指摘と項目を、selector でなく項目の番号（Evidence の中の位置）で結ぶ。同じ Evidence の別の項目を根拠にできない作りにする（画像の領域・説明の根拠も同じ番号で引く）。
4. **通常の Tab の確かめ**: 直の focus で「隠れたまま」などの指摘の候補になる項目が 1 つ以上ある画面だけ、文書の先頭から Tab を押して `activeElement` の並びを読む。
   - 記録: 候補の項目ごとに、Tab で届いたか、届いたときに画面の中に見えたか（スクロールの後の矩形・hit）、遮る要素があったか。直の focus の記録とは別の欄（方法 `SEQUENTIAL_TAB`）。
   - 終わり: 同じ要素に戻った、文書の外（body・アドレス欄）へ出た、または候補の項目を全部確かめた。数の上限は置かない（構造の事実で終える）。待ちは今の位置が落ち着く読み（続けて 2 回同じ）を使い、新しい秒の値を足さない。
   - Tab だけを押す（Enter・Space は押さない）。読み込みと BeakSight の要求は足さない。フォーカスでページが出す送信は Guard の決まりのまま扱う。ほかの証拠を集め終えた後に行い、終えたら元のフォーカスと位置に戻す（今の確かめと同じ）。
   - Shift+Tab は 1 版目では行わない（逆順の到達は Tab の並びの逆で足りるため。過剰な仕様を避ける）。
5. **判定**: Tab で届き、届いたときに見える項目は、直の focus で隠れたままでも「通常の操作では見える」として確信度を下げる。Tab で届かない項目は「キーボードでは届かない」事実を文に足す（指摘は残す）。

### 6.3 版・負荷・レビュー
- page.json は任意の項目（種別・根拠・Tab の記録）と閉じた一覧の値（`SEQUENTIAL_TAB`、種別）の追加で、版は今のまま。
- サイトへの読み込みは増えない。Tab の押下は、候補のある画面だけ、フォーカスできる要素の数のおよそ 2 倍まで（下の AUD-3 の Blocker の判断）。
- **AUD-3 の Blocker の判断（2026-11-19）**: Chromium では直の focus の位置が Tab の始まりとして残り、blur・選択の解除・body の focus・CDP の命令では戻せない（両方の Chromium で測った）。案 A（回り込み）を採る: 外（body・文書の外）へ出るまで Tab を押し、そこから記録を始め、もう一度外へ出たら終える。読むだけで DOM を書き換えない。案 B（body に一時的に tabindex を付ける）は DOM の書き換えがページに見えるので採らない。案 C（今の位置から一周）は罠の後の要素を届いたと誤るので採らない。
- Passive の Context でキーを押すので、独立レビュー（実機の実験つき）を受けてから AUD-4 へ進む。
- **REV-AUD3 の後の判断（2026-11-19）**:
  - Tab の確かめは主の読み込み（ビューポートごと）だけで行う。幅の走査と開いた状態では行わない（届くかは DOM の順で決まり幅ではほぼ変わらない。開いた状態は凍結の中で押せない。負荷の過剰を避ける）。
  - 外へ出る前に前に見た要素に戻った・iframe の中へ入って `activeElement` が変わらない・確かめ始めたときのフォーカスできる要素の集まりの外へ出た（押すたびに要素が増える画面）ときは、「確かめられなかった」として記録を変えずに返す（残りの候補を「届かない」と決めない）。
  - フォーカスが値を入れる要素（EV-4 の `EDITABLE_SELECTOR` と同じ判定）にあるときは、Tab を押す前に終える（Tab で欄の中身を変え、サイトの自動保存を起こさない）。
  - 項目の番号は指摘と項目を結ぶためだけに残し、fingerprint と候補群の鍵には入れない。
  - 種別の「小窓の端」は、小窓（dialog・role=dialog/alertdialog・aria-modal）の中だけで判定する。
  - 位置が落ち着くのを待つ読みは、今の確かめの期限で終える（新しい秒の値は足さない）。
  - Tab の keydown でページが出す削除の通信は、2026-11-16 の決まり（サイト自身の通信は削除のほか止めない、BeakSight が自分で起こした削除だけ止める）のとおり通して記録する。

## 7. AUD-4 の決まり（S-04 座標・画像・状態の一致）
### 7.1 今の形と問題
- 動かして撮る規則（重なり・覆い・フォーカス・見切れ・横スクロール）は、TII・EV-2 で「写ったか」（`targetInImage`）と保留（`FINDING_HOLD_REASONS`）を持つ。ほかの指摘は、矩形を読んだときと画像を撮ったときの文書のスクロールの差（dx・dy）だけを足して、矩形を画像に重ねている（`src/core/finding-image-regions.ts`）。
- 祖先のスクロール（内側のスクロール領域）・DOM の変化・前処理（通知を隠す）の差は見ていない。前回の Run で、幅 639 で負の座標・hit 0 と記録されたリンクが、その画像では画面の中に写っていた。

### 7.2 決まり
1. **状態の印を両方で記録する**: layout を読んだときと、状態の画像を撮ったときに、同じ部品で「状態の印」を読んで記録する。中身: 文書のスクロール、スクロールできる箱（`isScrollableBox`）ごとの selector とスクロールの位置、隠した通知の枠の数（AUD-1・2 の記録）、DOM の構造の要約（DUP の作りの鍵の部品のように値を持たない digest）。読むだけで、要求・読み込みを足さない。
2. **重ねる前に比べる**: 動かして撮る規則でない指摘を画像に重ねるとき、その指摘の対象の祖先のスクロールできる箱の位置、通知の枠の数、DOM の要約が、layout と画像で違えば、保留の理由 `EVIDENCE_MISMATCH`（証拠が合わない・撮り直し待ち）を付ける。文書のスクロールの差は今どおり dx・dy で合わせる。
   - 祖先の箱の位置の差だけなら、矩形をその差で動かして重ね、保留にしない（箱の中で見える範囲に入るときだけ。入らないなら `EVIDENCE_MISMATCH`）。
   - 指摘は消さない。保留は表示用モデルの確かめ待ちに数える（EV-5 の再開の列にも入れる）。
3. **動かして撮る対象は広げない**（撮る数と時間が増える過剰な仕様を避ける）。
4. **色差の背景色と画像の画素の照合は 1 版目では行わない**（画像を読む依存を足さない）。限界として spec に書く。
5. **AUD-4 の後の判断（2026-11-19）**: 文書全体の DOM の要約の比べはやめる（関係のない所の変化で画面の指摘が全部保留になり、判定できないが増えすぎる）。代わりに、状態の画像を撮る直前に layout の対象の矩形を読み直し、その指摘の対象の矩形が（スクロールの差を合わせた後で）変わった・見つからない・複数に当たるときだけ `EVIDENCE_MISMATCH`。

### 7.3 版・負荷
- page.json は任意の項目（状態の印）の追加、`FINDING_HOLD_REASONS` に値を 1 つ足す。版は今のまま。
- 読み込み・要求は増えない。状態の印の読み取りは、layout の読み取りと画像の撮影ごとに 1 回。

## 8. AUD-5 の決まり（S-02・S-07・S-01b）
指摘は消さない。区分・確信度・文・まとめ方で分ける。重さは今のまま。

### 8.1 S-02 画像の上の編集ボタン
- 今: 外しているのは、要素そのものの `position`・`z-index` が static でないものと、片方がもう片方を含む組だけ（`src/audit/overlap-pairs.ts`・`src/evidence/layout-collector.ts`）。画像の上の位置指定の入れ物の中の static なボタンは指摘になり、画像とボタン、画像とボタンの中の svg がそれぞれ別の組になる。
- 決まり:
  1. layout の要素の事実に「位置指定（absolute・fixed・sticky、または relative と z-index）の祖先が、組のもう片方と同じ入れ物の中にあるか」の印を足す（任意の項目）。
  2. 片方が画像（img・picture・svg の画像・背景の画像を持つ箱）で、もう片方が、その画像と同じ入れ物の下の位置指定の入れ物の中の押せる要素のとき、「意図した配置の候補」として確信度を下げ、文で分ける。
  3. 押せる要素の中の子（svg・アイコン）と画像の組は、その押せる要素と画像の組と同じ 1 件にまとめる（押せる祖先で寄せる）。
  4. 押せる要素どうし、入力欄との重なり、文字が画像の外へはみ出して別の部品にかかる形は、今どおり残す。

### 8.2 S-07 題名の重なり
- 今: `DUPLICATE_PAGE_TITLE` は文書の鍵だけで判定し、同じ編集フォームの別のレコード・日付違いを、別の機能の画面の同じ題名と同じに数える。
- 決まり: 同じ題名のページのうち、作りの鍵（DUP の `auditPageTemplateKeyOf`。SSOT として使い回す）が同じものは「同じ画面の別のデータ」として 1 つの群にまとめ、確信度を下げ、文で分ける。作りの鍵が違う組は今どおり指摘にする（疑わしければまとめない）。

### 8.3 S-01b 名前の不一致の区分
- 今: `labelInName.labelClass`（`SUPPLEMENT_ONLY_MISSING`・`MAIN_LABEL_MISSING` など）は、群の中に 1 つでもあれば群ごと確信度を下げる（`some`）だけで、集約の鍵に入らない。日付の形の違いなどは `MAIN_LABEL_MISSING` になる。
- 決まり:
  1. `labelClass` を群の鍵に入れ、区分の違う指摘を同じ群にしない。確信度は指摘ごとの区分で決める。
  2. 新しい区分 `NORMALIZED_MATCH`（全角・半角、空白、区切りの記号、数字の並びをそろえると主ラベルが名前に含まれる）を足す。合格にはせず、確信度を下げ、文で「表記の違いの候補」と分ける。axe の元の検出は残す。
  3. 日付・曜日の表記の違い（「月/日(曜)」と「年月日曜」）は、数字の並びとして比べて `NORMALIZED_MATCH` になりうる。
- 版: `labelClass` の閉じた一覧に値を 1 つ足す（版は今のまま）。

## 9. AUD-6 の決まり（S-08〜S-11）
### 9.1 S-08 準備の状態が分からない形
- 今: 落ち着きの待ちが `NOT_COMPLETED`（・`PARTIAL`）で終わった状態と、落ち着きの記録がない状態を、準備ができたものとして扱う（`page-readiness.ts` の `stateReadyOf`）。
- 決まり: その状態の内容の規則（`PAGE_READINESS_RULE_IDS`）の指摘は、保留の理由 `PAGE_READINESS_UNKNOWN`（準備の状態が分からない）を付ける（確かめ直しで同じ指摘が出たなら今どおり）。特定の画面の方針を全体に広げない。
- 影響を測った（設計者、2026-11-19。実環境の Run の page.json の数だけ）: 11-17 の Run は 434 ビューポートのうち `NOT_COMPLETED` 3（2 ページ）、11-19 の Run は 454 のうち 4（2 ページ）。判定できないの増え方は 1 Run で数件。
### 9.2 S-09 静的な警告の文
- `FORM_WITHOUT_ACTION`（INFO）の利用者向けの文を、事実の記録の文にする（「送り先の指定がない form がある」。送れないとは書かない）。
- `cursor: not-allowed` だけの注記は「押せない形の見た目の指定がある（実際に押せないかは確かめていない）」にする。判定と重さは変えない。
### 9.3 S-10 抜粋の省略と名前の根拠
- axe の HTML の抜粋が axe 自身の切り詰めの印（末尾の `...`）で終わるときは `truncated: true` と、切り詰めの種類 `SOURCE_TRUNCATED`（元が切り詰めた）を記録する（今は固定で false）。秘匿・未取得・空値と区別する。
- axe の結果の `relatedNodes`（重複 ID の他の出現・参照先）の目印（selector だけ。値・文字は持たない）を記録する。
- 名前の計算の根拠（`nameSource`）を読む範囲を、名前の規則（button-name・link-name・input の名前など）の違反の要素にも広げる（CDP の読み取りが増えるだけで、サイトへの要求は増えない）。
### 9.4 S-11 性能の 1 回だけの測り
- LCP など性能の指摘に「1 回の測り」の印を付け、確信度を下げ、文で「1 回の測りです」と分ける。測り直しは足さない（読み込みが増えるため。負荷の方針）。
- 未観測の INP を合格と数えないのは対応済み（変えない）。
### 9.5 版・負荷
- page.json は任意の項目・閉じた一覧の値の追加で、版は今のまま。ふだんの Run の読み込み・要求は増えない。
- AUD-6 の後の判断（2026-11-19）: `PAGE_READINESS_UNKNOWN` と AUD-4 の `EVIDENCE_MISMATCH` は EV-5 の再開の列に入るので、時間切れの後の再開でだけ、そのページの読み直しが起こりうる（今の移動の間隔の中、指摘が減らなくなったら終わる。実環境の数から 1 Run で数ページの見込み）。今の `PAGE_NOT_READY` と同じ扱いとして可とする。
