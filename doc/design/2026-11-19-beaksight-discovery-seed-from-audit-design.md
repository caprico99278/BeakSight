# 操作さがしに点検の段の画面を最初から全部引き継ぐ（追補設計書、2026-11-19）

## 1. 目的
- ユーザーの指摘（2026-11-19）: 監査の段で 200 ページ以上を見つけているのに、操作のさがしの段でまた 1 からページを数えている。
- 事実（実行中の操作さがしの途中の記録。数だけ）: 点検の段から引き継ぐのは、登録の画面らしいリンクとその一覧の画面だけ（OP-J の J1・OP-R の R2。今回 48）。残りは入口から BFS でたどり直す（読んだ 94、待ち 40）。同じ URL の読み直しは 0。全部の数が後から増えていくので、進み具合の全部の数が始めから分からない。
- ユーザーの判断（2026-11-19）: 直す（AUD-1〜6 の後で）。
- この設計書は、`2026-10-27-beaksight-one-pass-flow-design.md` 4.1.6（OP-J の J1）の「続けて、今どおり入口から読む」の部分を置き換える。

## 2. 決まり
1. まとめて実行の連鎖で、直前の点検の段の Run のディレクトリ（`chainedAuditRunDirectory`）を渡されたときは、その段で読んだ画面（`pages/` の各 `page.json` の `pageUrl`。点検の段の順＝ページの ID の順）を、操作さがしの待ち行列に最初から全部入れる。
   - 順: 登録の画面らしいリンクとその一覧の画面（今の OP-J・OP-R。ページの上限に数えない）→ 点検の段で読んだ画面（点検の順）→ 操作さがしの中で見つかった新しい画面（リンク・押して出た画面。今の BFS のまま後ろに足す）。
   - 点検の段で読めなかった画面（失敗・範囲の外）は、点検の記録の理由で判断する: 範囲の外（`isOutsideAuditScopeNavigation` など）は入れない。失敗は入れる（操作さがしで読めればよい）。
   - 読まないパス・危険な語・読む範囲・許可 Origin の除き（`isExcludedCrawlCandidate`）と、すでに待ち行列にある URL の重ねない決まりは今のまま。
   - 点検の段の成果物の読み方は、共通の部品（`src/core/audit-stage-links.ts`）に足す（画面のサーバの自動の下書きと同じ所）。新しい読み方を書き写さない。
2. 進み具合の全部の数（`pagesDiscovered`）は、始めから「入れた画面の数」になる。新しい画面が見つかれば今どおり増える（「延びます」）。
3. ページの上限（`crawl.maxPages`）・時間の上限・読み込みの間隔・Guard は今のまま。点検の段の画面はページの上限に数える（今の BFS で読んだ画面と同じ）。
4. 続き（`saved !== null`）は今のまま（前の実行の待ち行列から作り直す）。
5. 連鎖でない操作さがし（点検の段がない）は今のまま（入口から BFS）。

## 3. 負荷
- 読み込みの回数は今と同じか少ない（どの画面も操作さがしで 1 回読む。入口からたどり直す途中の画面も、点検の段の画面と同じ集まりに入る）。速さの上限は `crawl.minNavigationIntervalMs` のまま。

## 4. 版
- `discovery.json`・checkpoint の形は変えない（待ち行列に入れる元が増えるだけ）。
