# BeakSight 操作さがしの「同じ形の兄弟のボタン」をまとめる直し（CALDAY）と、窓の確かめで止めた接続の記録（FRETWS）

- 日付: 2026-11-25
- 状態: ユーザーの指摘に基づく（2026-11-25「予約投稿の日時を指定するダイアログでカレンダー上の一日ずつをボタン遷移している。これは操作のさがしとしては価値のない挙動だ」）。直し方は、決まった方針（数で網羅を決めず、見えた違いを残らず確かめたかで決める）に沿って設計者が選んだ。
- 根拠: 調査担当の実験（指示書 `CALDAY-investigation-brief.md`・`FRETWS-investigation-brief.md`。127.0.0.1 の自前のサーバ・本物の `executeDiscoveryRun`・本物の factory と Guard）
- 拡張する文書: COV-2b（`pressDigestOf`）、DEF-208-2（同じ語の組の `noRequestWords`）、FRET（`2026-11-24-beaksight-dialog-focus-return-design.md`）

## 1. 原因（実験で確かめた事実）

### 1.1 CALDAY
- 日付の選びの表の日のボタン 35 個は、識別の digest も押す組の digest（`pressDigestOf`）も同じで、文書の順の番号（`pressOrdinal`）だけが違う。押した組の記録の鍵（`processedKeyOf`・`pressKeyOf`）に番号が入るので、35 組として 35 回押す。
- 日を押しても文言と class が変わるだけで、状態の構造の鍵（`stateStructureKeyOf`）は変わらず、送信も起きない（`NO_REQUEST`）。それでも同じ段の待ち行列を最後まで押し切る。
- 実験: 3 つの形で日を 35 回押した（1 画面 57〜88 秒、テストの待ちの値で）。本番の待ちでは 1 画面 2 分前後の見込み。
- 今あるまとめ（LU-4・DEF-208-2・PSKIP・ISKIP・共通の枠の鍵）は、語のない同じ形の兄弟に当たらない。

### 1.2 FRETWS
- 実 Run の 1 画面目の mobile で、FRET が窓を開くボタンを 3 つ押した間に、サイトが新しい WebSocket を開き、押す期間の止め（`DIALOG_PRESS`）が止めた。決めたとおりの止め（ユーザー承認済み）で、viewport をまたいで残ったのではない（実験 6 回中 0 回）。
- ただ、止めた記録の理由が普通の止めと同じ `PASSIVE_WEBSOCKET` で、安全の指摘 `SAFETY_WEBSOCKET_BLOCKED` として出た。サイトの問題に見え、見分けもつかない。また、FRET の項目の `guardBlockedCount`（`scrollKeyPressBlocks`）に数えられていない。

## 2. 決めたこと

### 2.1 CALDAY: 代表を押した結果で、同じ組の残りを押さない（調査の案 2）
- 同じ状態の中で、押す組の digest が同じで、番号だけが違う押す対象を「兄弟の組」とする（新しい鍵の作りは、今の `pressDigestOf` を使う。写しを作らない）。
- 組の最初（文書の順）を押した結果が「送信なし（`NO_REQUEST`）で、状態の構造の鍵が変わらない」なら、同じ組の残りを押さない。
- 結果に違いが出たら（送信が起きた・構造の鍵が変わった・画面が移った・窓が開いた）、今どおり残りも押す。DEF-208-2 の同じ語の組の考えを、組の鍵に広げる。
- 代表の押下で状態が移ったとき、元の状態に残った兄弟は「代表で済んだ」として扱い、兄弟の数だけ読み込み直し（`reprobeRemaining`）をしない（違いが出た組を除く）。
- 数の上限は置かない。押さなかった兄弟の数は記録に残す（数と閉じた語だけ）。
- 押せない（無効の）確定のボタンが、代表の 1 回で押せるようになり、今の `disabledAt` の確かめ直しで押されること。

### 2.2 FRETWS: 押す期間に止めた接続を、押下の記録として分ける（調査の案 a）
- FRET の押す期間・止めの続きで止めた WebSocket に、専用の理由を付ける（HTTP の `SCROLL_KEY_PRESS_RESTRICTED` と同じ扱い。新しい値が要るなら閉じた一覧に足す）。
- その数を FRET の項目の `guardBlockedCount`（`scrollKeyPressBlocks`）に数える。
- 普通の止めの安全の指摘（`SAFETY_WEBSOCKET_BLOCKED`）には出さない。止める・通すの決まりは変えない。

## 3. 受け入れ
- CALDAY: 調査の 3 つの形（PLAIN・JS・SLOTS）を fixture にして、日を押す回数が 1〜2 回（SLOTS は違いが出た分だけ）。読み込み直し 0。JS・SLOTS で確定が押され `API_CREATE` が記録される。
- 日ごとに振る舞いが違う画面（ある日を押すと送信が起きる）では、残りも押す。
- FRETWS: 押す期間に開いた WebSocket が、専用の理由で記録され、`guardBlockedCount` に数えられ、`SAFETY_WEBSOCKET_BLOCKED` が出ない。普通の読み込みで止めた WebSocket は今どおり安全の指摘になる。サーバに届く読み取りでない要求 0 は変わらない。
- tsc（root と `apps/local-ui`）0。関係する単体・architecture。ブラウザの結合は、変えた所を import するものだけを 1 本ずつ。

## 4. 速さと負荷
- 押す回数と読み込みの回数は減るだけ。見込み: 日付の選びの窓 1 つで約 35 回 → 1〜2 回（本番で 2 分前後 → 数秒）。次の実 Run の DTIME で確かめる。

- 2026-11-25 実装の結果に対応（fix round 1）:
  - 兄弟の組の鍵を狭める。今の `pressDigestOf` は閉じた語の一覧に当たらない文字を見ないため、前の月・次の月、「メニュー」と文字のないボタンのような違う働きのボタンが 1 組になっていた。組の鍵に、押す対象の文字（空なら支援技術の名前）の数字を `{n}` にした型の digest を足す。ページの中の読み取りで作り、記録の外へ出さない。文字の違いは見えた違いなので、代表で済ませない。
  - 代表で済んで押さなかった共通の枠のボタンも、押した枠のボタンとして知らせる（`sharedLayout.onPressed`）。後の画面で兄弟を 1 つずつ押し直さないため。
  - 実験の値（テストの待ちの値）: PLAIN 57.1 → 8.9 秒、JS 58.8 → 11.4 秒、SLOTS 87.6 → 18.5 秒。読み込み直し 0、サーバに届いた読み取りでない要求 0。
  - 既知の限界: 組は代表の 1 回の結果で決める。最初の 1 つが送信せず、後の 1 つだけが送信する画面では、後の 1 つを押さない。
