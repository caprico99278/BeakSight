- 日付: 2026-11-24

## 2. 決めたこと

### 2.1 前面の窓（共通部品・RVP-0）

- 「前面の窓」を判定する部品を 1 か所に置く（ブラウザの中の読み取り。例: `role="dialog"`・`role="alertdialog"`・`aria-modal="true"`・`<dialog open>` の祖先を持ち、画面の大きな部分を覆う要素）。フォーカスの確かめ・固定要素の覆い・重なり・通知の枠の見分けが、同じ部品を使う（写しを作らない）。
- 判定できない・読めないときは、前面の窓でないとする（今の振る舞いのまま。指摘を消す側に倒さない）。

### 2.2 RVP-1 フォーカス（F1・F2）

- 直の focus で「押せない」（`NOT_HITTABLE`）と読んだ要素が、**押下を受けた要素が前面の窓の中で、対象がその外**なら、`FOCUSED_CONTROL_HIDDEN` の指摘にしない（前面の窓が背後を覆うのは作りどおり）。数はバンドルに残す。
- 前面の窓が開いている状態で、通常の Tab の確かめが走ったときは、Tab で前面の窓の外（背後）へ移ったかを記録し、移ったときだけ指摘にする（文: 前面の窓を開いたまま、Tab で背後の要素へ移ります）。閉じた後の戻り先は今回の範囲の外。
- 通常の Tab の確かめがない（走らなかった・途中で止まった）項目の指摘の文は、「押せません」と言い切らない。事実（直にフォーカスを当てたとき、ほかの要素の下にありました）と、Tab では確かめていないことを書き、確信度を 1 段下げる（今の `focusCheckLowersConfidence` の決まりに足す）。幅の走査の幅で Tab の確かめを新しく走らせることはしない（点検の時間の 55% が幅の走査のため）。

### 2.3 RVP-2 固定要素の覆いと重なり（F3）

- 覆っている固定要素が前面の窓なら、`FIXED_ELEMENT_OCCLUSION` の指摘にしない（開いた窓が下を覆うのは作りどおり）。前面の窓の中の要素どうしの重なりは、今どおり判定する。
- 重なり・覆いの対象が画像の外（`TARGET_NOT_IN_IMAGE`）のときの文は、「隠しています」と言い切らず、計った数の事実だけを書く。

### 2.4 RVP-3 通知の枠（F4）

- 「隠しました」の一文は、隠した幅（主の読み込みか、幅の走査の何 px か）を文に書き、その幅の画像の証拠を参照に足す。
- 閉じるボタンのある前面の窓を「閉じるボタンのない通知の枠」と見ていないかを、前面の窓の部品で確かめる（実装者が fixture で再現。見ていたら、前面の窓は通知の枠の候補から外す）。

### 2.5 RVP-4 無効のボタン（F5）

- axe の名前の規則（`button-name` など）の対象が無効（`disabled`・`aria-disabled="true"`）のとき、文に「無効の状態で見つけました（有効の状態は確かめていません）」を足す。有効の状態は作らない（入力・保存・公開をしない）。重さは変えない。

### 2.6 RVP-5 ラベルの参照・同じ id（F6）

- `DUPLICATE_ELEMENT_ID` の証拠に、その id を参照する要素の数（`label[for]`・`aria-labelledby`・`aria-describedby`・`aria-controls` など・`a[href="#id"]`）を足す。参照する要素が 0 なら、文にその事実を書き、確信度を 1 段下げる。
- axe のラベルの規則の対象が `aria-labelledby` を持つとき、参照先の数と、見えるか（見える・見えない・ない の 3 つ）を証拠に足す。
- schema は省略可の項目で足す（版は上げない。要るなら止まって報告）。

## 3. 受け入れ

- fixture（127.0.0.1）で:
  - 前面の窓を開いた画面の背後のボタン → `FOCUSED_CONTROL_HIDDEN` と `FIXED_ELEMENT_OCCLUSION` にならない。前面の窓のない画面で覆われたボタン → 今どおり指摘。
  - Tab で前面の窓の背後へ抜ける画面と、抜けない画面を区別する。
  - Tab の確かめのない指摘の文が「押せません」と言い切らない。
  - 通知の枠を幅の走査でだけ隠した → 文にその幅、参照にその幅の画像。閉じるボタンのある前面の窓 → 閉じるボタンのない通知の枠にしない。
  - 無効のボタンの名前の指摘に、無効の文が付く。
  - 同じ id で参照する要素が 0 と 1 以上を区別する。`aria-labelledby` の参照先がない・見えない・見える を区別する。
- テストは受け入れ条件ごとに最小限。tsc（root と `apps/local-ui`）0。関係する単体・architecture・UI Gate。ブラウザの結合は、変えた所を import するものだけを 1 本ずつ。

## 4. 今回は直さないもの（限界の記録）

- F7: 記録の引数で直に開いた画面のデータの読み取りの 4xx の責任の区分（記録がない・権限・監査の遮断）は、今の証拠では分けられない。開いた経路を記録する仕組みは、別の設計にする。
- F8: axe の背景色と画像の色の食い違いは 1 件。同じ時点の画像の取り直しは、別の設計にする。
- F9: LCP は既に「1 回の測り」と文に書いている。測り直しはサイトへの読み込みを増やすので行わない。

## 5. 速さと負荷

- サイトへの読み込みの回数は変えない。幅の走査に新しい確かめを足さない。前面の窓の判定は、今の読み取りの中で行う。
