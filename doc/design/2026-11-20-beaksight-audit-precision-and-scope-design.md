## 1. 背景（設計者が実環境の点検の記録 RUN-20261120010147 で数えた事実。名前は伏せる）

- 点検の失敗 2 画面のうち 1 つは、読み込みの後に画面自身が URL へ状態の query（名前に `cancelled` を含むもの）を足し、監査の段の危険な語 `cancel` に部分一致（`hitsDangerousTermIn` の `includes`）で当たって、SD-2 の `BLOCKED_EXTERNAL_REDIRECT` になった。BeakSight は移動していない。巡回の URL の語（`crawlUrlHasDestructiveWord`。境界つき）は同じ URL に当たらない。Run は PARTIAL。
- `DUPLICATE_PAGE_TITLE` は 132 件・132 組（1 組 1 ページ、`groupingKeys` が空）。題の種類は 22。115 件は data を除いた path が同じ画面どうし（query・データの違い）。違う画面どうしは 17 件（3 つの題）。
- `A11Y_LABEL_CONTENT_NAME_MISMATCH` は 1046 件（ERROR 1522 の 69%）。axe の node の `nameContext`（AX の名前と見えるラベルのかたまり `labelSegments`）で数えると、はっきりした違反は少ない:
  - 見えるラベルの先頭のかたまりが名前にない: 2 種（1 種は全画面の共通の枠のリンク 225 件。もう 1 種は区切りの記号の違いだけ）。
  - どのかたまりも名前にない: 15 種・37 件（多くは日付の書き方の違い `8/18(火)` と `2026年8月18日（火）`。1 種は本当に違う語）。
  - 先頭のかたまりは名前にあり、後のかたまり（役割・件数・ボタンの語など）だけがない: 17 種・511 件。
  - 全部のかたまりが名前にある: 34 種・265 件（axe が日本語を語に分けられないための違反）。
- スマホの点検は、幅 390 のパソコンのブラウザ（UA はパソコン、touch なし）。最初の設計は幅だけを決めている。

## 2. 決めたこと

### 2.1 DEF-304: 画面自身が足した query の語で、範囲の外にしない

- SD-2 の読み込みの後の範囲の判定（`navigatePage` の `movedOutside`、`auditScopeLeftUrl`、page-auditor の読み込みの後の判定、`audit-scope-watch`）で、**画面自身が読み込みの後に変えた URL の query** は、危険な語の判定に使わない。path・Origin・読まないパス・読む範囲（`auditPathPrefixes`）の判定は今どおり。path が変わった移動（危険な語の path を含む）は今どおり範囲の外。
- 「画面自身が変えた query」は、読み込みを頼んだ URL と、読み込みの後の URL の path が同じで、query だけが違う場合とする。BeakSight が頼んだ URL の query は、今どおり巡回の候補の判定（読み込みの前）で見ている。
- Guard の要求の判定（`isAuditExcluded`・`hitsDangerousTermIn` の部分一致）は変えない。危険な語の query を持つ要求は、今どおり Guard の決まりで扱う。理由: 守りを弱めずに、要求を伴わない URL の書き換えで点検を落とさないため。
- 危険な語の比べ方（部分一致）と巡回の語（境界つき）の 2 つのずれは、`commonization-candidates.md` に記録し、今回は変えない（Guard の比べ方を変えるのは安全の再レビューが要るため）。

### 2.2 DEF-305: ページの題の重なりは、違う画面どうしだけを、題ごとに 1 組

- 重なりの相手から、data を除いた path（`dataFreePathOfUrl`、`src/discovery/fingerprint.ts`）が同じ画面を除く。相手が残らなければ指摘しない。
- 同じ題の指摘を 1 組にまとめる組の鍵を持たせる（題の digest。題の文字そのものは鍵に入れない）。
- 見込み（今回の記録）: 132 組 → 3 組。

### 2.3 読み上げの名前の精度: 先頭の見えるラベルが名前にないものだけを違反にする

- WCAG 2.5.3 の考え方（名前は見えるラベルを含み、先頭に置くのがよい。補足の文字は含まなくてよい）に合わせ、`A11Y_LABEL_CONTENT_NAME_MISMATCH` の指摘を、次のときだけ作る:
  - 見えるラベルの先頭のかたまり（区切りの記号だけのかたまりは除く）が、書き方をそろえた形（今の `looseLabelFormOf`。全角と半角、空白、区切りの記号、日付の書き方）で名前に含まれない。
  - かたまりを読めない（`nameContext` がない・読めない）ときは、今の `UNDETERMINED` と同じく指摘を残し、確信度を下げる。
- 全部が名前にある（`LABEL_IN_NAME`・`NORMALIZED_MATCH`）と、先頭は名前にあり後のかたまりだけがない（`SUPPLEMENT_ONLY_MISSING`）は、指摘にしない。axe の違反そのものは今どおり証拠（EV-A11Y）に残る（事実は消さない）。指摘にしなかった数は、今の除外の数の置き場（あれば）に足す。新しい置き場は作らない。
- 先頭のかたまりを決める部品は 1 か所（`src/audit/label-in-name.ts`）。区分の名前は、今の区分を使い回し、要るなら `MAIN_LABEL_MISSING` の意味を「先頭のかたまりが名前にない」に改める。
- 見込み（今回の記録）: 1046 件 → 約 230 件（全画面の共通の枠のリンク 225 件と、本当に違う語の数件）。組は 65 → 数組。

### 2.4 スマホの点検の限界（文書だけ）

- `doc/spec/output.md`（か点検の範囲を書いた今の spec の 1 か所）の限界に、「スマホの幅の点検は、パソコンのブラウザの幅を狭めて行う。スマホのブラウザだと名乗らず、指で触る操作も真似しない。スマホかどうかで見せ方を変えるサイトでは、スマホで見える画面と違うことがある」と書く。コードは変えない。

## 3. 受け入れ

- DEF-304: 127.0.0.1 の fixture で、読み込みの後に `history.replaceState` で `?x_cancelled=1` を足す画面が点検される（`OK`）。path に危険な語を含む画面へ script で移る画面は、今どおり `BLOCKED_EXTERNAL_REDIRECT`。Guard と SD-2 の今のテストが全部通る。
- DEF-305: `/x/1` と `/x/2?a=1`（同じ型）の同じ題は指摘なし。`/a` と `/b` の同じ題は 1 組（2 ページ）。
- 精度: 単体で、先頭のかたまりがない → 指摘、全部ある・後だけない・書き方の違いだけ → 指摘なし、かたまりを読めない → 確信度の低い指摘。
- tsc（root と `apps/local-ui`）0。関係する単体・architecture・UI Gate。

## 4. 速さと負荷

- 読み込みの回数・間隔は変えない。2.1 は点検する画面が 1 つ増えるだけ。
