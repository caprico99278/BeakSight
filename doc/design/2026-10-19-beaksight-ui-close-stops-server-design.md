# 設計書 — 管理画面のブラウザを閉じたら、画面のサーバも止める

状態: ユーザーの指示（2026-10-19「BeakSightのブラウザを閉じたら、サーバも停止するようにして」）
作成: 2026-10-19（設計者）

## 1. 経緯

実テスト環境の確かめの途中で、利用者が管理画面のブラウザを閉じた後も、画面のサーバ（`apps/local-ui/launcher/serve.ts`）が動き続けた。古いコードのまま残り、起動し直しの妨げになった。今は、止めるのにターミナルの Ctrl+C（SIGINT。`shutdown.ts` の 2 段の扱い）が要る。

## 2. 設計

- **生きている知らせ:** 管理画面のページは、開いている間、名前つきの間隔（例: 5 秒）で、画面のサーバへ生きている知らせを送る。今の要求の守り（token の cookie、Host、同じ Origin）を通る、読み取りでない口ではない形にする（状態を変えない GET か、CSRF の守りを通る POST。今の守りの作りに合わせる）。
- **閉じたときの知らせ:** ページを閉じるとき（`pagehide`）に、閉じたことを知らせる（`navigator.sendBeacon`。今の守りを通る形）。読み込み直しでも送られるので、知らせを受けても、すぐには止めない。
- **止める決まり:** 画面のサーバは、次の 3 つがそろったら、今の終わり方（`shutdown.ts`。ジョブの後片付け、待ち受けを閉じる、管理データを閉じる）で止まる。
  - 起動の後に、ページが一度は知らせを送った（起動しただけで、まだ画面を開いていないときは止めない）。
  - どのページからも、名前つきの猶予（例: 閉じたときの知らせの後は 15 秒、知らせが途絶えた後は 30 秒）の間、生きている知らせがない（複数のタブなら、どれか 1 つが開いていれば止めない。読み込み直しは猶予の中で戻る）。
  - 動いているジョブがない。
- **動いているジョブがあるとき:** ジョブを止めない。ジョブが終わるのを待ち、終わった時点で上の決まりをもう一度確かめる（書き込みの途中で止めて結果を分からなくしないため）。待っている間に画面を開き直せば、止めない。
- **止めるときの表示:** ターミナルに、「管理画面が閉じられたので止めました」と、もう一度使うときの手順（`npm run ui`）を出す。文言はカタログに置く。
- **設定:** 猶予と間隔は名前つきの定数。Ctrl+C の止め方は今のまま。

## 3. 安全と影響

- 動いているジョブ（とくに書き込み）は止めない。
- 知らせの口は今の要求の守りを通るので、別のサイトから画面のサーバを止めることはできない。
- ログインの段のブラウザ（BeakSight が開く Chromium）は、管理画面のブラウザとは別。閉じても、この決まりに当たらない。

## 4. 受け入れ条件

1. 画面を閉じると、猶予の後に画面のサーバが止まり、port が空く（テストでは猶予を注入して短くする）。
2. 読み込み直しと、2 つ目のタブが開いているときは止まらない。
3. 起動しただけで画面を開いていないときは止まらない。
4. ジョブが動いている間は止まらず、ジョブが終わった後に止まる。
5. 別の Origin・token のない要求では、知らせを受けない。
