# 設計書 — 承認したサービスへの要求の上限を、止めずに待って続ける形にする（DEF-141）

状態: ユーザーの判断（2026-10-20「上限の値を上げながら、待って続ける形にする」）。実装中。
作成: 2026-10-20（設計者）

## 1. 経緯

実テスト環境の発見（ページの上限 20、読む範囲 `/admin`）が、4 ページで止まった（`SERVICE_REQUEST_LIMIT_REACHED`）。管理画面は 1 回の読み込みで、承認したサービスの Origin へ 70〜120 件ほどの要求を自分で出す。今の上限（Task 35 の T35R-fix のユーザーの判断。1 分あたり 120 件、1 回の Run あたり 600 件。どちらも既定が最大）に当たると、Guard はその後の要求を断り（ページの途中で止める）、Run は次のページを始めずに止まる。

ユーザーの方針（2026-10-19）は「ページの自然な送信は止めない。不自然な遮断はサイトの検知を招く。サイトに過負荷を与えない」。ページの途中で要求を断るのは不自然な遮断にあたる。1 分あたりの上限の目的は負荷の守りであり、次のページを読む前に待てば満たせる。

## 2. 設計

### 2.1 値

- 1 分あたり（`perMinute`）: 既定と最大を 600 件に上げる。
- 1 回の Run あたり（`perRun`）: 既定と最大を 10,000 件に上げる。
- 最小は今のまま 1。値の範囲は認証の設定の契約（`auth-setup-contracts.ts`）が確かめる。保存した設定にこの項目があれば、その値を使う（今の決まり）。

### 2.2 1 分あたりの上限は「待つ」

- ページの読み込みの途中では、1 分あたりの上限で要求を断らない。
- 次のページ（または次のビューポート・幅の読み込み）を始める前に、直近の 1 分に数えた要求が `perMinute` 以上なら、窓の中の数が `perMinute` を下回るまで待つ。待つ時間は、窓の中の最も古い要求が 1 分を過ぎるまで（最大で 60 秒）。今の読み込みの間隔（pacer）の待ちと重ねる（長い方を待つ）。
- 待ったことは、進みの知らせ（ジョブの画面の進み）と、`run.json`・発見・READ の結果の記録に、回数と合計の時間として残す（今の負荷の記録 `load` の近く）。
- 1 回の読み込みで、ページが 1 分あたりの上限を超える要求を出すことはありうる（それはページの自然な送信なので止めない）。負荷の守りは、読み込みの間を空けることで行う。

### 2.3 1 回の Run あたりの上限は今どおり止める

- 数えた要求が `perRun` に届いたら、今どおり Guard が以後の要求を断り（`SERVICE_REQUEST_LIMIT_REACHED`）、Run は次のページを始めずに止まる（`serviceRequestLimitReached`）。値を上げたので、ふつうはページ数と時間の上限が先に効く。

### 2.4 当てる段

監査・発見・READ の確かめ（スクリプトで送るログインの監査の段の口がある Run）。数え方の owner は `src/crawl/service-request-budget.ts` のまま。待つ判断は、読み込みの間隔の部品（pacer）と同じ場所で、Run Coordinator・発見・READ の確かめが共用する 1 つの部品にする。

## 3. 受け入れ条件

1. fixture: 1 回の読み込みでサービスへ多くの要求を出すページを並べた Run で、今の作りでは途中で止まること（RED）、直した後はページの途中で要求を断らず、1 分あたりの上限で次の読み込みの前に待ち、最後まで進むこと（GREEN）。時計は注入して、待ちを短くする。
2. `perRun` に届いたら今どおり止まる。
3. 待った回数と時間が `run.json`・発見の結果・ジョブの画面に出る。
4. 今の負荷の守り（読み込みの間隔、`site-load` の決まり）のテストが通る。安全の回帰（`safety-gates`、`guard-script-login`）を両方の Chromium で 1 回ずつ。
