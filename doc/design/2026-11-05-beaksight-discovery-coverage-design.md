# BeakSight 操作さがしの網羅の直し（DEF-208）設計書

- 日付: 2026-11-05
- 状態: ユーザー承認済み（2026-11-05。範囲は「B・C・D・G・H の後に A・F」。読み取りの扱いは「削除以外は全て通すという基本方針に従って。方針に沿わない動作は全てバグ」）
- 関係する文書: `2026-11-02-beaksight-list-row-update-design.md`（5.1 の D7、5.8 の DEF-190）、`2026-11-04-beaksight-login-session-design.md`（DEF-193・194 の PASS_EXCEPT_DELETE をログインの段に当てた決まり）、`2026-10-27-beaksight-one-pass-flow-design.md`（OP-I の既定 `DEFAULT_SITE_AUDIT_SEND_POLICY`）

## 1. 目的

実テスト環境の 2026-11-05 の操作さがしで、読んだ 31 ページの登録・更新の候補のほとんどが、試せないか「登録だけ」になった。調べ（DEF-208-research）で、原因は次の 5 つの重なりと分かった。

1. 1 画面 3 回の押す数のうち 55% を、どの画面にもある共通の枠（左の帯）のボタンが使った。10 ページでは本文のボタンを 1 つも押していない。
2. 登録・更新の語の段の中で、「追加」が文書の順で先に押された。そのため「保存」「登録」13 個が押されずに残った。
3. 押した後の凍結の間、Guard が読み取り（GET）まで止めた。そのため、保存の前に GET を待つ画面で、保存が送信まで進まない（`NO_REQUEST`）。押せない（disabled の）保存も、5 秒待って押す 1 回を使う。
4. 移動の文書の要求を Guard が止めると URL が変わらない。そのため、DEF-190 の「移った先の編集の画面を読む」で拾えない。
5. 欄と結び付く鍵が 0 の呼び出し（`/functions/` の下の手続きの呼び出し）が、「登録」の下書きになった。

この設計で、押す数・読むページの数を増やさずに、本文の登録・保存・更新のボタンが押され、更新が見つかるようにする。

## 2. 守る決まり（ユーザーの判断）

- **削除のほかは止めない（PASS_EXCEPT_DELETE）を、操作さがしの押した後にも当てる。** 方針に沿わない止め方は不具合として扱う。
- **押して出させた書き込みの送信そのものは、これまでどおり届けない。** 形を記録するだけにする（観察が目的。届けると押すたびに本当に登録される）。これはサイトの自動の通信ではない。
- 網羅と正確さを下げる案（読む数を減らすだけ、押さないボタンを増やすだけ）は採らない。サイトへの負荷を上げる案（上限を上げるだけ）は採らない。

## 3. 採用する設計

### 3.1 E: 押した後の凍結の間も、削除のほかの読み取りとサイトの自動の通信を通す

- 押した後の凍結（`src/safety/submission-observation.ts`）で止めるのは、次の 2 つだけにする。
  - 押して出させた、最初の読み取りでない送信（観察の対象）。
  - その後の、読み取りでない送信。押下の続きとみなす。
- 次の要求は、監査の段と同じ判定（`DEFAULT_SITE_AUDIT_SEND_POLICY`、`isAuditSendDangerous`、読まないパス、資格情報の守り）で通す。
  - 読み取り（GET・HEAD）。
  - 凍結の前からの、サイトの自動の通信。
- 通すのは許可 Origin と承認したサービスの Origin だけで、監査の段と同じ範囲にする。
- 文書の移動（main frame の GET）は、今の probe の決まり（移った先を読む・読まない）のままにする。
- **方針に沿わない止め方の棚卸し:** 操作さがし（`src/worker/discovery-run.ts`、`src/interaction/`、`src/safety/` の操作さがしの口）で、削除・危険な語・読まないパス・資格情報の守り・観察の対象の送信のほかを止めている所を、すべて挙げる。それぞれを、この決まりに合わせて直す。直せない所は、理由をつけて報告する。
- 記録: 通した読み取りの数を、操作さがしの記録に数として残す。値と URL は残さない。
- **DEF-208-1 の Blocker の後の設計者の判断（2026-11-05）:**
  - (a) **目印の値を運ぶ GET も通す。** BeakSight が入れた値が載る GET（例: 重複の確かめ）も、読み取りとして通す（ユーザーの基本方針。GET で書き込むサイトは想定の外。限界として書く）。通した中で目印を運んだものの数を、別に数える。
  - (b) **出口の中継。** 凍結の中にも、Guard が通した読み取りだけを中継が通す状態を足す。印は、ログインの段の `EgressSendAdmissions` と同じ考え方の、読み取りの写し（`egressReadAdmissions`）で付ける。Guard が通していない要求と CONNECT は、今のとおり拒む。凍結の時にソケットを切る動きは今のまま。
  - (c) **時間の範囲。** 読み取りは、凍結の間ずっと通す（観察の窓の中と外のどちらも）。読み取りでない送信は、凍結の間ずっと止める（押下の続きと見分けられないため。「観察の対象とその続き」に入れる）。
  - (d) **その他。** sub frame の文書の GET は、読み取りとして同じ判定で通す。ポップアップと WebSocket は、凍結の間は今のまま止める（押下の続きの書き込みと見分けられないため）。この 2 つは限界として書く。
  - **判定:** 凍結の読み取りの判定は `src/safety/request-policy.ts` に 1 か所で置く。中身は、監査の段の判定、`isAuditSendDangerous`、読まないパス（ページの文書でない読み取りにも当てる）、資格情報の守り。
  - **(e) https の宛先（DEF-208-1 の報告の後の判断）:** 凍結の後も、Guard が凍結の読み取りとして通した宛先（host とポート）への CONNECT だけは受け入れる。仕組みは、`OPEN` の間の CONNECT の受け入れ（DEF-125 の `tunnelAdmission`。知らせを待つ時間も同じ）を使う。凍結の時にソケットを切る動きは今のまま。知らせのない宛先への CONNECT と Upgrade は、今のとおり拒む。トンネルの中身は中継から見えないので、読み取りでない送信を止めるのは Guard（CDP と route の層）だけになる。これを安全のレビューで、https の仮のサイトを使って確かめる。
  - **(f) 押下のない凍結（SREV-1105-2 の Minor-1 の後の判断）:** 凍結の読み取りの判定は、観察の口のある PRIMARY の Passive の Context のすべて（入口の確かめ・READ の確かめ・書き込みの段の READ の発見の凍結の後を含む）に効く。基本方針（削除のほかは止めない）に合うので、この広がりは意図したものとする。通した数は、操作さがしの記録にだけ残る。
  - **(g) ブラウザ自身の送信:** Guard を通らない Chromium 自身の送信（報告の機能など）は、起動の引数で止める（DEF-211）。トンネルを開く前提の「中は Guard だけで足りる」は、これが止まっていることに依る。
  - **(h) 既知の限界（DEF-212、ユーザーの判断「止めない」）:** HTTP/2 の Early Hints（103 の `Link: rel=preload`）でブラウザが取りに行く同じ Origin の読み取りは、Guard を通らず記録もない。止められるのは HTTP/1.1 に限る起動だけで、性能の計測が変わるので採らない。サイト自身が指定した読み取りで、ふつうの利用者のブラウザも同じ動きをする。`doc/spec/safety.md` の既知の残る経路にも書く。
  - **網の失敗:** 凍結の間に通した読み取りの網の失敗は、凍結の前と同じく違反にしない（通した要求に印を付けて見分ける）。

### 3.2 B: 確定の語を、行を足す・開く語より先に押す

- 押す順の段（`src/discovery/submission-probe-contracts.ts` の `pressRankOf`）で、登録・更新の語の段を 2 つに分ける。
  - 先: 確定の語（保存・登録・更新・送信などの、今の分類の語のうち確定のもの）。
  - 後: 行を足す・開く語（追加・新規・作成・編集など）。
- 語の一覧は、今の分類の語（`src/discovery/classification-words.ts`）を共用する。新しく足すのは、登録の語の部分集合「行を足す語」（add・new・create・追加・新規・作成）の 1 つだけ（DEF-208-2 の Blocker の後の判断。開く語が更新の語の部分集合であるのと同じ作り）。確定の語は、登録・更新の語から、行を足す語と開く語を除いたもの。

### 3.3 C: 同じ語で何も送らなかったボタンの 2 つ目からは、押す数を使わない

- 同じ画面で、同じ語の組（`submitterWords`）のボタンを押して `NO_REQUEST` だったときは、同じ語の組の 2 つ目からは押さない。
- 押さなかったボタンには、新しい理由 `SAME_WORDS_NO_REQUEST` を付ける。押す数は使わない。
- 語のないボタンには当てない（語で見分けられないため）。

### 3.4 D: 押せない送信ボタンは押す数を使わない

- 押す前に、ボタンが押せない（disabled、`aria-disabled="true"`）ことを読む。押せないときは押さずに、新しい理由 `DISABLED_SUBMITTER` を付ける。押す数は使わず、5 秒の待ちもしない。
- 入れる値を入れた後に押せるようになるボタン（欄を入れてから押す今の流れ）は、入れた後に読む。

### 3.5 G: 止めた文書の移動の行き先も「移った先」として拾う

- 開き手を押して出た文書の移動を Guard が止めた場合は、違反の記録にある行き先（同じ Origin、GET、読まないパスでない）を使う。その行き先を、DEF-190 の「移った先の編集の画面」の候補（`openedEditPageOf`）に渡す。
- 読む数の上限（`MAX_OPENED_EDIT_PAGE_READS=3`）と、同じ型は 1 回の決まりは変えない。

### 3.6 H: 欄と結び付かない呼び出しを「登録」と見なさない

- `/functions/` の下のパスを、手続きの呼び出し（`PROCEDURE_CALL_PATH`）として扱う。今の `/rpc/` と同じ判定の 1 か所（`src/core/api-request-shape.ts`）に足す。
- 欄に結び付く鍵が 0 の登録の型は、自動の下書きにしない。理由は既存の理由の鍵から選び、なければ新しい鍵を足す。

### 3.7 A: 共通の枠のボタンは、操作さがし全体で 1 回だけ押す

- 2 ページ以上に、同じ枠の位置と同じ識別で出るボタンは、共通の枠のボタンとする。識別は、語の組・種類・祖先の目印の形で決め、ページの path と値は含めない。
- 共通の枠のボタンは、最初に出たページでだけ押す。2 ページ目からは押さず、新しい理由 `SHARED_LAYOUT_PRESSED` を付ける。押す数は使わない。
- 識別は、成果物に digest だけを残す。schema は任意の項目で広げる。

### 3.8 F: 同じ型の画面は、操作さがしでは 1 つだけ読む（DEF-201 の案 1）

- 番号の区切りを `{id}` にした同じ型の path の画面は、操作さがしでは最初の 1 つだけ読んで押す。
- 型の決め方は、`MAX_OPENED_EDIT_PAGE_READS` の「同じ型は 1 回」と同じ部品を使う。
- 見るだけの点検（監査）の読み方は変えない。

## 4. 変えないもの

- 押す数の上限（1 画面 3 回）、読むページの上限、読み込みの間隔。
- 観察の対象の送信を届けない守り、削除・危険な語・読まないパス・資格情報の守り。
- 書き込みの段の判定と承認。

## 5. サイトへの負荷

- 押す数と読むページの数は増えない。
- 3.1 で通す読み取りは、押した後にサイトが出す GET だけ。押下は 1 画面 3 回まで。
- 3.4 の欄に入れる操作（押す前）は、押す数と別に、入れた後に押せなかった回を 1 画面 3 回（`MAX_SUBMISSION_PROBE_DISABLED_FILLS_PER_PAGE`）までにする。入れる前から押せないボタンは、欄に入れない（SREV-1105-3 の Important-1）。1 画面で欄に入れる回数は、押す数 3 と合わせて最大 6 回。
- 3.3・3.4・3.7・3.8 は押す数・読む数を減らす方向に働き、空いた分で本文のボタンと別の画面に回る。

## 6. テスト

- 仮のサイト（127.0.0.1）で、調べの場面を再現して直したことを確かめる。
  - 場面 A: 枠に文字のあるボタンが 40、本文に「追加」3 つと「保存」がある。
  - 場面 B: 保存の前に GET を待つ。
  - 場面 C: rich text の本文が空の間は、保存が disabled。
- 安全: 観察の対象の送信と、その後の読み取りでない送信は、サーバに届かない。サーバの記録で数え、2 つの Chromium で確かめる。
- 既存: 操作さがし・D7・DEF-190・DEF-198・DEF-203 のテストは、今のとおり通る。
- 1 ファイルずつ `--maxWorkers 1` で流す。verify:all は流さない。
