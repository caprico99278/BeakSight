# 2〜3 サイトの点検を同時に流す（追補設計書、2026-11-17）

## 1. 目的
- ユーザーの依頼（2026-11-17）: 「仮に 2〜3 サイト並列で監査することは現実的に可能だろうか？」→ 調べ（PAR の 1 段目）の案に「よい」。
- 今は「動いているジョブは管理データ全体で同時に 1 つ」。これを「サイトごとに同時に 1 つ」に変え、別々のサイトの点検を同時に流せるようにする。
- 端末の測り（実環境の Run の最中）: 1 つの点検で、作業用の node 約 405MB、Chromium 約 980MB、CPU は多くの時間で数%。

## 2. 決まり
- **プロファイルごとに同時に 1 つ。** 管理データの一意の部分索引を、プロファイルごとにする（管理データの版を 23 に上げる）。`createStartingJob` もそのプロファイルの終わっていないジョブで確かめる。理由の値 `JOB_ALREADY_ACTIVE` の意味は「このサイトの作業が動いている」に改める。連鎖の段の移り（前の段の行を締めてから次の段の行を作る）は、同じプロファイルの確かめで通る。
- **同じサイトは同時に始めない。** 許可 Origin のどれかが重なるジョブ（DEF-180 と同じ「サイト」の決め方）が動いていれば始めない（理由 `SITE_ALREADY_ACTIVE`）。許可 Origin はターゲット設定にあるので、管理のメモリに「動いている連鎖 → Origin」の表を置き、行を作るトランザクションの guard の中で照らし、同じ tick で表に足す（await を挟まない）。管理が知らない終わっていない行（前のサーバのワーカーがまだ動いている）があれば、今どおり拒む。読み込みの間隔の守りはワーカー（Run）ごとなので、この決まりがサイトへの負荷の守りの前提になる。
- **端末の負荷。** 同時に流す数の上限は置かない。動いているジョブが 1 つ以上あるときだけ、新しいジョブを始める前に、端末の空きメモリが「全体の 30%（使用率 70% の線）＋ 1 本分」以上かを確かめ、足りなければ始めない（理由 `MACHINE_MEMORY_LOW`）。1 本目と、連鎖の次の段・自動ログインのし直しは確かめない。1 本分は名前つきの定数で、今の測り（約 1.4GB）からの仮の値。最初に実環境で同時に流すときに、1 本の最大を測って直す。
- **出力先の印。** 出力先ごとの監査中の印（`run-exclusion.ts`）を「出力先 + 対象の ID」の単位にする。出力先は共有したままでよい（再開の Run 選びは対象の ID で絞り、後始末は Run のディレクトリの中だけ）。
- 変えないもの: 画面のサーバは 1 つ（`instance-lock.ts`）。8 つの守り・削除の操作をしない守り・読み込みの間隔・自動ログインの間隔と回数・資格情報・凍結は、ワーカーごと・プロファイルごとのまま。ワーカーのプロトコルと成果物の schema の版は変えない。

## 3. 画面
- サイトの一覧・作業の履歴・作業の画面・止めるボタン・「続きから」は今のまま（どれもジョブごと・サイトごと）。
- 開始の画面の押す前の確かめに 2 つ足し、1 文で出す: 「このサイトは、いま別の設定で点検しています。終わってから始めてください。」「パソコンの空きが足りません。動いている点検が終わってから始めてください。」
- 文言の「作業は同時に 1 つだけ」「同じ出力先で…」を直す。

## 4.1 REV-PAR の後の判断（2026-11-17）
- 同時に始める判定のサイトの鍵は、許可 Origin を正規の形にそろえ、ホスト名の先頭の `www.` の有無を同じとみなす（同じサーバへの負荷を 2 倍にしないため。ほかの所の意味は変えない）。
- 出力先の印を離しても、出力先そのものは消さない（共有の出力先で、別の対象の印が取れてしまう競合を避けるため）。Run を始めずに終わると、中身が空の出力先が残る（前の DEF-081 の「空の出力先も残さない」はやめた。成果物と Run のディレクトリは書かない）。
- 下調べの後に続けて始める点検は、同じ流れの続きなので空きメモリを確かめない。同じサイトで始めなかったときは、作業の画面に理由を出す。
- `JOB_ALREADY_ACTIVE` の文は中立にする（このサイトか、前に動かした作業が、まだ終わっていない）。

## 5. 限界
- 許可 Origin の違う 2 サイトが同じ ID の発行元（IdP）を共有するときは、同時にログインが起きうる（自動ログインの間隔と回数はプロファイルごと）。
- 同時に流すと CPU の取り合いで、表示の速さの測りの値が悪く出る余地がある（今の CPU は数%なので小さいと見る。未測定）。
