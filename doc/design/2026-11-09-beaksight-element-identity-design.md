# BeakSight 欄を入れると前に行が足される画面で、欄を見失わない（DEF-237）設計書

- 日付: 2026-11-09
- 状態: ユーザーの指示「DEF-237も修正対象として」（2026-11-09）。方式は設計者の判断（調査の推奨）
- 調査: INV-237（2026-11-09。仮のサイト、2 つの Chromium、操作さがし・API の書き込み・form の書き込みで比べ、回帰 19 場面を流した）

## 1. 原因（調査で確かめた事実）

1. 欄と押すボタンは、要素の位置の道（`src/browser/element-path-engine.ts:56-77`・`:111`）でたどる。欄を入れた時点で同じ親の前の位置に行が足されると、道が別の要素を指す。合図の受け手（backendNodeId で付けた印）がないので、5 秒待って失敗する（`PRESS_FAILED`。押さない側。届いた数 0）。
2. 書き込みの段でも同じずれが起きる。
   - API の書き込み: 押す直前の道の比べ（`api-write-submitter.ts:917`）で止まる（`PRECHECK_FAILED`）。
   - form の書き込み: 形の比べ（`write-form-submitter.ts:1163`）に道が入っていて `FORM_CHANGED` で止まる。

## 2. 採用する設計（INV-237 の案 D′）

「同じ要素かは backendNodeId で決め、位置の道は探すための手がかりにとどめる」を、1 か所の決まりにする。

1. **engine（共通の部品 1 か所）。** 道の要素が合図の受け手でないとき、文書の全部の要素に合図を送り、受け手の要素（確かめの時と同じ backendNodeId）を返す。受け手がなければ今のとおり失敗（押さない）。
2. **API の書き込み。** 押す直前の確かめから、道が同じかの比べを外す。backendNodeId の比べは残す。
3. **form の書き込み。**
   - 形の比べ（`signatureOf`）は道を除いて比べる。
   - 要素の確かめは backendNodeId だけにする。
   - 道は、今読んだ値に更新する（`:1221-1229`、`:1489-1490`、`:1503-1504`）。
   - 名前のない欄が足されて形が変わったときは、今のとおり止める。
4. 一覧の行の form を道で決める所（`write-form-submitter.ts:1011-1012`）と、一覧の行の開き手（`api-write-submitter.ts:1087-1127`）は、同じ決まりに合わせられるかを実装で確かめる。合わせられなければ、今のまま（止める側）として報告する。

## 3. 採らない案

- A（先に要素を掴む）: 外れた要素の理由が変わり、API の書き込みの入れ直しが働かなくなる（既存のテストが落ちる）。
- B（名前で探し直す）: 写しの行を同じ欄と取り違える。
- C（目印の属性を付ける）: サイトのスクリプトから見え、写しの行にも写る。型の記録に影響が出た（漏れ）。

## 4. 変えないもの

- 見失ったときは押さない（安全の側）。
- 押す前の確かめ（ボタンが押せるか、欄の値が入れたとおりか、承認の照合）。
- 合図の受け手の仕組み（ページから読めない）。

## 5. サイトへの負荷

変わらない。サイトへの要求は増えない。道を外したときだけ、ページの中の全部の要素を走査する（画面の中の処理）。

## 6. 限界

1. shadow root の中の要素は、今のとおり対象外。
2. 大きな画面で全部の要素を走査する時間は、約 50,000 要素で約 100 ms（SREV-237）。
3. ページの JS が、送信ボタンの click の受け手の中で既定の動きを止め、承認と同じ本文の別の form の `submit()`（submit の事象を出さない）を自分で呼ぶ形は、届く（SREV-237 の C-2。修正の前からある）。ページが承認と同じ要求を自分で 1 回送るのと区別できない。本文・宛先・送り方が少しでも違えば Guard が止め、通すのは承認した 1 回だけ。
4. 押す時点の確かめ（SREV-237 の Critical-1 の直し）は、form owner・つながり・的を比べる。書き込みの段は文言・属性も比べる。操作さがしは届けないので、文言・属性は比べない（押す瞬間に文言が変わる画面を見落とさないため）。

## 7. テスト

- 仮のサイト（INV-237 の autoTrail：欄を入れると同じ親の前に行が足される。一般の文言）で、操作さがしが送信の形（API_CREATE）を取れる。
- API の書き込みと form の書き込みで、前に要素が足される画面に 1 回だけ届く。
- 2 つの Chromium で確かめる。
- INV-237 の回帰の 19 場面が通る。
  - 部品の橋渡し `isolated-element-bridge`
  - API の書き込み `api-write-submitter`
  - form の書き込み `write-form-same-element`、`write-form-submitter`
  - 操作さがし `discovery-submission-probe`、`press-order`、`def-221`、`discovery-notification`、`form-list-row-update-run`
