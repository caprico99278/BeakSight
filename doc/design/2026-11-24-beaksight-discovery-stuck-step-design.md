# BeakSight 操作さがしの「静まらない」3 分の打ち切りの直し（QUIET）

- 日付: 2026-11-24
- 状態: ユーザーの判断を得た（2026-11-24「よい。画面が安定するまでに何分もかかるはずがない。そこもおかしいと考える」）
- 根拠: 調査担当の実験（127.0.0.1 の自前のサーバ・本物の `executeDiscoveryRun`・凍結。指示書 `QUIET-investigation-brief.md`）
- 拡張する文書: L0（`src/core/progress-watch.ts`）、DEF-289（押下の対象が替わったときの押し直し）、DTIME・DBG-1

## 1. 原因（実験で確かめた事実）

- 3 分の打ち切りは、画面が静まらないためではない。押下の 1 手のうち期限なし（`timeout: 0`）の Playwright の操作（欄の `inputValue`・`fill`、送信ボタンの `isDisabled`・`click`）が、狙う要素が文書から消えた（ページが欄を作り直した・ボタンが消えて戻らない）後も待ち続け、中身の進みの印が 3 分付かないため。
- 理由の名前が「静まらない」になるのは、L0 の判定が、最後の中身の進みの後にページの印が 1 回でも付けば `STAGE_NEVER_QUIET` とする作りのため（実験: ページの印は 2.7 秒で止まり、打ち切りは 180.6 秒）。
- 1 画面で何度もくり返すのは、打ち切りのたびに残りの候補を読み込み直して押し（`reprobeRemaining`）、新しい 3 分の見張りを一から数えるため。候補 N 個で N 回。
- 凍結が止める POST の手続きの呼び出し・その取り直し・GET の poll・アニメーションは、単独では打ち切りを起こさない（10 場面で 0 回）。
- 別の事実: 凍結の中で、共通の枠が押下ごとに手続きの呼び出しを出すと、押下の観察がそれを押下の送信の形として記録し、本当の保存の形が隠れる（実験の 3 場面。実 Run の `PROCEDURE_CALL_PATH` 152 件の正体の候補）。

## 2. 決めたこと

### 2.1 QUIET-1 消えた要素を待たない（調査の案 B・B2）
- 欄の 1 手（`onField` の `inputValue`・`fill`、選択肢の `selectOption`、RCA の入力）にも、今の送信ボタンの 1 手と同じ「狙う要素が文書から消えた」の確かめ（`stepOnUsableDocument` の `targetGone` の形）を付け、消えたら、その 1 手を見放す。見放した 1 手は、合図つきの locator が消えた要素にしか合わないので、後から入れない（新しい試験で確かめる）。
- 送信ボタンが消え、同じ鍵の替わり（DEF-289 の押し直しの対象）がないときも、見放す。替わりがあるときは、今の DEF-289 の押し直しのまま。
- 見放した候補の理由は、今の閉じた一覧の値を使う（新しい値が要るなら止まって報告）。新しい秒の値を足さない。
- 作り直された欄を読み直して入れ直す形（調査の B'）は、今回は行わない。

### 2.2 QUIET-2 打ち切りの理由の名前（調査の案 A）
- L0 の打ち切りの理由を、最後のページの印 1 つでなく、見張りの窓の後半もページの印が続いていたかで分ける（続いていなければ `STAGE_UNRESPONSIVE`）。窓の長さ（3 分）は変えない。点検の段と操作さがしで同じ部品なので、両方に効く。

### 2.3 QUIET-3 共通の枠の自発の送信を、押下の形にしない
- 押下の観察で、その押下の前から同じ文書で出ていた送信の形（同じ method・同じ path の形。押下の前の読み込みや、ほかの候補の押下でも出たもの）は、その押下の送信の形の候補から外す。ほかに形がなければ、今どおり記録する（取りこぼさない側）。凍結が止めることは変えない（守りは同じ）。
- 判定の材料が今の観察の記録で足りなければ、止まって報告する。

### 2.4 QUIET-4 次の実 Run の測り（DBG-1 を通す）
- 見張りが終えたとき（`watchDiscoveryScreen` の終わり）に 1 行: 終わりの理由、最後の中身の進みからの ms、最後のページの印の種類とそこからの ms。
- 待っている 1 手の印: 操作の名前（fill・inputValue・isDisabled・click・selectOption）と役割（FIELD・SUBMITTER・OPTION）、打ち切りの時点の locator の数。
- 書くのは数と digest と閉じた語だけ（URL・query の値・入力値を書かない）。測りの点の閉じた一覧に足す。

## 3. 受け入れ

- 調査の場面 g・g0（欄が作り直される）・h2（ボタンが消えて戻らない）を fixture にして: 打ち切り 0、読み込み直し 0（h2 は今の画面の移りの読み込み直しを除く）、1 押下が数秒。消えた要素に後から入れない（サーバに届く読み取りでない要求 0、記録の上でも）。
- 場面 h（同じ語の新しい要素で戻る）は今どおり DEF-289 で押し直す。
- QUIET-2: ページの印が早く止まった打ち切りは `STAGE_UNRESPONSIVE`、続いた打ち切りは `STAGE_NEVER_QUIET`（偽の時計）。
- QUIET-3: 共通の枠が押下ごとに手続きの呼び出しを出す画面で、本当の保存の形が記録される。
- QUIET-4: 入のとき行が書かれ、query の値が入らない。切のとき何もしない。
- tsc（root と `apps/local-ui`）0。関係する単体・architecture。ブラウザの結合は、変えた所を import するものだけを 1 本ずつ。

## 4. 速さと負荷

- 読み込みの回数は減るだけ（打ち切りの後の読み込み直しがなくなる）。見込み（調査の写しの値）: 1 押下 180.6 秒 → 約 1.7 秒。実 Run の打ち切りの待ち 221 分の大半が消える見込み（次の実 Run の DTIME で確かめる）。

## 設計変更履歴

- 2026-11-24 新規（ユーザーの判断と調査の結果に基づく）。
- 2026-11-24 QUIET-3 の Blocker（観察の記録は押下の窓の中で止めた形だけで、押下の外の形が残らない）に対応: 実装者の案 A を採る。操作さがしの要求の数え方（`InFlightRequestCounter` の `dataActivity().endpoints`。method・Origin・path）で、押下の窓の外（押下の前の読み込みと、押下の間）で出た口を画面ごとに集め、押下の窓の中だけで初めて出た口と分ける。押下の観察の形のうち、押下の窓の外でも出た口に当たるものは、押下の形の候補から外す（ほかに形がなければ今どおり記録）。観察の形（Origin の区分と path の型）と口（URL の path）の突き合わせは、今の path の型の部品の 1 か所で行う（写しを作らない）。案 B（凍結の前の読み込みが見えない）は採らない。
