## 1. 目的

監査は、端から端まで行う。何を読む・押す・記録するかを数（1 回だけ、全部、N 回まで、代表 1 つ、上限で打ち切り）で決めない。見つかった先は新しい監査の対象として、再帰的に広げる。終わりは構造の事実で決める。

## 2. ユーザーの方針（言葉どおり。2026-11-09）

- 「BeakSight内で上限を定めないで。サイトの構造に合わせて。」
- 「徹底的に端から端まで監査できなければ価値が無い」
- 「1度だけとか全部とか、そういう仕様の決め方が良くない。まさしく見落としが出る思想だ」
- 「違うかどうかは画面を見ないと分かりませんというのはおかしい。何のために監査をしているのか？監査で先が見つかったのなら、再帰的に監査の枝葉を伸ばしていけばよい」

## 3. 採用する設計

### 3.1 状態の鍵（SSOT。1 か所の純粋な部品）

1. **場所の鍵。** 次の 2 つを合わせたもの。
   - 正規化した URL。path の全体と、query の名前と値を持つ。秘密は伏せる。
   - frame・開いた枠の印。
   
   同じ場所の鍵は 1 回だけ読む。違う場所の鍵は全部読む。
2. **構造の鍵。** 次のものの digest。文字の値は入れない。
   - path の型（番号を `{id}` にしたもの）と、query の名前の集合
   - 共通の枠を除いた候補の識別の集合
   - 欄（名前・型・必須・無効・選択肢の値の集合）
   - 開いた窓・区画の有無
   - 見出しと landmark の構造
   - 状態の語
3. 置き場は `src/discovery/fingerprint.ts` の隣。見るだけの点検と操作さがしが共用する。

### 3.2 再帰的に広げる待ち行列（共通の部品）

1. 1 つの状態を読んだら、出た先を全部、辺として待ち行列に入れる。辺の種類は次のとおり。
   - リンク
   - SPA の経路
   - query の変化
   - 押した後の画面
   - 開いた欄や窓
   - frame
   - select・radio の選択肢
2. 押す辺は、（構造の鍵、候補の識別、状態の中の順番）がまだ見ていないものだけ。押した後の状態は、構造の鍵がまだ見ていないものなら、新しい段として読み直し、さらに伸ばす。
3. **終わり。** 待ち行列が空になったら終わる。同じ場所の鍵に戻った道や、同じ（構造の鍵・押す候補）に戻った道は、そこで終える。
4. **終わりのない続き（日付の「次へ」など）。** その道は、新しい場所の鍵（行き先のリンクなど）か新しい構造の鍵が出る間は続け、出なくなったら終える。終えた理由を記録に残す。
5. **共通の枠のボタン。** 「前の画面で押した」ことでは飛ばさない。構造の鍵が違う状態では押す（同じ構造の鍵の状態では押し直さない）。
6. 見るだけの点検の待ち行列（`crawl-frontier.ts`）と操作さがしの待ち行列（`discovery-run.ts`）を、この部品に寄せる。段ごとに違うのは「押してよい辺」だけにする。
   - 見るだけの点検で押してよいのは、Guard が読み取りでない送信を止める今の操作だけ。開いた状態（タブ・折りたたみ・窓）にも、DOM・axe・layout を当てる。
   - 操作さがしで押すのは、凍結した押下（送らない）。

### 3.3 置き換える決まり（INV-COV の表の (A) と (C*)）

| 決まり | 置き換え |
| --- | --- |
| 同じ型の画面を 1 つだけ読む（`SAME_TEMPLATE_PAGE_READ`） | 全部読む。押すのは、まだ見ていない構造の鍵の画面と候補だけ |
| 1 画面に押す数 3 回、入れたのに押せなかった回 3 回 | 外す。状態の鍵で終える |
| 読み込み直し 1 回まで | 押していない候補が残り、前の読み込み直しで進んだ間は続ける |
| 同じ識別の開き手は 1 つ（`SAME_IDENTITY_PRESSED`）、同じ語（`SAME_WORDS_NO_REQUEST`）、共通の枠（`SHARED_LAYOUT_PRESSED`） | 鍵を（構造の鍵・候補の識別）に変える |
| 移った先の編集の画面 3・同じ型は 1 回、先に読む登録の画面 10 | 外して、待ち行列に入れる |
| select・radio は最初の選択肢だけ | 選択肢ごとに選び、欄の構造の鍵が変わる選択肢の分を押す |
| query の値を全部捨てる正規化（既定） | query の名前と値を場所の鍵に入れる（3.2 の 4 で終える） |
| iframe の中を読まない | 同じ Origin の frame を状態として入れる |
| 見るだけの点検の操作 20 件・候補 100・深さ 20 | 外す。同じ構造の鍵の候補は重ねない |
| 内側のスクロールは最も大きい 1 つだけ | 全部の領域をたどる（AUD-5 と一緒） |
| 幅の走査は決まった 5 幅 | CSS の media query の境目の両側の幅を足す |
| Evidence・リンク・候補・目印・観察の型・読まなかった画面の記録の件数の上限 | 打ち切らずに、分けて集める・書く |
| READ の確かめの 20 の上限 | 外す。束に分けて続ける |
| 索引の型の digest 3 件（押す上限と結び付き。管理データの版 13 の CHECK） | 押す上限と切り離して外す（管理データの版を上げる） |
| AUD-2d の「1 回・最大 3 秒」 | DOM の digest が静まるまで（時間の上限は自分の処理の上限として記録する） |

### 3.4 変えないもの（サイトの負荷と安全の決まり）

- 読み込みの間隔（`createNavigationPacer`）、承認したサービスへの要求の 1 分あたり・1 回の Run の上限、自動ログインの間隔と回数。
- 操作さがしで押した送信は届けない（凍結）。削除・危険な語・資格情報は押さない・止める。
- 書き込みの段の決まり（承認した 1 回、入れ直しの回数、予期しない要求の上限）。
- 利用者が点検の開始で選ぶページの上限と時間の上限。

## 4. サイトへの負荷と時間

- BeakSight が出す読み込みは、見つかった先の数だけ増える。読み込みの間隔は今のまま守る。
- 11/4 の実テスト環境の規模での見積もり:
  - 同じ型の画面を全部読む: +31 ページ（約 +10〜13 分）
  - 押す回数: 1 画面 10〜60 回、1 回 3〜4 秒（+1〜7 時間）
  - 共通の枠を構造ごとに押す: +2 時間台
  
  実装の前に、1 画面 70〜250 個のボタンの仮の画面で、押す時間と要求の数を測る。
- 押す 1 回の間隔（静まる待ち 2 秒）と、1 回の押下の読み込み直しの扱いは、実装の設計書に明記する。
