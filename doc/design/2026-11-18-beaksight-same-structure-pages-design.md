# 同じ画面・同じ作りの画面の点検を減らす（追補設計書、2026-11-18）

## 1. 目的
- ユーザーの判断（2026-11-18）: 「1（実質的に同じ画面は点検しない）は確かに直してよい。2（作りが同じでデータだけ違う画面）は、2 回目以降は軽い点検にする。」
- 実環境の監査の Run の記録（数だけ。名前は伏せる）: 217 画面のうち、同じ作りの 2 つ目以降が 102 画面、計 23,349 秒（約 6.5 時間）。うち幅の走査が 19,541 秒（84%）、フォーカスの確かめ 771 秒、axe は Desktop 83 秒・Mobile 64 秒、主の読み込みは Desktop 1,179 秒・Mobile 1,158 秒。
- この設計書は、網羅の設計書 `2026-11-09-beaksight-coverage-by-state-design.md` 3.1〜3.2 の「場所の鍵が違えば全部読む」を、見るだけの点検のページについて拡張する。

## 2. 決まり
- **作りの鍵**: Desktop の主の読み込みで DOM を読んだ直後に作る。データを抜いた形にする。中身は path の型と query の名前、欄（名前・型・label）、見出しの構成、landmark、状態の語、操作の候補の形（tag・role・type・href の path の型。名前と文字は入れない）。
- **中身の要約**: layout を読んだ後に作る。中身は title、見える文字の全体、見出しの文字、画像（URL・alt・大きさ）、欄（名前・型・label・見えるか）と入っている値の digest（パスワードと hidden は除く）、送信のボタンの文字と値、layout のあらまし（文書の幅と高さ、layout の指摘の種類と対象の組）。リンクの href は入れない（戻り先の query だけが違う画面を同じにするため。表示は変わらない）。
- **1 回目（FULL）**: その作りで最初に読んだ画面。状態が AUDITED か、PARTIAL でも途中で止まった理由（時間切れ・不調・セッションの切れ・違反・中断・読み込みの失敗の閉じた一覧）がないときだけ 1 回目と認める。認められなければ、次の同じ作りの画面をしっかり点検し、それを 1 回目にする。表は巡回の保存に持たせ、再開でも引き継ぐ。
- **SAME**: 作りの鍵が 1 回目と同じで、中身の要約も同じ。links を読んだ後の段（画像・axe 以降、幅の走査、Mobile）をしない。記録に「どの画面と同じか」を残す。毎回変わる文字（時計など）があれば SAME にならず LIGHT に倒れる（違う側に倒れるので安全）。
- **SAME の記録（DUP-3 の後の判断、2026-11-18）**: SAME の画面は Mobile を始めない。Desktop の layout の事実は判定にだけ使い、指摘は作らない（同じ中身の 1 回目の指摘と重なるため。画像を撮らないので証拠のない指摘を作らない）。ページは途中で止まった扱い（PARTIAL）にせず、時間切れの再開の読み直し（EV-5）の候補にもしない。記録には深さ（SAME）と、どの画面と同じかを残す。そのための状態や理由の値は、閉じた一覧に任意の値として足す。
- **LIGHT**: 作りの鍵が同じで、中身の要約が違う。残すのは Desktop と Mobile の主の読み込み・dom・layout（重なり・はみ出し・見切れ・固定の枠の覆い）・画像・指摘の対象を撮る（reveal）・確かめ直し・links と、Desktop の axe（102 画面で約 1.4 分と安く、データで出る alt や名前の指摘を拾えるため）。省くのは Mobile の axe、幅の走査、Interaction、性能、フォーカスの確かめ。
- 段の表（FULL・LIGHT・SAME で、どの段をするか）は `page-audit-plan.ts` の 1 か所に置く（SSOT）。
- **使わない場面**: チェックした画面だけの点検（WSO）では使わない（利用者が選んだ画面なので全部しっかり点検する）。
- **再開（EV-5）**: 読み直しで点検を終えた画面は、そのとき 1 回目になれる。LIGHT の画面の読み直しは LIGHT のまま。
- page.json・run.json・巡回の保存の項目は任意で足し、版は今のまま（T44c の前例どおり）。

- **DUP-4・5 の後の判断（2026-11-18）**: SAME の相手は、しっかり点検した 1 回目に加え、点検を終えた LIGHT の画面も含める（中身が同じなので、省いても LIGHT で見る範囲を失わない。戻り先の query だけが違う画面が 1 回目の変種とは限らないため）。SAME の Mobile は `SKIPPED`・理由 `SAME_CONTENT_AS_EARLIER_PAGE`（detail は同じ中身のページの ID）で、途中で止まった理由には数えない（判定は `src/core/status.ts` の 1 か所）。SAME の Desktop は Rule に安全の記録だけを渡す（安全の指摘は残す）。FULL の画面の候補の発見は 2 回のまま（作りの鍵のための発見は DOM の直後で、Interaction の発見は後の段の後に遅れて出る候補を拾うため。どちらも読むだけで読み込みは増えない）。

- **REV-DUP の後の判断（2026-11-18）**: (1) 1 回目と認めるのは、LIGHT が省く段（段の表から導く: 幅の走査・Interaction・フォーカスの確かめ・Mobile の axe・性能）に未完了の理由がなく、Mobile が FAILED でも SKIPPED でもなく、止まった理由（時間切れ・不調・セッションの切れ・違反・中断・読み込みの失敗・文書の入れ替わり・落ち）がないときだけ。(2) 作りの鍵の path と query は `src/discovery/fingerprint.ts` の `isDataLikePathSegment`・`dataFreePathOf`・`dataFreeQueryItemsOf` で作る。数字を含む 3 文字以上の英数字（日付・番号）はデータ。query の値は数字・`/`・`:` を含まない 32 文字までの語（http で始まらない）だけ鍵に入れる。候補の行き先は同じ Origin の http だけ形を入れ、特別な scheme と外のサイトは種類だけ。(3) SAME の Desktop の Rule には安全・通信・console の記録を渡す（HTTP・資源・JS の指摘は残す）。始めるビューポートと Rule に渡す記録の種類も段の表の項目。(4) 欄の値の digest は記録に残さず判定の中だけで使う。(5) 既知の限界: SAME の画面の読み直しは前の相手のまま（中身を比べ直さない）、canvas・inline の SVG・背景の画像・閉じた details・iframe の中身は中身の要約に入らない、表に入った 1 回目が後で認められない形になっても表から消えない。

## 3. 報告
- まとめの 1 文（案）: 「同じ作りの画面が多かったので、2 つ目からは画面の崩れなど主な点だけを確かめました（N 画面）。中身がまったく同じ画面 M 個は、点検を省きました。」
- 画面ごと: 「『○○』の画面と同じ作りなので、軽い点検にしました」「『○○』の画面と同じ内容なので、点検を省きました」。語は `messages.ts`。

## 5. 時間の見込み
- 直した作りの鍵で実環境の Run の記録を数え直した（数だけ）: 215 画面が 135 の組、2 画面以上の組 13、同じ作りの 2 つ目以降 80 画面。ただし記録に候補の形がないので、本番の鍵は候補の形の分だけ割れて、この数より少なくなりうる。
- 2 つ目以降の画面は SWR の前の記録で平均 229 秒。LIGHT は主の読み込み 2 回と軽い段で、読み込みの間隔を入れて 1 画面 1 分弱の見込み。80 画面で約 5 時間が約 1 時間強になる見込み（実環境ではまだ流していない）。

## 6. 限界
- 同じ作りの 2 つ目以降の画面で、データでだけ出るボタンを押した先（Interaction）と、幅を変えたときにだけ出る崩れは見ない。候補の形が違えば作りの鍵が変わり、しっかり点検になる。
