# サイトの画面に出す名前を、見分けの印と分ける（追補設計書、2026-11-16）

## 1. 目的
- ユーザーの判断（2026-11-16）: 「見分けの印はそのままにして、画面に出す名前を別に持たせよう」。
- 今は、サイト（プロファイル）の名前 `profileId` が、見分けの印と画面に出す名前を兼ねている。点検の記録・書き込みの承認・ログインの設定がこの印に結び付くので、作った後は変えられない。
- 画面に出す名前を別に持ち、あとから変えられるようにする。見分けの印と、それに結び付く記録は変えない。

## 2. 決まり
- 画面に出す名前（表示名）は、管理データのプロファイルごとの表示の設定（`profile_display_settings`）に 1 列を足して持つ。管理データの版を 1 つ上げる（版ごとに 1 ファイルの今の作り。前の版のデータは表示名なしで読める）。プロファイルの文書（設定の JSON）と、その digest・版は変えない。
- 表示名がない・空のときは、今どおり `profileId` を出す。表示名の決め方（なければ印）は 1 か所の関数にし、画面のどこもそれを通す。
- 長さは 1〜80 文字（前後の空白は除く）。改行と制御文字は不可。同じ表示名のサイトがあってもよい（見分けは印で行う）。秘密の語の検査の対象ではない（利用者のこのパソコンの中だけの値）。
- 出す所（ローカルの画面だけ）: 点検するサイトの一覧の名前、サイトの詳細の題、作業の履歴・ジョブの詳細のサイトの名前、ほかに `profileId` を利用者に見せている所。URL・記録のファイル・報告（HTML・CLI・バンドル）は、今どおり印を使う。
- 変える所: サイトの詳細の「詳しい設定」の中に「画面に出す名前」の欄を 1 つ足し、保存で変える。作る画面は今のまま（作るときの名前は、印と最初の表示名の両方になる）。
- 画面の文は利用者向けにやさしく、技術の語（ID・プロファイルなど）は出さない。

## 3. 受け入れ条件
- 表示名を変えて保存すると、一覧・詳細の題・履歴で新しい名前が出る。印・記録・承認・ログインの設定は変わらない。
- 前の版の管理データを開けて、表示名なしで今どおり出る（移行のテスト）。
- 空・長すぎ・改行の表示名は保存できず、分かる文が出る。
- 画面のテスト（`npm run test:ui` の関係するもの）と、管理データの単体。

## 4. 段
- DN-1: 管理データの版上げ、表示名の読み書き、表示名の決め方の関数、画面の欄と出す所。
