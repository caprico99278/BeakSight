# 操作の候補の発見と READ の確かめの手順（テスト環境・読むだけ）

テスト環境の管理画面に、ログインの後に「どんな操作があるか」を書き込みなしで洗い出し（操作の候補の発見）、読み取り（READ）の操作だけは実際に読んで、期待と照らす（READ の確かめ）手順です。候補と結果の見方、サイトへの読み込み、守りの範囲、確かめていないことも書きます。
画面の操作の細部は「[管理画面の操作の候補と READ の確かめ](local-ui.md#操作の候補と-read-の確かめ)」に、ログインと、ログインの後の読み取りの決まり（読まないパス、伏せ字、セッションが切れたときなど）は「[認証つきの監査](authenticated-audit.md)」と「[自動ログイン](automated-login.md)」にあります。

[README に戻る](../../README.md)・[仕様の索引](README.md)

> 操作の候補の発見と READ の確かめは、管理画面からだけ動かせます（CLI からは動かせません）。テスト用の小さなサイトで確かめています。実際のテスト環境へは、まだ接続して確かめていません。

## 使ってよい場合

- **テスト環境だけに使います。本番には使いません。** 本番から隔離されていることを確かめたテスト環境だけを対象にします（「[認証つきの監査の使ってよい場合](authenticated-audit.md#使ってよい場合)」と同じです）。
- 監査モードが `TEST_AUTH_PASSIVE`（認証つきの読み取り）か `TEST_APPROVED_WRITE`（承認した書き込み）のプロファイルで使えます。どちらも、始める条件（認証の設定、自動ログインなら資格情報）は同じです。公開の監査のプロファイル（`PUBLIC_PASSIVE`）では使えません（「[モードごとに使える操作](profiles.md#モードごとに使える操作)」）。
- `TEST_APPROVED_WRITE` のプロファイルでも、発見と READ の確かめは書き込みをしません（下の「[守りの範囲](#守りの範囲)」と同じです）。このモードの監査（`AUDIT`）は実行できません。書き込みは、シナリオを承認した後に、別の画面から人が始めます（「[承認された登録の手順](approved-create.md)」）。
- **READ の確かめの送る値は、テスト環境のテスト用の値だけにします。** 送る値は、管理データにそのまま保存し、画面に表示します（「[READ の定義](#4-read-の確かめの定義を作る)」）。

## 手順

### 1. プロファイルと認証の設定を用意する

認証つきの監査と同じプロファイルと認証の設定を使います。承認した書き込みのモード（`TEST_APPROVED_WRITE`）のプロファイルでも、同じ手順で認証の設定（自動ログインなら資格情報）を作れます（プロファイルの `mode` だけが違います）。

- 手動のログイン（`MANUAL_SESSION`）: 「[認証つきの監査の手順 1〜3](authenticated-audit.md#手順)」。
- 自動ログイン（`AUTOMATED_LOGIN`。Windows だけ）: 「[自動ログインの手順 1〜5](automated-login.md#手順)」（資格情報の登録とログインの確かめまで）。

読み込む範囲は、認証の設定の「読む範囲のパス」（`auditPathPrefixes`）の中で、「読まないパス」と既定で読まない語を除いたものです。速さの上限（`crawl.minNavigationIntervalMs`、`crawl.maxPages`、`crawl.maxDepth`、`crawl.maxRuntimeMs`）は、プロファイルの設定のファイルの値のまま使います。

### 2. ログインする

どちらのジョブも、始めるたびに、ジョブの初めにログインします（前のジョブのログインの状態は使いません）。

- 手動のログイン: ジョブを始めると、ログインのためのブラウザが開きます。人がそのブラウザでログインします（「[開いたブラウザでログインする](authenticated-audit.md#5-開いたブラウザでログインする)」と同じです）。
- 自動ログイン: BeakSight が、保存した資格情報で 1 回だけログインを送信します。自動ログインの上限（同じプロファイルで `AUTO_LOGIN_MIN_INTERVAL_MS`＝5 分以上あける、24 時間に `AUTO_LOGIN_DAILY_MAX_ATTEMPTS`＝10 回まで、など）は、発見と READ の確かめのジョブにも掛かります。発見の直後に READ の確かめを始めるときは、5 分あけます。

### 3. 操作の候補を探す（発見）

プロファイルの詳細の「操作の候補と READ の確かめ」から画面「操作の候補」を開き、「操作の候補を探す」を押します。

- BeakSight は、ログインの後に、読む範囲の管理画面をリンクでたどって読み込み、各画面のフォームとボタンを集めて分類します。**フォームの送信、入力、クリックはしません。**
- 各画面は、読み込んでから落ち着くのを待ちます。落ち着いたとみなす条件は、「進行中の要求が 0 の状態が `DISCOVERY_NETWORK_QUIET_MS`＝500 ms 続く」かつ「2 回続けて同じ候補の集合」です。待つ上限は `DISCOVERY_SETTLE_TIMEOUT_MS`＝5 秒です。
- 落ち着きの待ちの間は、候補の集合を、間隔をあけて何度も読みます（1 回だけではありません）。読み始めどうしの間は `DISCOVERY_SETTLE_PROBE_INTERVAL_MS`＝250 ms 以上あけます。この間の読み取りは、凍結の前に行います。
- 落ち着いたら（または上限を超えたら）、ページの JavaScript による送信を止め（Interaction の凍結）、最後にもう 1 回読みます。候補は、この最後の読み取りから作ります。
- ページの中の読み取りは、CDP の isolated world で行います。isolated world は、ページの JavaScript とは別の global と prototype で、同じ DOM を読む所です。そのため、ページの JavaScript は、標準の関数を書き換えて読み取りの結果を偽れません。読み取りの間に、ページの JavaScript は動きません。
- JavaScript の結び付き（listener）は、main world の要素の objectId を使って、CDP の読み取り（`DOMDebugger.getEventListeners`）で取ります。listener は、登録した world の objectId からしか取れないためです。これも CDP の側で読むだけで、ページの JavaScript は動きません。
- 画面ごとに新しいブラウザのコンテキストを使います。
- ジョブが止まったら（中断、止める、セッションの切れなど）、再開はしません。もう一度始めます。

### 候補の見方

画面「操作の候補」には、最後の発見の要約と、画面（path）ごとの候補の一覧が出ます。

**分類**（`src/discovery/candidate-contracts.ts` の `CANDIDATE_CLASSIFICATIONS`）は、規則の表で決めます（意味の判断や LLM は使いません）。次の順で、最初に当たったものに決めます。

| 順 | 条件 | 分類 | この画面から |
| --- | --- | --- | --- |
| 1 | 送信先が許可 Origin の外 | `BLOCKED_EXTERNAL` | 実行できない |
| 2 | 実際の method が DELETE、危険な語（送信ボタンの文言、送信先の path、query の名前、GET のフォームの欄の名前。英語と日本語の閉じた一覧 `DISCOVERY_DESTRUCTIVE_WORDS`）、または GET のフォームに `_method` の欄がある（型を問わない） | `NOT_EXECUTABLE`（理由 `DESTRUCTIVE`） | 実行できない |
| 3 | GET のフォーム（password の欄を持つ GET、multipart の GET は `UNSUPPORTED_READ_TRANSPORT`。JavaScript の結び付きがあれば `NEEDS_BINDING`） | `READ` | READ の確かめに使える |
| 4 | POST の検索（検索・絞り込みの語）、`/graphql` への POST | `UNSUPPORTED_READ_TRANSPORT` | 実行できない |
| 5 | JavaScript の結び付き（フォームや送信ボタンの listener、document・window・祖先の押す・送る listener の委譲） | `NEEDS_BINDING` | 実行できない |
| 6 | PATCH・PUT（`_method` を含む）、または更新の語 | `UPDATE` | 実行できない（書き込みのモードでは、シナリオにできる） |
| 7 | 登録の語 | `CREATE` | 実行できない（書き込みのモードでは、シナリオにできる） |
| 8 | それ以外（listener のない form の外のボタン、`dialog` の form、閉じた一覧の外の `_method`、同じ識別で中身の違う候補など） | `DISPLAY_ONLY` | 実行できない |

- **READ だけが「READ の確かめに使える」です。** `CREATE` と `UPDATE` の候補は、この画面からは実行しません。承認した書き込みのモードのプロファイルでは、シナリオにして承認した後に、1 件ずつ送れます（「[書き込みのシナリオの承認の手順](scenario-approval.md)」）。`NOT_EXECUTABLE`・`NEEDS_BINDING`・`DISPLAY_ONLY` は、どの段階でも、推測だけで実行の対象にしません。
- **危険な語の比べ方**: 比べる前に、Unicode の正規化（NFKC）と大文字小文字の畳み込みをかけます（全角の英数字も当たります）。比べる所によって、当たり方が違います。
  - 送信ボタンの文言（ボタンの文字・`aria-label`・`title`）、送信先の path（percent-encode を外した形も）、送信先の query の名前、READ の確かめの送る値の名前と値: 部分一致です。区切り（空白、`-`、`_` など）を除いた形でも比べます（`Sign out` も `signout` に当たります）。
  - GET のフォームの欄の名前（英語の語）: 語の単位で比べます。欄の名前を、区切り（`_`・`-`・`.`・`[`・`]`・空白など）、数字との境、大文字の切れ目で分けた語と一致したときだけ当たります。たとえば `delete_flag`・`deleteFlag`・`user[remove]`・`delete2` は当たり、`include_disabled`・`show_archived`・`filter[deleted]` は当たりません。
  - GET のフォームの欄の名前（2 語の語）: `sign-out` などの 2 語の語は、分けた語がその順に並んだときに当たります。
  - GET のフォームの欄の名前（日本語の語）: 区切りがないので、部分一致です（`削除フラグ` は `削除` に当たります）。
- GET のフォームに、型を問わず（見える欄でも）`_method` の名前の欄があれば、実行できないもの（理由 `DESTRUCTIVE`）にします。送ると、サーバが method の上書きとして扱いうるためです。
- `active`・`status`・`deleted` などの名前の欄を持つ候補には、「状態の欄」の印を付けます。
- 読み切れなかった画面には、理由（`INCOMPLETE_SETTLE_TIMEOUT`: 落ち着きの待ちの上限、`INCOMPLETE_FRAME_OR_CLOSED_SHADOW`: iframe か closed な shadow root がある、`INCOMPLETE_LIMIT_REACHED`: 読む上限（1 つの画面の候補は `MAX_PAGE_CANDIDATES`＝500 件まで、など）に達した、など）を出します。読めた分の候補は出します。

**ドリフト**（`DISCOVERY_INDEX_DRIFTS`。最後の発見に対して）は、候補の識別（画面、method、送信先、入力の欄の名前と種類、送信ボタンの分類の語などの digest。入力の値とトークンは入れません）で突き合わせます。表の行ごとに文言の違うボタンでも、分類の語の組が同じなら、同じ識別になります。

| 値 | 意味 |
| --- | --- |
| `NEW` | 新しく現れた。 |
| `CHANGED` | 入力の規則（必須、読み取り専用、制約、選択肢の値など）、分類、理由、状態の欄の印のどれかが変わった。 |
| `UNCHANGED` | 変わらない。 |
| `MISSING` | 読み切れた画面に、もうない（記録は残す）。 |
| `NOT_REVISITED` | その画面を、今回は読まなかった（ページの上限など）。 |

各候補の「詳しい内容」には、ボタンの分類の語、欄の名前・種類・必須などの印と制約、選択肢の値（`MAX_SELECT_OPTION_VALUES`＝50 件まで）、値を送れるかを出します。

- **送信ボタンの文言は、成果物にも画面にも出しません。** 文言（ボタンの文字。`input` のボタンは `value`、画像のボタンは `alt`。ほかに `aria-label`・`title`）は、分類の語の閉じた一覧（`DISCOVERY_SUBMITTER_WORDS`。危険な語・検索の語・更新の語・登録の語）のうち、文言に当たった語だけに変えてから捨てます。表の各行のボタンの文言（例「<行の名前> を編集」）から、行の中身を写さないためです。
- 成果物（`discovery.json` の `submitterWords`）と画面（「ボタンの分類の語」）には、その分類の語だけを出します。当たる語がなければ、画面には「分類の語なし」と出します。
- `<label>`、`aria-labelledby`、`aria-describedby` の文も、候補に持ちません。
- **入力の値、CSRF のトークン、hidden の値、選択肢の label は、成果物にも画面にも出しません。**
- **ページが書いた値をそのまま持つ項目があります。** 送信先の path と query の名前、欄の名前、欄の制約（`pattern`・`min`・`max`・`step`・`minlength`・`maxlength`・`autocomplete` の属性の文字列）、選択肢の値です。ページがそこに個人情報や表の行の中身を書けば、`discovery.json` と画面に出ます（例: 送信先の path に利用者の ID、`pattern` に名前）。
- **選択肢の値（`value`）は持ちます。** READ の確かめの定義で、送る値を選ぶために要るためです。選択肢の値は、利用者の ID、名前、メールアドレスなどの個人情報になりえます。`discovery.json` と画面は、テスト環境のデータと同じに扱ってください。

### 4. READ の確かめの定義を作る

画面「READ の確かめ」の「READ の候補」の「この候補で作る」から、送る値と期待を決めて保存します。

- **送れる欄**: その候補の、名前があり、見えていて、読み取り専用でも無効でもない欄だけです。値を入れた欄だけを送ります。hidden の欄、CSRF のトークン、読み取り専用の欄の値は送りません。パスワードとファイルの欄は、名前にかかわらず送りません（値を入れると、保存せずに理由 `READ_PARAMETER_NOT_ALLOWED` を出します。この決まりより前に保存した定義も、READ の確かめの前に止めます（`READ_BLOCKED_BY_POLICY`、詳しい理由 `PARAMETER_NOT_SENDABLE`））。
- **秘密に見える名前の拒否**: 秘密に見える名前（`token`、`session`、`code`、`state`、`key`、`api_key` など。URL の伏せ字と同じ一覧。「[秘密を出さないこと](authenticated-audit.md#秘密を出さないこと)」）の欄に値を入れると、保存せずに、その欄に理由（`READ_PARAMETER_SECRET_LIKE`）を出します。黙って落としません。
- **危険な語の拒否**: 送る値の名前か値に、発見の分類の危険な語（`DISCOVERY_DESTRUCTIVE_WORDS`。日本語を含む）があると、保存せずに、その欄に理由（`READ_PARAMETER_DANGEROUS_WORD`）を出します。比べ方は部分一致です（「[候補の見方](#候補の見方)」の危険な語の比べ方）。percent-encode を外した形でも比べます。
  - 部分一致なので、管理画面の状態の絞り込みでよく使う値も止まります。例: `deleted`、`disabled`、`cancelled`、`停止中`、`無効`、`キャンセル済み`。名前も同じです。例: `reset_date`、`batch_no`。値の中に語を含むものも止まります。例: `archive2024`。
  - 止まる値で読みたいときは、その値を使わない定義にしてください。危険な語を送る READ の確かめは、今はできません（止める側に寄せています）。
- **期待の種類**（`READ_CHECK_EXPECTATION_KINDS`。1 件以上 `MAX_READ_CHECK_EXPECTATIONS`＝10 件まで）:

| 種類 | 意味 |
| --- | --- |
| `ROW_COUNT_EQUALS` | 結果の表（または一覧）の行の数が、ちょうどこの数。 |
| `ROW_COUNT_AT_LEAST` | 結果の表（または一覧）の行の数が、少なくともこの数。 |
| `TEXT_CONTAINS` | 結果の本文が、この文を含む。 |
| `DETAIL_FIELD_EQUALS` | 結果の詳細（`dl`）の、この名前の項目の値が等しい。 |

- 1 つのプロファイルの定義は `MAX_READ_CHECK_DEFINITIONS_PER_PROFILE`＝20 件までです。送る値の長さは `MAX_READ_CHECK_PARAMETER_VALUE_LENGTH`＝256 文字までです。
- 保存のときに、サーバが、最後の発見の結果の候補に照らして確かめ直します。拒んだときは、理由（`READ_CHECK_DEFINITION_REJECTION_REASONS`: 秘密に見える名前、危険な語、送れない欄、READ でない候補、最後の発見の結果にない候補、件数の上限、版の衝突など）を項目ごとに出します。

### 5. READ を確かめる

画面「READ の確かめ」の「READ を確かめる」を押します。定義が 1 件もなければ、始められません。

- BeakSight は、ログインの後に、定義ごとに次を行います。
  1. 対象の候補の画面を読み込み、候補が同じ形（識別の digest が同じ）で、今も `READ` に分類されることを確かめます。送る値の欄が、今も送れる欄であることも確かめ直します。
  2. 候補の送信先と、定義の送る値だけで、GET の URL を組み立てます（**フォームの送信はしません**。CSRF のトークン、hidden の値、読み取り専用の値は URL に入りません）。組み立てる前に、送る値の名前と値に、秘密に見える名前と危険な語がないことを確かめ直します。危険な語があれば、読まずに `READ_BLOCKED_BY_POLICY`（詳しい理由 `PARAMETER_DANGEROUS_WORD`）にします。この確かめ直しで、危険な語の拒否より前に保存した定義も止まります。
  3. 読み込む前に、要求の判定（読まないパス、既定で読まない語、許可 Origin の外、ログインの画面）に通し、止まれば読みません。
  4. 読み込みの間隔を守って、新しいブラウザのコンテキストで URL を読み込み（GET）、落ち着いた後に、結果を表・一覧・詳細の構造にして、期待と照らします。
- ジョブが止まったら、再開はしません。もう一度始めます。

### 6. 結果の見方

画面「READ の確かめ」に、ジョブごと・定義ごとの結果（`READ_CHECK_RESULTS`）を出します。

| 結果 | 意味 |
| --- | --- |
| `MATCHED` | 読んで、すべての期待に合った。 |
| `NOT_MATCHED` | 読んで、合わない期待があった。 |
| `UNDETERMINED` | 判定できなかった（数える構造がない・2 つ以上ある、HTTP の 4xx・5xx、読み込みの失敗、落ち着かない、セッションの切れなど）。 |
| `READ_BLOCKED_BY_POLICY` | 読む前に止めた（読まないパスなどの要求の判定、秘密に見える名前、送る値の危険な語、送れなくなった欄、URL を組み立てられない）。 |
| `READ_CANDIDATE_DRIFTED` | 対象の候補が見つからない（画面が変わった）。発見をやり直し、定義を見直します。 |
| `READ_CANDIDATE_NOT_READ` | 対象の候補が、今は `READ` に分類されない（POST に変わった、JavaScript の結び付きが付いた、など）。 |

- 詳しい理由（`READ_CHECK_DETAILS`）、HTTP の状態、期待ごとの結果の要約（数えた行の数、文を含んだか、詳細の項目の取れた値）を出します。**表の全体（テスト環境のデータ）は写しません。**
- 成果物 `read-evidence.json`（Run のディレクトリ）には、定義の ID、読んだ URL（伏せ字の後。送る値が入ります）、HTTP の状態、構造の要約（件数と照らした項目だけ）、照らした結果を書きます。発見の成果物は `discovery.json` です。`discovery.json` の画面ごとの安全の記録（`blockedRequests`）は、読み取り以外の method の遮断（Guard が止めた POST など）だけを数えます。読まないパスと既定で読まない語による遮断（理由 `AUDIT_EXCLUDED_URL`）と、出口の中継の拒否は、この数に入りません（DEF-090）。
- `read-evidence.json` と `discovery.json` は、画面からダウンロードできます（「[成果物の取り出し](local-ui.md#成果物の取り出し)」）。
- 発見の Safety Ledger の記録（遮断した要求の一つ一つ、中継の拒否など）は、`discovery.json` を含むどの成果物にも出ません（DEF-090）。`discovery.json` に入るのは、上の画面ごとの件数（`blockedRequests`）だけです。

## サイトへの読み込み

| ジョブ | 読み込み | 上限 |
| --- | --- | --- |
| 発見（`DISCOVERY`） | ログインの段の画面と、読む範囲の画面を 1 画面につき 1 回 | 設定の `crawl.maxPages`、`crawl.maxDepth`、`crawl.maxRuntimeMs` |
| READ の確かめ（`READ_CHECK`） | ログインの段の画面と、対象の候補の画面を 1 画面につき 1 回、定義ごとに READ の URL を 1 回 | 1 回のジョブで READ は `MAX_READ_CHECKS_PER_JOB`＝20 件まで（承認された値）。設定の `crawl.maxRuntimeMs` |

- 読み込みどうしの間隔は、設定の `crawl.minNavigationIntervalMs` 以上あけます（公開の監査と同じ。「[サイトへの負荷](site-load.md)」）。発見と READ の確かめは、今の監査とは別のジョブなので、監査と合わせて回数が増えます。
- 読み込み直し（再試行）はしません。読めなかった画面は「読めなかった」と記録します。
- ページ自身が読み込む画像やスクリプト、fetch などの GET は、公開の監査と同じく届きます。

## 守りの範囲

- **書き込みは 0 件です。** 発見と READ の確かめの間に、BeakSight がサイトへ送る要求は、ログインの段で許したログインの送信（POST。自動ログインは 1 回）のほかは、GET と HEAD だけです。ページのスクリプトが送ろうとした送信（ビーコンなど）は、公開の監査と同じく Guard が止めて記録します。
- **発見の間は凍結します。** 各画面を読む前に、そのページの JavaScript による送信を止めます（Interaction の凍結）。発見のコードは、クリック、入力、キーの押下、イベントの発火、フォームの送信を呼びません（自動の検査で確かめます）。
- **ページの JavaScript は読み取りを偽れません。** 発見のフォームとボタンの読み取りと、READ の結果の構造の読み取りは、CDP の isolated world で行います（「[3. 操作の候補を探す](#3-操作の候補を探す発見)」）。読み取りの間に、ページの JavaScript は動きません。
- **閉じる前に、通信の中継を凍結します。** 発見と READ の確かめを含む、Guard の付いたすべてのブラウザの環境（Context）の通信は、BeakSight の出口の中継（127.0.0.1 の proxy）を通ります。Guard は、環境を閉じる前に中継を凍結します。凍結した中継は、すべての通信を拒みます。
  - これは DEF-085 の対策です。ページが同じタスクの中で 2 つ目のポップアップを開くと、環境を閉じる途中に、そのポップアップの要求が Guard の横取りを外れて、読まない URL や別の Origin へ届くことがありました。その要求を、凍結した中継が拒みます。
  - 閉じる直前に凍結した中継が拒んだ要求は、Safety Ledger に記録しません。Guard の許した普通の要求（ポーリングなど）と見分けられないためです。中継が閉じた後に出ようとした要求も、届きませんが、記録は残りません。
  - 発見の凍結では、中継も一緒に凍結します。その後に中継が拒んだ要求は、理由 `INTERACTION_FROZEN_EGRESS` で記録します。この記録は、凍結の時点で進行中だった、Guard が許した普通の要求を含むことがあります（凍結で上流の接続が壊れ、Chromium が送り直すため。推測）。そのため、Guard を通らずに出た要求の証拠とは限りません。Interaction の環境でも同じです。Guard の許さない method や URL を中継が拒んだ要求は、理由 `GUARD_BYPASS_EGRESS` で記録します。
  - 公開の監査も同じ中継を通ります（「[読み取り専用の保証の範囲](safety.md#読み取り専用の保証の範囲)」）。
- **URL は定義の値だけです。** READ の URL の query は、定義の送る値の名前だけです（巡回の正規化と `crawl.allowedQueryParameters` は通しません）。保存の後に欄が見えなくなった・読み取り専用になった・無効になった場合は、読まずに止めます。
- **読まないパスと既定で読まない語**は、発見の巡回でも READ の URL でも読みません（「[監査の段](authenticated-audit.md#監査の段)」と同じ判定）。
- **秘密を出しません。** Cookie、localStorage、資格情報、CSRF のトークン、hidden の値、入力の欄の今の値、選択肢の label、ボタンの文言（文字・`value`・`alt`・`aria-label`・`title`）、`<label>`・`aria-labelledby`・`aria-describedby` の文は、成果物（`discovery.json`、`read-evidence.json`）、管理データ（候補の索引は、指紋・分類・画面の path・時刻だけ）、画面、ログ、ワーカーとの間の通信のどこにも書きません。URL は伏せ字を通します。
- **ページが書いた値は、そのまま出ます。** 送信先の path と query の名前、欄の名前、欄の制約、選択肢の値は、ページが書いた値をそのまま持ちます（「[候補の見方](#候補の見方)」）。ページがそこに表の行の中身や個人情報を書けば、成果物と画面に出ます。「表の行の中身を書かない」の範囲は、上の読まない所と、ボタンの文言です。
- READ の送る値（テスト用の値）が出てよい場所は、次の 5 つだけです。
  - 定義の画面。
  - 管理データ。
  - `read-evidence.json` の URL（伏せ字の後）。
  - 親（画面のサーバ）からワーカーへのジョブの開始の通信（`START`。定義の一覧）。
  - ワーカーから親へのログインの状態の知らせ（`AUTH_STATE`）の、セッションの切れ（`SESSION_LOST`）の URL。この URL は管理データに記録されます。READ の URL の読み込みでセッションが切れると、送る値を含む URL で知らせるためです。

### 確かめたこと（目印の検査）

テスト用の小さなサイトで、実行ごとのランダムな値を目印にし（セッションの Cookie、localStorage、資格情報、CSRF のトークン、hidden の値、入力の欄の今の値、選択肢の label、表の行の中身（行のボタンの文字・`value`・`alt`・`aria-label`・`title`、`<label>`・`aria-labelledby`・`aria-describedby` に置いたものを含む）、秘密に見える名前の欄に入れて拒まれた値）、手動のログインと自動ログイン（本物の DPAPI。Windows）のそれぞれで、画面から発見 → 定義の作成 → READ の確かめを行って、目印が 1 つも出ないことを、UTF-8 と UTF-16LE の両方のバイトで確かめています。

- 探した場所: Run のディレクトリのすべてのファイル（`discovery.json`、`read-evidence.json`、ZIP があれば中身）、管理データのファイルと WAL と SHM と、すべての表のすべての行、画面のサーバとワーカーの標準出力と標準エラー、ワーカーとの間の通信のすべて（両方の向き）、すべての画面の HTML と成果物の画面、Server Function の応答、子プロセスの起動の引数。
- READ の送る値が、上の出てよい場所にだけ出ることも確かめています。ただし、`AUTH_STATE` の `SESSION_LOST` の URL は、この確かめの場面でセッションが切れないため、確かめていません。
- 同じ確かめで、サイトに届いた要求が、GET と HEAD のほかはジョブごとにログインの送信 1 回だけであること、発見の間の GET は BeakSight の読み込みとページ自身の GET だけであること、読まないパス・危険な語・範囲の外へは 0 件であること、読み込みの間隔が設定の値以上であること、READ の URL の query が定義の名前だけであることを確かめています。
- 探す読み方が正しいことは、わざと目印を置いたファイル（UTF-16LE、圧縮した ZIP の中、SQLite の WAL、表の行）で見つかることで確かめています。

## 確かめていないこと・使えないこと

- **closed な shadow root と iframe の中**: 読みません。その画面を「不完全」（`INCOMPLETE_FRAME_OR_CLOSED_SHADOW`）として記録します。open な shadow root は読みます。
- **SPA の待ちの上限**: 落ち着きの待ちの上限（`DISCOVERY_SETTLE_TIMEOUT_MS`＝5 秒）を超えて後から描画される候補は、見落とすことがあります（その画面は「不完全」として記録します）。
- **POST で読む画面**: POST の検索と `/graphql` は `UNSUPPORTED_READ_TRANSPORT` として表示だけします。READ の確かめはしません。HEAD も使いません。
- **CREATE と UPDATE の実行**: 発見と READ の確かめでは行いません。候補をシナリオにして承認・撤回する手順は「[書き込みのシナリオの承認の手順](scenario-approval.md)」に、承認の後に送る手順は「[承認された登録の手順](approved-create.md)」と「[承認された更新の手順](approved-update.md)」にあります。
- **閉じた一覧の語の限界**: 分類と危険な語の拒否は、閉じた一覧の語との比べだけで決めます。次のものは当たりません。
  - 一覧にない言語の語（中国語、ドイツ語など）。
  - 似た形の文字（キリル文字の `е` など）で書いた語。
  - `İ`（U+0130）を含む語の一部。`İ` は、畳み込むと `i` と結合文字（U+0307）になります。部分一致の比べは、区切りを除いた形で当たりますが、欄の名前の語の単位の比べと、検索・更新・登録の語の比べでは当たりません（例: 欄の名前 `dİsable_flag`、ボタンの文字 `Edİt`）。
  - アイコンだけのボタン（文字、`aria-label`、`title` がない）。
  - 欄の名前の語形の変化（`deleted`、`archived` などは、`delete`、`archive` に当たりません）。
- **欄の名前の語の単位の比べをすり抜ける形**: GET のフォームの欄の名前で、語を区切りや別の文字で割った形は、危険な語に当たりません。例: `dele_te`、`de` と `lete` の間にゼロ幅の文字（U+200B など）を挟んだ形、結合文字を混ぜた形（`délete` など）、`re-move`、`DELETİON`。
- **形を変えた `_method` の欄**: 先頭に空白やゼロ幅の文字のついた名前（` _method` など）は、`_method` の欄として扱いません。サーバがその名前を `_method` と読む作りの場合は、止められません。
- 一方で、`bulk`・`batch`・`reset` などの危険な語は、欄の名前の中に語として現れれば当たります（例: `bulk_size` の GET のフォームは、実行できないものになります）。止める側に寄せた結果です。
- **path の中の ID の型**（`/items/123` と `/items/456` を同じ画面として扱うこと）: しません。別の画面として記録します。
- **ページのスクリプトの読み取り**: ページ自身が読み込みのときに送る GET（画像、スクリプト、fetch）は、公開の監査と同じく届きます。その GET が、サイトの側で状態を変える作りの場合は止められません（GET で状態を変えるサイトの作りは、守りの範囲の外です）。
- **実際のテスト環境**: まだ接続して確かめていません（ユーザーの承認の後に、小さく確かめます）。
- 公開の監査のプロファイルでの発見、CLI からの発見と READ の確かめ。
