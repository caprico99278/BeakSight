# CLI

CLI のオプションの細かい決まり、headless で使うブラウザ、終了コード、実行中と結果の表示、Windows PowerShell での日本語の表示です。
コマンドとオプションの一覧は、README の「[使い方](../../README.md#使い方)」にあります。

[README に戻る](../../README.md)・[仕様の索引](README.md)

## オプション

- `--headed` と `--headless` は、同時に指定できません。同時に指定すると、設定のエラー（終了コード 4）になります。
- `--new` は、`run` だけのオプションです。`validate-config` で指定すると、設定のエラー（終了コード 4）になります。`--new` は値を取りません（`--new=yes` のように値を付けると、設定のエラーになります）。
- 値を取るオプション（`--config`、`--output`）を2回以上指定すると、設定のエラー（終了コード 4）になります。後の値で上書きすることはしません。
- 知らないオプション、値のないオプション、余分な引数、知らないコマンドも、設定のエラー（終了コード 4）になります。このとき、使い方も表示します。
- `--help` は、ほかの引数を解析できれば、コマンドの有無によらず使い方を表示します。
- どちらのオプションも指定しない場合は、設定の `browser.headed` に従います。既定値は `false`（headless）です。

## headless で使うブラウザ

BeakSight は、headless で実行するときも、Playwright に同梱の通常の Chromium（`channel: 'chromium'`）を、新しい headless の方式で使います。
これは `npx playwright install chromium` で入るもので、追加の準備は要りません。
headless の既定のブラウザ（`chrome-headless-shell`）を使わないのは、Windows では、そのブラウザが Ctrl+C を受けて終わってしまい、1回目の Ctrl+C で今のページを監査し終えられないためです（「[中断と再開](resume.md#中断と再開)」の「Ctrl+C で止める」）。

## 終了コード

終了コードは、最終の Run Status と、Run の外で決まる結果（設定のエラー、Run を始められない、中断）だけで決まります。
サイトの Finding の件数（エラーが何件あるか）では決まりません。
エラーの Finding があっても、必要な確認をすべて終えていれば、終了コードは 0 です。

| 終了コード | 結果 | 意味 |
| --- | --- | --- |
| `0` | 完了（`COMPLETE`） | 必要な確認を、すべて終えました。`validate-config` の成功と、`--help` も 0 です。 |
| `1` | 失敗（`FAILED`） | 監査を実行できませんでした。結果のファイルを書き出せなかった場合と、想定していないエラーの場合も 1 です。 |
| `2` | 一部未完了（`PARTIAL`） | 一部の確認を終えられませんでした。結果は、確認できた範囲のものです。1回目の Ctrl+C で止めた場合、実行時間の上限で止まった場合、サイトが応答しないため止まった場合も、ふつうは 2 です（同じコマンドで、続きから再開できます）。 |
| `3` | 安全のため中止（`ABORTED_BY_SAFETY`） | 安全の不変条件の違反を記録したため、監査を中止しました。 |
| `4` | 設定のエラー（`CONFIG_ERROR`） | 設定のファイル、または CLI の引数に誤りがあります。 |
| `4` | Run を始められない（`RUN_UNAVAILABLE`） | Run を始めずに終えました。同じ出力先で別の Run が実行中の場合、途中の Run の版が違う場合、ほかのプロセスが同じ Run を実行している・同じ Run の再開を始めた場合、再開のための保存を読み書きできない場合です。結果のファイルは書き出しません（「[中断と再開](resume.md#中断と再開)」）。 |
| `5` | 中断（`INTERRUPTED`） | 2回目の Ctrl+C（または SIGTERM、SIGHUP）で、すぐに止めました。結果のファイルは書き出していません。再開のための保存は、最後に監査を終えたページまで残っています。同じコマンドを実行すると、続きから再開します。 |

## CLI の表示

`run` は、実行中に、ページの監査が1つ終わるたびに、進み具合を1行で表示します。サイトへの負荷が上限の中に収まっていることを、実行中に数字で確かめるためです（「[サイトへの負荷](site-load.md#サイトへの負荷)」）。

```text
進み具合: 監査を終えたページ 12件（発見したページ 85件、上限 50件）・ページの読み込み 284回・許可 Origin への要求 1,930件（直近1分 38件、1分あたり最大 61件）・許可 Origin の外 12件・経過 24分10秒
```

- 監査を終えたページ: 監査を終えたページの数です。一部未完了と失敗のページも含みます。結果の「監査したページ」（最後まで監査できたページだけの数）とは、別の数です。括弧の中は、これまでに発見したページの数と、ページの数の上限（`crawl.maxPages`）です。再開した Run では、再開の前に監査を終えたページも含みます（Run の全体の数です）。
- ページの読み込み: ページの読み込みの回数です。`run.json` の `load.navigationCount` と同じ数え方で、読み込みを始められなかったものも含みます（「[実績の確かめ方](site-load.md#実績の確かめ方)」）。
- 許可 Origin への要求: 許可 Origin へ、ネットワークに送った要求の件数です。括弧の中は、直近の1分に終わった要求の件数と、1分あたりの最大です。
- 許可 Origin の外: 許可 Origin の外へ、ネットワークに送った要求の件数です。
- 経過: この実行を始めてからの時間です。1時間未満は秒まで、1時間以上は分まで示します（例: `1時間5分`）。再開した Run でも、その起動を始めてからの時間です。
- 再開した Run では、ページの読み込みの回数と、要求の件数も、再開の前の分を含みます（`run.json` の `load` と同じ数え方です）。

途中の Run を再開するときは、開始の行（`監査を始めます。`）の前に、再開の知らせを1行で表示します。監査を終えたページの数は、進み具合の行と同じ書き方で、再開の前に監査を終えたページの数です。ほかの知らせは「[中断と再開](resume.md#中断と再開)」を見てください。

```text
途中の Run（RUN-20261001000000。監査を終えたページ 3件）を、続きから再開します。最初から始めるには --new を付けてください。
監査を始めます。
対象: example
開始の URL: https://example.com/
```

`run` は、最後に次の項目を表示します。

- Run の状態（例: `完了（COMPLETE）`）
- 出力先（Run のディレクトリ）と、HTML レポートと ChatGPT 用のバンドルのパス。バンドルの名前の日時は、最後の実行の終わりの時刻（UTC）です
- ページの網羅（発見、監査、一部未完了、失敗、スキップのページの数）
- サイト品質の指摘の件数（エラー、警告、情報）と、安全の指摘の件数
- サイトへの負荷（ページの読み込みの回数と、許可 Origin への要求の件数と1分あたりの最大。「[サイトへの負荷](site-load.md#サイトへの負荷)」）
- 実行の記録（実行の回数と、再開の回数）。`run.json` の `executions` の件数が実行の回数で、そのうち最初の起動の後の起動が再開です。中断せずに終えた Run でも、`実行: 1回、再開 0回` と表示します（「[中断と再開](resume.md#中断と再開)」）
- この起動の終わり方（ラベルとコード。例: `この起動の終わり方: 実行時間の上限で停止（STOPPED_BY_RUNTIME_LIMIT）`）。コードの意味は「[中断と再開](resume.md#中断と再開)」の終わり方の表を見てください
- サイトが応答しないため止まった場合は、止めたことと、再開のしかた（「[サイトが応答しないとき](site-unavailability.md#サイトが応答しないとき)」）
- 未完了の理由がある場合は、その件数

たとえば、Windows で、出力先が既定の `artifacts` の Run では、結果の最初に次の行を表示します。パスは、出力先を絶対パスにしたものです。

```text
監査の結果
Run の状態: 完了（COMPLETE）
出力先: C:\path\to\BeakSight\artifacts\RUN-20260925010203
HTML レポート: C:\path\to\BeakSight\artifacts\RUN-20260925010203\report.html
ChatGPT 用のバンドル: C:\path\to\BeakSight\artifacts\RUN-20260925010203\beaksight-audit-bundle_20260925023015.zip
```

たとえば、2回中断して、3回目の起動で最後まで終えた Run では、サイトへの負荷の行の次に、次の行を表示します。

```text
実行: 3回、再開 2回
この起動の終わり方: 最後まで実行（COMPLETED）
```

サイトが応答しないため止まった Run では、この起動の終わり方の行の次に、止めたことの1行を表示します。

```text
実行: 1回、再開 0回
この起動の終わり方: サイトの不調で停止（STOPPED_BY_SITE_UNAVAILABLE）
サイトが応答しないため、監査を止めました（desktop:passive:TIMEOUT）。サイトが戻ってから、同じコマンドで続きから再開してください。
```

- この行は、この起動の終わり方（`run.json` の `executions` の最後の `endReason`）が `STOPPED_BY_SITE_UNAVAILABLE` のときだけ表示します。Run の理由では決めません。前の起動がサイトの不調で止まっていても、この起動がほかの終わり方（最後まで終えた場合など）なら、表示しません。
- 括弧の中は、最初に検知した失敗の技術的な詳細で、`run.json` の `incompleteReasons` の `SITE_UNAVAILABLE` の `detail` と同じです。その理由がない場合は、括弧を表示しません。

## Windows PowerShell での日本語の表示

CLI の出力は、UTF-8 の日本語です。

- コンソールに直接表示する場合は、Windows PowerShell 5.1 と cmd.exe のどちらでも読めます。
- Windows PowerShell 5.1 で、出力をパイプやリダイレクトに渡すと、`[Console]::OutputEncoding` が既定（コードページ 932）のままの場合に、文字化けします。パイプやリダイレクトの前に、次のコマンドを実行してください。

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

- BeakSight は、コンソールのコードページを変えません。
- 結果は、UTF-8 の `report.html` と JSON（`run.json`、`audit.json`）で見ることも勧めます。
