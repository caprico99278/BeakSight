# 成果物を外へ渡す前の確かめ（匿名化）

BeakSight の成果物と管理データを、ChatGPT などの外のサービスや、ほかの人に渡す前に、何が入っているかと、何を見て何を伏せるかを確かめる手順です。

[README に戻る](../../README.md)・[仕様の索引](README.md)

## 結論

- **BeakSight は、成果物を外へ自動で送りません。** 渡すのは、人が手で行うときだけです。
- **BeakSight が伏せるのは、秘密（資格情報、Cookie、localStorage、CSRF のトークン、hidden・readonly の欄の値など）と、URL の秘密に見える query の値だけです。** 画面に見えている文、スクリーンショット、人が入れた値、送った値は伏せません。
- **認証つきの監査の成果物には、管理画面の文とスクリーンショットが入ります。** 伏せ字は足していません。渡す前に、人がこの手順で確かめます。
- **書き込みの報告には、人が入れた値と、送った値が入ります。** 報告の先頭とバンドルの目録に、その注意が出ます。
- 確かめられないときは、渡さないでください。

## 成果物ごとの中身

| 成果物 | 入るもの | 伏せてあるもの |
| --- | --- | --- |
| 公開の監査の `run.json`・`audit.json`・`pages/`・`report.html`・ChatGPT 用のバンドル | ページの URL、可視テキスト（`visible-text.txt` と `page.json`）、スクリーンショット、Finding の文言、Evidence（ネットワークの要求の URL など）、実際に使った設定 | URL の利用者名とパスワード。公開の監査では、URL の query の値は伏せません（「[秘密を出さないこと](authenticated-audit.md#秘密を出さないこと)」）。 |
| 認証つきの監査の上と同じファイル | 上に加えて、**管理画面に表示されたデータ**（テスト環境のデータ。可視テキストとスクリーンショット）、ログインの後の画面の URL | Cookie、localStorage、資格情報（保存しません）。秘密に見える名前の query の値（`[REDACTED]`。一覧は「[秘密を出さないこと](authenticated-audit.md#秘密を出さないこと)」）。 |
| `discovery.json`（操作の候補の発見） | ページが書いた値: 送信先の path と query の名前、欄の名前、欄の制約（`pattern` などの文字列）、選択肢の値、ボタンの分類の語 | 入力の値、CSRF のトークン、hidden の値、選択肢の label、ボタンの文言そのもの（「[候補の見方](discovery-and-read-check.md#候補の見方)」）。 |
| `read-evidence.json`（READ の確かめ） | 読んだ URL（送る値が入ります）、HTTP の状態、構造の要約、期待ごとの結果と、詳細の項目の取れた値（画面の文字。人が入れた値でありえます） | URL の秘密に見える名前の query の値。表の全体は写しません。 |
| 書き込みの報告（`action-evidence.json`・`approval-summary.json`・`action-report.html`・書き込みのバンドル）と `action-run.json` | 送った値（合成のテストデータ）、送信先の path、応答の HTTP の状態、登録の ID、**更新の変えた欄の前の値**、**照合の READ で画面から読んだ値**、承認の要約（シナリオの ID、承認の digest、期限、上限、副作用の確認） | 資格情報、Cookie、CSRF のトークン、hidden・readonly の欄の値、保つ欄の値、`lock_version`（読むだけで記録しません）。URL の秘密に見える名前の query の値。 |
| 管理データ（`local-data/`） | プロファイル、認証の設定（URL とパスとセレクタ）、READ の定義の送る値、入力の規則の人が入れた値、発見の根拠の写し（ページが書いた値）、書き込みの結果（送った値、更新の前の値）、承認の記録 | パスワード、token、Cookie（保存しません）。 |
| 資格情報のファイル（`local/secrets/`） | 暗号化したユーザー名とパスワード | 暗号化してあります。外へ渡しません（「[自動ログインの手順](automated-login.md)」）。 |

- **人が入れた値**: 更新の変えた欄の前の値と、照合の READ で画面から読んだ値は、BeakSight が作った値ではありません。BeakSight が登録したテストのレコードでも、登録の後に人やほかの仕組みが編集していれば、その値が入ります。この値があるとき、`action-evidence.json` の `containsHumanEnteredValues` が真になり、`action-report.html` の先頭（「人が入れた値が入りうる報告です」）と、書き込みのバンドルの `manifest.json`（`humanEnteredValuesNotice`）に注意が出ます。
- **送った値**: 入力の規則で作った合成のテストデータです（メールは `example.invalid` の宛先、電話は `090-0` で始まる形）。ただし、入力の規則に人が入れた値の一覧（住所、URL など）を使った欄は、その値がそのまま入ります（「[入力の規則とデータの生成](data-rules.md)」）。
- 伏せ字の一覧に当たらない秘密は、伏せません: URL の fragment（`#` の後）、一覧にない名前の query の値、URL でない文（見えている文、console の文、誤りの文）の中の秘密（「[確かめていないこと](authenticated-audit.md#確かめていないこと)」）。

## 渡す前の手順

1. **渡す先と目的を決めます。** 公開の監査の結果か、テスト環境の結果かで、確かめる量が違います。テスト環境の結果は、渡す先がそのテスト環境のデータを見てよいかを、テスト環境の管理者と確かめます。
2. **渡すファイルを最小にします。** ChatGPT の意味監査には、ChatGPT 用のバンドル（`beaksight-audit-bundle_*.zip`）を使います。Run のディレクトリ全体（`checkpoint/`、`diagnostics/` を含む）や、管理データ、`local/` は渡しません。
3. **ZIP を展開して、中身を見ます。**
   - `manifest.json` の一覧で、入っているファイルを確かめます。
   - 各ページの `page.json` の可視テキストと URL を読みます。認証つきの監査では、管理画面に表示された氏名、メールアドレス、電話番号、住所、社内の識別子などが入っていないかを見ます。
   - スクリーンショット（`pages/<pageId>/.../*.png`）を、1 枚ずつ開いて見ます。
   - 書き込みのバンドルは、`manifest.json` の注意と、`action-evidence.json` の送った値・更新の前の値・照合の READ の取れた値を見ます。
4. **伏せる必要があるときは、BeakSight の外で行います。** BeakSight には、成果物の文やスクリーンショットを伏せる機能はありません。伏せた写しを別の場所に作り、元の Run のディレクトリは編集しません（Run のディレクトリのファイルを編集すると、再開や画面の報告の配布に影響します）。伏せた写しでは、ZIP の `manifest.json` の SHA-256 が中身と合わなくなります。
5. **伏せきれないときは、渡しません。** スクリーンショットの全体に個人の情報が写る、などのときです。
6. **渡した記録を残します。** 何を、いつ、どこへ渡したかを、Git の管理の外に記録します。

## ChatGPT などに渡すときの注意

- 渡すのは、人が手でアップロードするときだけです。BeakSight は、外のサービスへ成果物を送りません。
- 本来の監査対象のサイトの名前、URL、顧客の名前を、Git に載るファイルや、共有する文書に書かないでください。設定のファイルは `local/` に置きます（「[`config/targets/` と `local/` の使い分け](configuration.md#configtargets-と-local-の使い分け)」）。
- 渡す先のサービスの、データの保存と学習への利用の設定を確かめてください（BeakSight からは確かめられません）。
- テスト環境の成果物（認証つきの監査、発見、READ、書き込み）は、テスト環境のデータと同じに扱います。本番の個人データがテスト環境に入っていないことを、テスト環境の管理者と確かめてから監査してください。
- 管理データ（`local-data/`）と資格情報のファイル（`local/secrets/`）は、渡しません。

## 確かめていないこと

- 認証つきの監査の成果物の、文とスクリーンショットの伏せ字（作っていません。ユーザーの判断で、この手順で扱います）。
- 渡した先での扱い（保存、学習への利用、ほかの人への公開）。
- 人が入れた値の一覧に、秘密に見えない名前の欄で秘密を入れた場合の扱い（入れた値のまま残ります）。
