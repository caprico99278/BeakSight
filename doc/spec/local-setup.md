# 管理データの準備（環境の準備と初期化）

ローカルの管理画面が使う管理データ（SQLite）を、何もない状態から準備する手順と、うまくいかないときの対処です。

[README に戻る](../../README.md)・[仕様の索引](README.md)

> CLI の監査（`run`、`validate-config`）は、管理データを使いません。管理データがなくても動きます。管理データは、管理画面（「[管理画面（ローカル）](local-ui.md)」）が使います。

## はじめに知っておくこと

- **SQLite を別に入れる必要はありません。** BeakSight は、Node.js に組み込まれている SQLite（`node:sqlite`）を使います。SQLite のプログラムやライブラリを、別に入れるものはありません。
- **Node.js 24.15.0 以上が必須です。** Node.js 24 の最新の版を勧めます（24.15.0 より後の版に、SQLite の安全の修正があります）。Node.js の更新は利用者の環境の変更なので、BeakSight は強制しません。
- 管理データは、リポジトリの直下の `local-data/beaksight-control.sqlite` に置きます。場所は変えられません（場所を変える引数や環境変数はありません）。
- `local-data/` は Git の管理の外です（`.gitignore` の `/local-data/`）。コミットされません。

## 手順

上から順に行います。2 回目以降に同じ手順を行っても、何も壊れません。

### 1. Node.js を入れる

Node.js 24 の最新の版（24.15.0 以上）を入れます。入れた後、版を確かめます。

```powershell
node -v
```

`v24.15.0` 以上が表示されれば十分です。SQLite は Node.js に組み込まれているので、ほかに入れるものはありません。

### 2. 依存のパッケージを入れる

リポジトリの直下で、固定した版のまま、install の script を動かさずに入れます。

```powershell
npm ci --ignore-scripts
```

### 3. Chromium を入れる（監査に使う場合だけ）

監査（`run`）には Chromium が要ります。管理画面だけを使う場合は、要りません。

```powershell
npx playwright install chromium
```

### 4. 管理データを準備する

```powershell
npm run setup:local
```

ビルドしてから、次のことを行います。

1. 環境を確かめます（Node.js の版、組み込みの SQLite が使えるか）。足りなければ、何も作らずに止めます。
2. `local-data/` がなければ作ります。
3. 管理データのファイルがなければ作り、あれば開いて、BeakSight の管理データかと版を確かめます。
4. 版が古ければ、最新に上げます。
5. ファイルが壊れていないかを確かめます（`quick_check`）。
6. 結果を表示します。

成功すると、次のように表示し、終了コード 0 で終えます（場所、版、SQLite の版、プロファイルの件数は、環境によって違います）。

```text
管理データの準備ができました。
管理データの場所: C:\...\BeakSight\local-data\beaksight-control.sqlite
結果: 新しく作りました（版 1）。
SQLite の版: 3.x.x
プロファイル: 有効 0件、取り消し 0件
整合性の確かめ（quick_check）: 問題はありません（ok）
画面は npm run ui で起動します（doc/spec/local-ui.md）。
```

既に準備してあれば、`結果: 既にありました（版 1）。何も変えていません。` と表示します。古い版の管理データなら、版を上げて `既にありました。版 N から版 M に上げました。` と表示します。

止めた場合は、理由、取るべき手順、詳細を表示し、終了コード 1 で終えます（下の「[困ったとき](#困ったとき)」）。

### 5. 画面を起動する

```powershell
npm run ui
```

コンソールに出た URL をブラウザで開きます。画面と操作、守りの範囲は「[管理画面（ローカル）](local-ui.md)」にあります。画面の起動も、はじめに同じ準備を行うので、`npm run setup:local` を忘れても、正しく準備してから起動します。

## 困ったとき

`npm run setup:local` が止めたときに表示する文（理由）と、取るべき手順です。BeakSight は、利用者のファイルを消したり、上書きしたり、移したりしません。

| 理由のコード | 表示される文 | 取るべき手順 |
| --- | --- | --- |
| `NODE_VERSION_UNSUPPORTED` | Node.js の版が古く、管理データ（SQLite）の機能を使えません。 | Node.js 24 の最新の版（24.15.0 以上）を入れてから、もう一度実行してください。版は node -v で確かめられます。 |
| `NODE_SQLITE_UNAVAILABLE` | この Node.js では、組み込みの SQLite（node:sqlite）を使えません。 | SQLite は Node.js に組み込まれているので、別に入れるものはありません。SQLite を止める指定（--no-experimental-sqlite。環境変数 NODE_OPTIONS の中を含む）があれば外し、それでも使えなければ Node.js 24 の最新の版を公式の配布から入れ直してください。 |
| `DATA_DIRECTORY_NOT_DIRECTORY` | 管理データを置くフォルダ（local-data）の位置に、フォルダではないファイルがあります。 | そのファイルを別の名前に変えるか、別の場所へ移してから、もう一度実行してください。BeakSight は、このファイルを消したり、上書きしたり、移したりしません。 |
| `DATA_DIRECTORY_NOT_WRITABLE` | 管理データを置くフォルダを作れないか、そのフォルダに書き込めません。 | フォルダの書き込みの権限を確かめてください。リポジトリは、ローカルのディスクに置いてください（ネットワークのドライブや同期のフォルダでの動作は確かめていません）。 |
| `NOT_A_SQLITE_FILE` | 管理データのファイルの位置に、SQLite ではないファイル（またはフォルダ）があります。 | そのファイルを別の名前に変えるか、別の場所へ移してから、もう一度 npm run setup:local を実行してください。新しい管理データが作られます。BeakSight は、このファイルを消したり、上書きしたり、移したりしません。 |
| `NOT_A_BEAKSIGHT_DATABASE` | SQLite のファイルですが、BeakSight の管理データではありません。 | そのファイルを別の名前に変えるか、別の場所へ移してから、もう一度 npm run setup:local を実行してください。新しい管理データが作られます。BeakSight は、このファイルを消したり、上書きしたり、移したりしません。 |
| `DATABASE_FROM_NEWER_VERSION` | この管理データは、今より新しい版の BeakSight で作られています。この版では読み書きしません。 | 新しい版の BeakSight を使ってください。BeakSight は、このファイルを消したり、上書きしたり、移したりしません。 |
| `DATABASE_LOCKED` | 別のプログラムが、管理データのファイルを開いているか、書き込んでいます。 | 画面のサーバ（npm run ui）や、ほかにこのファイルを開いているプログラムを閉じてから、もう一度実行してください。 |
| `DATABASE_READ_ONLY` | 管理データのファイルが読み取り専用で、書き込めません。 | ファイルの読み取り専用の設定と、書き込みの権限を確かめてから、もう一度実行してください。 |
| `DATABASE_WAL_UNAVAILABLE` | 管理データのファイルを、必要な書き込みの方式（WAL）にできません。ネットワークのドライブなどに置かれている可能性があります。 | リポジトリをローカルのディスクに置いてから、もう一度実行してください。 |
| `DATABASE_INTEGRITY_FAILED` | 管理データのファイルが壊れています。 | そのファイルを別の名前に変えるか、別の場所へ移してから、もう一度 npm run setup:local を実行してください。新しい管理データが作られます。前のデータは、名前を変えたファイルに残ります。BeakSight は、このファイルを消したり、上書きしたり、移したりしません。 |
| `MIGRATION_FAILED` | 管理データの版を上げる処理が失敗しました。途中の変更は元に戻してあります。 | もう一度実行してください。繰り返し失敗する場合は、表示された詳細を開発者に伝えてください。 |
| `DATABASE_OPEN_FAILED` | 管理データのファイルを開けませんでした。 | ほかのプログラムがファイルを開いていないか、ファイルの権限を確かめてから、もう一度実行してください。表示された詳細も確かめてください。 |

## 管理データの扱い

- **ローカルのディスクに置いてください。** ネットワークのドライブや、同期のフォルダ（クラウドのストレージと同期するフォルダ）での動作は、確かめていません。
- **消す機能や作り直す機能はありません。** BeakSight は、管理データを消したり、作り直したりしません。新しく作り直したい場合は、手で `local-data/beaksight-control.sqlite` を別の名前に変えるか、別の場所へ移してから、`npm run setup:local` を実行してください。新しい管理データが作られます。前のデータは、名前を変えたファイルに残ります。
- 管理データのファイルと同じフォルダに、SQLite の作業用のファイル（`-wal`、`-shm` で終わるもの）ができることがあります。管理データのファイルと一緒に扱ってください。
- 秘密（パスワード、token、cookie）は、管理データに保存しません。

## 守りの範囲の外（受け入れる危険）

- 同じ PC で動くほかのプログラムは、`local-data/` の中のファイルを直接読めます。BeakSight の守り（画面のサーバの Host の確かめ、合言葉、CSRF の確かめ）は、画面のサーバへの要求を守るもので、ファイルの直接の読み書きは守りの範囲の外です。
- 画面のサーバの合言葉の cookie は、同じ PC の 127.0.0.1 のほかの port で動くサーバにも送られます（cookie は port で分かれないため）。管理画面を使うあいだ、信頼できないローカルのサーバを動かさないでください。
