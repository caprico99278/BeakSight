# スクリプトで送るログインの観察の手順（開発者ツール）

利用者が、普段のブラウザの開発者ツールで、テスト環境のログインと管理画面の振る舞いを観察し、その「形」だけを記録する手順です。
この観察では、BeakSight を使いません。記録は、スクリプトで送るログインに対応する設計の材料にします。

[README に戻る](../../README.md)・[仕様の索引](README.md)

## 決まり

- **形だけを記録します。** ドメイン、URL の値、token、Cookie の値、メールアドレス、パスワード、画面に出たデータは書きません。「同じホスト・別のホスト」「鍵の名前の形」「JSON か」のように書きます。
- **名前を書きません。** 本来の監査対象のサイトの名前、ドメイン、URL、プラットフォームの名前、外部の認証のサービスの名前は、記録にも書きません。「外部の認証のサービス」と書きます。
- **記録は Git の管理の外に置きます。** 例: `local/` の下のファイル。設計者に伝えるときも、形だけを伝えます。
- **負荷をかけません。** 画面の開き直し（再読み込み）を繰り返さない、ログインを繰り返さない、ほかの画面を次々に開かない。1 つの観察で、ログインは 1 回にします。ログインに失敗したら、繰り返さずに、そこで止めます（アカウントのロックを避けるため）。
- **登録・更新・削除を押しません。** 例外は O7 で利用者が判断したときだけです（下の O7）。
- テスト環境の、テスト用のアカウントだけを使います。

## 準備

1. 普段のブラウザで、テスト環境のログインの画面を開きます（まだログインしません）。
2. 開発者ツールを開き、「ネットワーク」タブを選びます。
3. 「ログを保持」（Preserve log）にチェックを入れます。ページが移っても、記録が消えないようにするためです。
4. 記録の表（下の「記録の形」）を、Git の管理の外のファイルに用意します。

- 開発者ツールの表示の名前（タブ、絞り込み、欄）は、ブラウザの種類と版、表示の言語で違うことがあります。ここでは、日本語の表示の Chromium 系のブラウザの名前で書きます。
- 「ヘッダー」の欄では、ヘッダの名前だけを見ます。値（`Authorization` の値、Cookie の値など）は書き写しません。
- 「ペイロード」の欄では、鍵の名前だけを見ます。値は書き写しません。

## 観察すること

### O1. ログインの送信

1. 絞り込みを「Fetch/XHR」と「Doc」にして、ログインします。
2. ログインを押した直後の `POST`（か、ほかの method）の行を選び、次を見ます。
   - 行の「種類」: `fetch`・`xhr`（画面の中のスクリプトで送る）か、`document`（フォームの送信）か。
   - 「ヘッダー」の「リクエスト URL」: 送り先のホストが、ログインの画面と同じホストか、別のホストか。path の形（区切りの数、`token` のような語を含むか）と、query の名前（値は書かない）。
   - 「ヘッダー」の「リクエスト メソッド」。
   - 「ヘッダー」の「リクエスト ヘッダー」: ヘッダの名前の一覧（`Content-Type`、`Authorization`、独自の名前のヘッダなど）。値は書かない。`Content-Type` だけは、形（`application/json` か `application/x-www-form-urlencoded` か）を書いてかまいません。
   - 「ペイロード」: 本文の形式（JSON か、フォームの形か）と、鍵の名前の一覧。値は書かない。
3. ログインの後に、同じ流れで出た要求（ログインの直後の GET など）があれば、O4 で記録します。

### O2. 事前確認（OPTIONS）

1. O1 と同じ記録で、絞り込みを「すべて」にします。
2. ログインの送信の直前に、同じ送り先への method `OPTIONS` の行があるかを見ます（「種類」が `preflight` と出ることがあります）。
3. あれば、その「レスポンス ヘッダー」の名前のうち、`Access-Control-` で始まるものの名前を書きます（値は書かない）。

### O3. ログインの後のローカル ストレージと Cookie

1. ログインが済んだら、「アプリケーション」タブを開きます。
2. 「ローカル ストレージ」の下の、管理画面のホストの項目を選びます。鍵（キー）の名前の形を書きます（例: 「接頭辞 + `-auth-token` のような形」）。値は見ても書きません。値が JSON に見えるかどうか（`{` で始まるか）だけは書いてかまいません。
3. 「Cookie」の下の、管理画面のホストの項目を選びます。Cookie の名前の形と数を書きます。値は書きません。
4. 「セッション ストレージ」にも同じ形の鍵があるかを見ます（あるか、ないかだけ）。

### O4. 管理画面のデータの読み方

1. 「ネットワーク」タブの記録を消し（「ログを保持」はそのまま）、絞り込みを「Fetch/XHR」にします。
2. 管理画面の一覧の画面を 1 つだけ開きます（開き直しを繰り返しません）。
3. 出た要求の行ごとに、次を見ます。
   - 送り先が、管理画面と同じホストか、別のホストか。
   - method（`GET` か `POST` か）と、path の形（`rest`・`rpc` のような語を含むか、区切りの数）。query の名前（値は書かない）。
   - `POST` なら、読み取り（データを取るだけ）の呼び出しに見えるか（path に `rpc` を含む、など）。
   - 「リクエスト ヘッダー」の名前（O1 と同じく、値は書かない）。
4. その画面を開いたときの、API への要求の数を数えます。

### O5. token の更新

1. ログインした管理画面を開いたまま、何もせずに待ちます（画面を開き直しません）。
2. 絞り込みを「Fetch/XHR」にして、何分ほどで、ログインの送り先と同じ形の `POST` が出るかを見ます（「ペイロード」の鍵に `grant_type` があり、その値が `refresh_token` のように更新を示すもの。値は書かない）。
3. 待った時間（分）と、出たか・出なかったかを書きます。待つのは、決めた時間（例: 30 分）までにします。

### O6. WebSocket

1. 絞り込みを「WS」にします。
2. 管理画面を開いている間に、WebSocket の接続の行があるかを見ます。
3. あれば、送り先が同じホストか、別のホストかと、path の形を書きます。「メッセージ」の中身は書きません。

### O7. 登録と更新の送り方

**まず、画面の構造だけを見ます。押しません。**

1. 登録の画面と、更新の画面（テスト用のデータの 1 件）を開きます。
2. フォームの欄の名前（ラベルではなく、開発者ツールの「要素」タブで見える `name` の形）と、送信のボタンがあるかを見ます。`<form>` があるか、ボタンだけか、を書きます。

**実際に押して観察するかは、利用者が判断します。** 押すと、テスト環境のデータが変わります。

- 押すときは、テスト用のデータだけで、登録 1 件・更新 1 件までにとどめます。削除はしません。
- 押したときは、O1 と同じく、送信の行の「種類」、送り先のホスト（同じか別か）、method、path の形、本文の形式と鍵の名前を書きます（値は書かない）。
- 登録したデータと更新したデータは、テスト環境の管理者に伝えます（片付けは BeakSight では行いません）。

### O8. ログアウト

1. 画面のログアウトの操作の場所と、そのときに開く画面の path の形を見ます。
2. ログアウトの後に、O3 のローカル ストレージの鍵が消えるか、残るかを見ます。
3. ログアウトのときに、送り先への要求（`POST` など）が出るか、ローカル ストレージを消すだけかを書きます。

ログアウトは、観察の最後に 1 回だけ行います。

## 記録の形

次の表を、Git の管理の外のファイルに書きます。値を書く欄はありません。

| 番号 | 見たこと | 記録 |
| --- | --- | --- |
| O1 | ログインの送信の種類 | `fetch`・`xhr`・`document` のどれか |
| O1 | 送り先 | ログインの画面と同じホスト・別のホスト |
| O1 | method と path の形 | 例: `POST`、区切り 3 つ、`token` の語を含む |
| O1 | query の名前 | 名前だけ（例: `grant_type`） |
| O1 | 本文の形式と鍵の名前 | 例: JSON、鍵は `email`・`password` の形（値は書かない） |
| O1 | 要求のヘッダの名前 | 名前だけ（例: `Content-Type`、`Authorization`、独自の名前のヘッダが 1 つ） |
| O2 | 事前確認（`OPTIONS`） | ある・ない。ある場合は `Access-Control-` のヘッダの名前 |
| O3 | ローカル ストレージの鍵 | 鍵の名前の形と数。値が JSON に見えるか |
| O3 | Cookie | 名前の形と数 |
| O3 | セッション ストレージ | ある・ない |
| O4 | 管理画面のデータの読み方 | 同じホスト・別のホスト、`GET`・`POST`、path の形、読み取りの `POST` に見えるか |
| O4 | 1 画面の要求の数 | 数 |
| O5 | token の更新 | 出た・出なかった、待った分数 |
| O6 | WebSocket | ある・ない。ある場合は同じホスト・別のホストと path の形 |
| O7 | 登録と更新の画面の構造 | `<form>` があるか、欄の `name` の形、送信のボタン |
| O7 | 押して観察したか | した（登録 1 件・更新 1 件まで）・しなかった。した場合は O1 と同じ項目 |
| O8 | ログアウト | 画面の path の形、要求が出るか、ローカル ストレージの鍵が消えるか |

- 見られなかった項目は、「見られなかった」と理由を書きます。推し量って埋めません。
- 設計者に伝えるときも、この表の形だけを伝えます。スクリーンショットや、開発者ツールから書き出した記録（HAR など）は渡しません（値と URL が入るため）。
