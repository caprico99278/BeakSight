# 導入（最初の監査まで）

BeakSight を何もない状態から使い始め、最初の公開の監査を終えるまでの手順です。
3 つのモードを通して使う順は「[通しの使い方](end-to-end-usage.md)」にあります。

[README に戻る](../../README.md)・[仕様の索引](README.md)

## 必要なもの

| もの | 内容 |
| --- | --- |
| Node.js | 24.22.1 以上の 24 系（`package.json` の `engines` は `>=24.22.1 <25`）。24.22.1 は、Node.js の 2026-10-21 のセキュリティリリースの修正版です。SQLite は Node.js に組み込まれているので、別に入れません（「[管理データの準備](local-setup.md)」）。 |
| 依存のパッケージ | リポジトリの `package-lock.json` の版のまま入れます。 |
| Playwright の Chromium | 監査に使います。Chromium だけを使います。 |
| Windows | BeakSight が Windows を求めるのは、自動ログイン（`AUTOMATED_LOGIN`）だけです。資格情報を Windows の暗号化（DPAPI）で保存するためです（「[自動ログインの手順](automated-login.md)」）。 |
| ローカルのディスク | 管理データ（`local-data/`）は、ローカルのディスクに置きます。ネットワークのドライブや同期のフォルダでの動作は確かめていません。 |

- Windows 以外の OS で、管理画面と、認証つきの監査と書き込みを通して動かすことは、確かめていません。

## 初期設定

リポジトリの直下で、上から順に行います。

```powershell
node -v
npm ci --ignore-scripts
npx playwright install chromium
npm run build
```

- `node -v` が `v24.22.1` 以上であることを確かめます。
- `npm ci --ignore-scripts` は、固定した版のまま、install の script を動かさずに依存を入れます。
- `npx playwright install chromium` は、監査に使う Chromium を入れます。BeakSight は headless でも、この通常の Chromium を使います（「[headless で使うブラウザ](cli.md#headless-で使うブラウザ)」）。
- `npm run build` は、CLI と監査のワーカー（`dist/`）をビルドします。

管理画面を使うときは、続けて管理データを準備します。

```powershell
npm run setup:local
```

- 成功すると「管理データの準備ができました。」と表示し、終了コード 0 で終えます。止まったときの理由と手順は「[困ったとき](local-setup.md#困ったとき)」にあります。
- `npm run ui` も起動の初めに同じ準備を行うので、`setup:local` を省いても、正しく準備してから起動します。

## 最初の監査（CLI）

CLI は、公開の監査（`PUBLIC_PASSIVE`）だけを行います。

1. 監査の対象の設定のファイルを作ります。顧客を特定できる実際の設定は、Git の管理の外の `local/targets/<対象名>.json` に置きます（「[`config/targets/` と `local/` の使い分け](configuration.md#configtargets-と-local-の使い分け)」）。書き方は「[監査の対象の設定](configuration.md)」にあります。
2. サイトへの負荷を決めます。読み込みの間隔（`crawl.minNavigationIntervalMs`。既定 5 秒）と、ページの上限（`crawl.maxPages`。既定 500）を、サイトの運営者と決めた値にします（「[サイトへの負荷](site-load.md)」）。最初は、ページの上限を小さくして始めることを勧めます。
3. 設定を確かめます。監査は行わず、ブラウザも起動しません。

   ```powershell
   node dist/cli/index.js validate-config --config local/targets/<対象名>.json
   ```

4. 監査します（headless を勧めます）。

   ```powershell
   node dist/cli/index.js run --config local/targets/<対象名>.json --headless --output artifacts
   ```

5. 結果を見ます。出力先の `RUN-YYYYMMDDHHmmss` のディレクトリの `report.html` をブラウザで開きます（「[出力と結果の読み方](output.md)」）。終了コードの意味は「[終了コード](cli.md#終了コード)」にあります。

- Ctrl+C を 1 回押すと、今のページの監査を終えてから止まります。同じコマンドを実行すると、続きから再開します（「[中断と再開](resume.md)」）。

## 最初の監査（管理画面）

画面の言葉は、この文書の言葉と違うところがあります（例: 監査は「点検」、プロファイルは「点検するサイト」、ジョブは「作業」）。対応は「[画面の語と文書の語](local-ui.md#画面の語と文書の語)」にあります。どの画面も、上から要点（今の様子）、次に押す主のボタン 1 つ、たたんだ「詳しい内容」1 つの形です。直すための欄と、調べるための情報は「詳しい内容」の中にあり、開かなくても流れは進みます。

1. 画面を起動します。

   ```powershell
   npm run ui
   ```

2. コンソールに出た `http://127.0.0.1:4317/?token=…` の URL をブラウザで開きます。URL の `token` は起動ごとの合言葉なので、ほかの人に渡しません（「[画面の起動](local-ui.md#画面の起動)」）。
3. 左のメニューの「サイトを足す」で、公開の監査のプロファイルを作ります。対象の設定のファイルは、前もって作らなくてかまいません。次の 3 つだけを行います（「[管理画面でのプロファイルの作り方](profiles.md#管理画面でのプロファイルの作り方)」）。

   | 入れる・選ぶ・押すもの | 内容 |
   | --- | --- |
   | 開始のアドレス | 監査を始める画面の URL。 |
   | 使い方 | 「ログインしなくても見られるサイト」（環境は公開（本番）（`PUBLIC`）、監査モードは公開の監査（読むだけ）（`PUBLIC_PASSIVE`）、認証の方式はログインしない（`NONE`）になります）。 |
   | 点検を始める | 押すと保存して、サイトの下調べ（入口の確かめ。ログインしないで開始の URL を 1 回 `GET`）をしてから、続けて監査を始めます。ボタンの下に「押すと、サイトを下調べしてから点検を始めます。」が出ます。 |

   名前（profileId）は、開始の URL のホスト名から決めます（同じ名前があれば `-2` などを付けます。保存した後は変えられません）。設定のファイルは、同じ開始の URL のファイルが `config/targets/` か `local/targets/` に 1 つあればそれを使い、同じサイトのファイルがなければ `local/targets/<名前>.json` を作ります。同じサイトのファイルが複数ある、別の開始の URL のものだけ、などで決められないときだけ、保存せずに止め、拒否の知らせの中で、使うファイルか「開始のアドレスから新しく作る」を選ばせます。許可 Origin は、開始の URL の Origin 1 つです（作成の画面には、名前・設定のファイル・許可 Origin の欄はありません。作った後に、プロファイルの詳細の「詳しい内容」のサイトの設定で直せます）。

4. サイトの下調べの作業の画面から、続けて始めた監査の作業の画面へ自動で移ります（監査を続けて始めなかったときは、プロファイルの詳細へ移り、要点に理由が出ます）。2 回目からは、プロファイルの詳細の主のボタン「点検を始める」で開始の画面を開き、開始の画面の主のボタン「点検を始める」を押します。設定の要点（開始の URL、ページの上限、時間の上限、ページの読み込みの間隔）は、開始の画面の「詳しい内容」にあります（開始の画面では変えられません）。
5. 監査のジョブの画面（画面では「作業の様子」）で、進み具合を見ます（「読んだページ 3 / 20。長くても あと 約 3 分」の形）。この画面は自動で新しくなり、閉じても監査は続きます。監査が終わると（一部のページを見られなかったときも）、プロファイルの詳細へ自動で移り、要点の 1 行目に「点検が終わりました。…」の結果が出ます。失敗した、「点検を止める」で止めた、などのときは、ジョブの画面に残り、理由と次にすることを出します。
6. 結果は、移ったプロファイルの詳細の主のボタン「結果を見る」で HTML レポートを開きます（後から見るときは、サイトの一覧の「前回の点検」の「詳細」か、左のメニューの「作業の履歴」からジョブの画面を開き、主のボタン「結果を見る」を押します）。レポートの冒頭は「まとめ」の段（何を見たか、問題の数、大事な問題、見られなかったところ）、技術の記録は末尾の記録の段です（「[HTML レポート](output.md#html-レポート)」）。`run.json`・`audit.json`・ChatGPT 用のバンドルは、ジョブの画面の「詳しい内容」から落とせます（「[監査の実行](local-ui.md#監査の実行)」）。

- 開始の URL から作った設定のファイルは、最初の監査のための控えめな負荷（ページの上限 3、読み込みの間隔 10 秒）で作ります。ほかの負荷の項目は既定の値です。ページの上限・時間の上限・読み込みの間隔は、プロファイルの詳細の「詳しい内容」の「点検の負荷」で変えられます（`local/targets/<名前>.json` のときだけ。ほかの値は設定のファイルを直します）。読む範囲を広げるときは、サイトの運営者と決めた値にします（「[サイトへの負荷](site-load.md)」）。
- 保存した後は、プロファイルの詳細の要点と主のボタンをたどれば、残りの手順を進められます。
- 監査は、画面全体で同時に 1 つだけです。
