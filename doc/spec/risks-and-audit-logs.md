# リスクと監査の記録

承認の履歴、書き込みの履歴、監査済みデータの台帳の読み方と、利用者に関わる未解決の不具合と受け入れた限界、安全の保証の範囲と確かめていないことです。

[README に戻る](../../README.md)・[仕様の索引](README.md)

## 記録の置き場所

| 記録 | 場所 | 中身 |
| --- | --- | --- |
| 監査の Safety Ledger | `run.json` の `safety`、各ページの `page.json` | Guard が止めた操作と、安全の不変条件の違反（「[Safety Ledger の読み方](safety.md#safety-ledger-の読み方)」）。 |
| サイトへの負荷の記録 | `run.json` の `load` | ページの読み込みの回数、許可 Origin への要求の数など（「[実績の確かめ方](site-load.md#実績の確かめ方)」）。 |
| 実行履歴 | 管理画面の「実行履歴」 | 画面から始めたジョブの一覧（種類、状態、Run、終わり方）。CLI で始めた Run は入りません。 |
| 承認の履歴 | シナリオの詳細（管理データの `approval_receipts`・`scenario_revisions`） | 承認と撤回の記録、版の写し（下の「承認の履歴の読み方」）。 |
| 書き込みの履歴 | シナリオの詳細の「書き込みの履歴」、ジョブの画面の「書き込みの結果」 | 書き込みの 1 回ごとの結果（下の「書き込みの履歴の読み方」）。 |
| 書き込みの報告 | Run のディレクトリの `action-evidence.json`・`approval-summary.json`・`action-report.html`・書き込みのバンドル | その回の証拠と、始めた時点の承認の要約（「[書き込みの報告](output.md#書き込みの報告)」）。 |
| 監査済みデータの台帳 | 管理画面の「監査済みデータの台帳」 | BeakSight が登録したかもしれないデータの一覧（下の「監査済みデータの台帳の読み方」）。画面だけで、ファイルへの書き出しはありません。 |

- 承認と撤回の記録、シナリオの版の写し、入力の規則の版の写しは、追記だけです。BeakSight のコードは書き換えも削除もしません（自動の検査で確かめます）。ただし、管理データのファイル（`local-data/`）を別の道具で書き換えると、記録を変えられます（「[守りの範囲](scenario-approval.md#守りの範囲)」）。
- 承認者は、固定の値 `LOCAL_OPERATOR` です。人の名前や OS の利用者名は記録しません。誰が承認したかは、このコンピュータの利用者の運用で管理します。

## 承認の履歴の読み方

シナリオの詳細（「シナリオ」の一覧の「開く」）に、次の節があります。

| 節 | 読み方 |
| --- | --- |
| 承認の状態 | 下書き・承認済み・要再承認・期限切れ・撤回済み。要再承認なら「再承認が要る理由」に当たった理由をすべて出します（「[再承認が要る場合](scenario-approval.md#再承認が要る場合)」）。 |
| 承認と撤回の履歴 | 1 件ずつ、種類（承認か撤回か）、日時、承認した版、期限、内容。同じシナリオを何度承認しても、記録は増えるだけです。 |
| 版の履歴 | 版ごとに、記録した日時、送る欄、上限、承認の期限の日数。シナリオを変えるたびに版が 1 つ進みます。 |
| 最後の承認との差分 | 最後の承認から変わった項目ごとに「前の値 → 今の値」と説明。承認の前に読みます。 |
| 書き込みの履歴 | 下の「書き込みの履歴の読み方」。 |

- 書き込みの 1 回が、どの承認の下で行われたかは、その回の `approval-summary.json`（承認の記録の ID、承認の digest、承認した日時と期限、始めた時点で撤回されていたか、実行の許可と予約の時刻）で確かめます。値は、書き込みを始めた時点のものです。
- `approval-summary.json` の「人が決めたこと」（シナリオの承認、入力の規則、上限、副作用の確認、更新の欄の役割）と「BeakSight が自動で行ったこと」（値の生成、更新の対象のレコードの選択、送信、結果の判定、照合の READ）で、人の判断と自動の処理の境を確かめます。

## 書き込みの履歴の読み方

| 項目 | 読み方 |
| --- | --- |
| 結果 | 照合済み（`VERIFIED`）、照合できていない（`PARTIAL`）、結果が分からない（`UNKNOWN`）、登録されなかった（`FAILED`）、送らずに止めた（`BLOCKED`）。照合済みのほかは、完了と扱いません（「[結果の種類と意味](approved-create.md#結果の種類と意味)」）。 |
| 送信 | 送った・送っていない・送ったか分からない。送ったか分からない回は、テスト環境に登録や更新がされたかもしれません。 |
| 予約の締め | 送って応答を受けた（`COMMITTED`）、送ったか分からない（`UNKNOWN`）、送らずに止めて返した（`RELEASED`）。累積の上限の数え方に使います。 |
| 報告 | 報告を開くリンク、または「配らない」（「[報告を配らない場合](output.md#報告を配らない場合)」）。 |

- `UNKNOWN` の回は、BeakSight は自動で確かめ直さず、送り直しもしません。テスト環境で、レコードの有無と中身を人が確かめます（「[UNKNOWN の後にすること](approved-create.md#unknown-の後にすること)」）。
- ワーカーが途中で異常終了した回は、報告がなく、画面の結果だけが残ります。

## 監査済みデータの台帳の読み方

台帳（プロファイルの詳細の「監査済みデータの台帳を開く」）は、BeakSight がテスト環境に作ったかもしれないデータを、片付けのために一覧にしたものです。

| 列 | 読み方 |
| --- | --- |
| 登録の ID | 成功の後に取れた登録の ID。取れなかった回は「取れていない」（テスト環境で、送った値から探します）。 |
| シナリオと版 | どのシナリオのどの版で登録したか。 |
| seed の記録 | 実行の許可の ID と、入力の規則の digest。送った値を作った元です。 |
| ジョブと Run | ジョブの画面と、Run のディレクトリへの手がかり。 |
| 照合の状態 | 送信の状態、結果、照合の READ の結果。 |
| この ID への UPDATE | その登録の ID を対象にした更新の回数と、最後の結果。送らずに止めた回は数えません（送ったか分からない回は数えます）。 |
| 件数（シナリオごと） | 累計の件数と上限。実行の許可の判定と同じ数え方で、送ったか分からない回を含みます。 |

- 送らずに止めた回は、台帳に入りません。送ったか分からない回（登録したかもしれない回）は入ります。
- **BeakSight は、登録したデータを削除も復元もしません。** 片付けは、台帳をもとに、テスト環境の管理者が行います。片付けたことは、台帳には記録されません（台帳は BeakSight の記録だけを示します）。

## 利用者に関わる未解決の不具合と受け入れた限界

開発の記録に残した不具合のうち、利用者の結果や運用に関わるものです。どれも、サイトへの書き込みや秘密の漏れの向きではなく、止める側か、結果の質の問題です（下の「安全の保証の範囲」）。

### 監査が止まる・一部未完了になる

- **Guard の上限と競合による停止**: 1 つのページで 64 件を超える iframe を同時に読み込む、別のプロセスの iframe（OOPIF）が 64 を超える、横取りの処理の途中で frame が消える（広告の iframe の入れ替えなど）、などで、Guard が安全の側に倒して違反を記録し、Run が `ABORTED_BY_SAFETY` になることがあります。iframe の `src` を 1 ms ごとに変えるページでも起きることがあります。
- **連続する移動の取り消し**: main frame が 0〜5 ms の間隔で `location.replace` を続けるページでは、違反（`HTTP_MAIN_FRAME_DELIVERY_FAILED`）で止まります。要求はサーバに届いていません。
- **一時停止中に消える iframe**: 別のプロセスの iframe の文書を一時停止している間に、その iframe が消されると、違反で止まることがあります。
- **書き込みの段の再送信**: ページの JS が送信の約 30 ms 後にもう一度送ると、違反で `ABORTED_BY_SAFETY` になることがあります。届く POST は 1 件です。
- **混雑の下の閉じる処理**: PC が強く混んでいると、ブラウザを閉じる処理が期限に間に合わず、Run が `PARTIAL` になることがあります。
- **古いロックの取り直し**: 混雑の下で、古い Run のロックの取り直しが間に合わず、どの起動も再開しないことがあります（同じ Run を 2 つ同時に再開することはありません）。同じ出力先で 3 つ以上の監査をほぼ同時に始めると、2 つが同時に開始のロックを持つことがあります。
- **高い頻度のポーリング**: 2 つの Origin へ高い頻度でポーリングするページは、出口の中継の負荷で遅くなり、`PARTIAL` になることがあります（「[中継を通さない場合との既知の違い](safety.md#中継を通さない場合との既知の違い)」）。

### 監査の結果の質

- **雑音の Finding**: 本文が HTML でない 404 のページに、文書の構造の Finding（title や lang がない、など）が出ます。広告の計測の通信をブラウザが捨てた分が、画像の読み込みの失敗（`IMAGE_LOAD_FAILED`）として全ページに出ることがあります。
- **`/favicon.ico` で終わる URL**: Guard の付いた環境では、URL が `/favicon.ico` で終わる要求（ページの画像を含む）を、Playwright が黙って止めます。その画像は、スクリーンショットで壊れて見えることがあります。
- **止めた移動の後の画面**: Guard が許可 Origin の外への main frame の移動を止めると、エラーの画面が確定し、元の DOM が消えることがあります。認証つきの監査で、読み込みの後にフォームを送る画面を Guard が止めた後、その画面の読み取りが `PARTIAL` になったことが 1 回ありました。
- **ページの JS による証拠の偽り**: DOM・色・レイアウトの Evidence、スクロール、リンクの抽出は、ページの JS と同じ世界（main world）で読みます。ページの JS が結果を偽れます（公開の監査の Evidence は、もともとページ自身が中身を決めるものです）。操作の候補の発見の読み取りとログインのフォームの確かめは、ページの JS から切り離した読み取り（isolated world）で行います。
- **DOM の上書き**: form や document の名前つきの子で標準の読み方が上書きされたページでは、アクセシビリティの Evidence が `PARTIAL` になることがあります（依存のライブラリの中）。自動ログインの成功と失敗の条件のセレクタは、当たらないとして扱われることがあります（成功を誤って認めない側）。
- **時間の計測値**: 出口の中継を通るので、時間の値は中継の分だけ遅く出ます（「[出口の中継と計測値](safety.md#出口の中継と計測値)」）。

### 書き込みとログイン

- **送る直前の確かめ直しの後の撤回**: 確かめ直しの答えを受けてから要求が届くまでの短い間（テスト用のサイトで 0.07〜0.28 秒）に撤回すると、送ります（「[確かめていないこと](approved-create.md#確かめていないこと使えないこと)」）。
- **名前だけを照らす欄**: CSRF のトークンなど、ページが作る値の名前の閉じた一覧に当たる欄は、値を照らしません。ページの JS がその値を書き換えても見つけられません。
- **ログインの送信の送り直し**: 自動ログインの送信は、ブラウザが送ります。応答の前に接続が切れると、ブラウザが同じ送信をもう一度送ることがあります。BeakSight は、その回を 2 回と数えます（「[ログインの送信の回数と上限](automated-login.md#ログインの送信の回数と上限)」）。
- **ログインの段のポップアップからの送信**: スクリプトで送るログインで、ページが空のポップアップ（`about:blank`）から送信すると、サーバに届かないのに token の送信の回数を使い、ログインが回数の上限で終わることがあります（届かない側です。「[ログインの結果と、止めた送信の見方](authenticated-audit.md#ログインの結果と止めた送信の見方)」）。
- **ログインの段で止めた送信の表のパス**: 値に見える区切りとメールアドレスの形は伏せますが、短い値などは伏せられません（同じ節）。
- **スクリプトで送るログインの監査で通す呼び出し**: 監査の段で通す「読み取りの手続きの呼び出し」（`POST`）は、読むだけかどうかを利用者が判断して登録します。BeakSight は、その本文を照らしません（「[スクリプトで送るログインの後の監査](authenticated-audit.md#スクリプトで送るログインの後の監査)」）。
- **幅の走査の API のデータ**: スクリプトで送るログインの監査の幅の走査と Interaction の読み込みでは、承認したサービスの Origin へ要求を送らないので、API のデータが空のまま表示されることがあります。
- **読む範囲の外の、スクリプトの形のデータ**: スクリプトで送るログインの監査では、読む範囲の外でも、`<script src>` の形で返るデータ（JSONP など）と、`preload`・`modulepreload` の読み込みが届きます（「[スクリプトで送るログインの後の監査](authenticated-audit.md#スクリプトで送るログインの後の監査)」）。
- **サービスの Origin への要求の数**: `run.json` の `load.approvedServiceOrigins` は、本文を読まない応答を数えないことがあり、少なく出ることがあります（上限には影響しない見込み。推測）。
- **サービスの Origin への要求の上限と再開**: 強制終了の後の再開では、最大でページ 1 つ分だけ Run の全体の上限を超えることがあります。再開のための保存を別の道具で書き換えると、「上限に届いた」印を消せてしまいます（守りの範囲の外）。
- **サービスの Origin の URL の伏せ方の限界**: scheme のない `//ホスト/…` の形、許可 Origin の URL の query に percent-encode で入った URL、名前の形の path の区切り、数字の ID と UUID は伏せません（「[スクリプトで送るログインの後の監査](authenticated-audit.md#スクリプトで送るログインの後の監査)」）。
- **報告の入れ替え**: 書き込みの報告は、締めのときに確かめます。締めた後に Run のディレクトリの `action-report.html` と書き込みのバンドルを入れ替えると、入れ替えた後のファイルが画面から配られます（「[報告を配らない場合](output.md#報告を配らない場合)」）。
- **サーバの側の通知**: 登録や更新を契機にしたメールや SMS は、BeakSight からは確かめられません。副作用の確認と、テスト環境の証跡に頼ります。

## 安全の保証の範囲

| 保証すること | 根拠と範囲 |
| --- | --- |
| 公開の監査と認証つきの監査は、ページを観測する段階で `GET` と `HEAD` だけを送ります。 | Guard の CDP の横取りと route、出口の中継（「[読み取り専用の保証の範囲](safety.md#読み取り専用の保証の範囲)」）。保証できない範囲も同じ節にあります。 |
| 書き込みは、承認された形の `POST` を、1 回の Run で 1 件、BeakSight が 1 回だけ送ります。削除（DELETE）は送りません。自動の再試行はしません。 | 書き込みの段の Guard、送る中身の照合、送る直前の確かめ直し、実行の許可と予約（「[守りの範囲](approved-create.md#守りの範囲)」）。 |
| 本番には書き込みません。 | 書き込みは `TEST_APPROVED_WRITE`（環境 `TEST`、環境の証跡の参照が必須）のプロファイルだけです。ただし、テスト環境かどうかは、人が入れた記録の参照に頼ります。BeakSight は参照の中身を読まないので、隔離が未確認であることを示す参照でも、書き込みの許可を拒みません。書き込みに進む前の隔離の扱いは、人が判断します（「[実テスト環境の手順](real-test-environment.md)」）。BeakSight は、URL の名前だけでテスト環境と見なしません。 |
| 秘密を保存しません。 | 資格情報（自動ログインは DPAPI で暗号化して `local/secrets/` だけ）、Cookie、localStorage、CSRF のトークン、hidden の値は、成果物・管理データ・ログ・ワーカーとの通信に残しません（目印の検査で確かめています）。 |
| サイトへの負荷の上限を守ります。 | 読み込みの間隔、ページの上限、同時に 1 つ、書き込みの連続の上限（5 分の間隔、24 時間に 5 件）、自動ログインの上限（5 分の間隔、24 時間に 10 回）。 |
| 成功と偽りません。 | 結果が分からない回は `UNKNOWN` とし、件数は使ったものとして数えます。 |

## 確かめていないこと

- **実際のテスト環境**: 認証つきの監査、自動ログイン、操作の候補の発見、READ の確かめ、書き込みは、テスト用の小さなサイトだけで確かめています（「[実テスト環境の手順](real-test-environment.md)」）。
- **対応しないログイン**: 別の Origin のログインのサービス（IdP）、多要素認証（MFA）、画面の中のスクリプトで送るログイン、CAPTCHA。
- **HTTPS の証明書**: 書き込みの送り手は、Node の同梱の証明書と OS の証明書で確かめます。ブラウザ（Chromium）が、社内の CA の証明書をどう扱うかは確かめていません。
- **HTTP/2 だけを話すサイト**: 書き込みの要求を送れません。
- **ブラウザが自分で送る要求との違い**: 書き込みの要求は BeakSight の送り手が送るので、一部のヘッダや TLS の形がブラウザと違います。実際のテスト環境で、この違いでサイトの振る舞いが変わるかは確かめていません（「[登録の要求の送り方](approved-create.md#登録の要求の送り方)」）。
- **Windows 以外での動作**: 管理画面、認証つきの監査、書き込みを、Windows 以外で通して動かすことは確かめていません。自動ログインは Windows だけです。
- **headed での Chromium 自身の外部への接続**: headless だけで確かめています（「[Chromium 自身の Google への接続](safety.md#chromium-自身の-google-への接続)」）。
- 各段の文書の「確かめていないこと」も読んでください（[認証つきの監査](authenticated-audit.md#確かめていないこと)、[自動ログイン](automated-login.md#確かめていないこと残る危険)、[発見と READ](discovery-and-read-check.md#確かめていないこと使えないこと)、[シナリオ](scenario-approval.md#確かめていないこと使えないこと)、[入力の規則](data-rules.md#確かめていないこと使えないこと)、[登録](approved-create.md#確かめていないこと使えないこと)、[更新](approved-update.md#確かめていないこと使えないこと)）。
