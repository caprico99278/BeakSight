## 新しい指摘と、設計者の判断

- **I-1 / Important**: click の前にマウスが対象に乗ると、`:hover` の見た目の変化（transform、font-weight、padding）が、大きさの変化として VERIFIED の根拠になる。
- **I-2 / Important**: ボタンの中や同じ行の遅延読み込みの画像が、click の後に届くと、ボタンの大きさが変わり、VERIFIED になる。
- **設計者の判断（I-1・I-2）**: 対象の位置と大きさの変化は、click の結果かどうかを区別できない。そのため、方針を次のように改める（設計書 4.4.1）。F15 で実装する。
  - 対象の位置と大きさの変化だけでは、VERIFIED の根拠にしない。
  - 根拠にするのは、次の変化とする。
    - ARIA の状態の変化
    - 対象自身の属性の変化
    - `aria-controls` の先の表示の変化
    - 位置と大きさ以外の、既存の根拠
  - 凍結の前の下準備で、対象に hover しておき、hover した後の状態を「観測の前の状態」とする。
- **M-1**: 設計書は `aria-controls` の先の layout の変化を根拠に挙げているが、実装は表示の変化だけを見ている。
  - 判断: layout の変化は、遅延読み込みでも起きうる。そのため、実装に合わせて、設計書の記述を「表示の変化」に直す。
- **M-2**: 押すと対象の外（上）に内容を差し込むボタンが、NOT_VERIFIABLE になる。
  - 判断: 設計書 4.4.4 に、制約として明記する。
- **M-3**: `lifecycle.reason` と Ledger の記録の理由は、整形していない。512字で切り詰めてから制御文字を除くので、切れた ANSI の断片が残りうる。
