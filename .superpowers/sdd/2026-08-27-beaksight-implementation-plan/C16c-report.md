## 実装者の判断と、設計者の判断

1. `ArtifactWriter` の ID の検証が、以前より緩くなった。→ **承認しない。C16d で直す。**
   - 以前は、ASCII の ID の形だけを通していた。いまは、共通の区切り1つの規則になり、ID の形でない値（日本語、`_x` など）も通る。
   - 安全性（Run のディレクトリの外に書かない）は保たれている。しかし、指示書の「今の振る舞いを変えない」に反する。
   - 直し方:
     - ID の形の判定（`isRunId`、`isPageId`）を、ID の owner の `src/core/ids.ts` に置く。
     - `ArtifactWriter` は、その判定で確かめる。形の違う値は、以前と同じく `RangeError` にする。
2. 規則を厳しくしたことで、次の入力が拒まれるようになった。→ 承認する。
   - スクリーンショットの収集: NUL 以外の制御文字
   - バンドル: C1 の制御文字
   - 撮る側のパスは、ID と固定の名前から作られるので、実際には起きない。撮る側と読む側の規則がそろった。

## 発見事項と、設計者の判断

1. 共通の規則は、Windows の予約名（`CON` など）、末尾の `.` と空白、区切りの途中のコロン、Cf の文字、対になっていないサロゲートを拒まない。→ 今は直さない。
   - artifact のパスは、ID と固定の名前だけから作られる。そのため、これらは起きない。
   - 利用者が入れた文字列を、パスに使うことになった場合に、規則を見直す。この条件を、CC-027 に書いた。
2. 共通部品台帳と、CC-026・CC-027 の状態の更新。→ 設計者が行った。
