## 新しい指摘と、設計者の判断

- **I-1 / Important**: 押したときに、ripple が CSS の変数を style に残すと、何もしないボタンが VERIFIED になる。
  - 判断: style の変化が CSS のカスタムプロパティ（`--*`）だけの場合は、根拠にしない（設計書 4.4.1）。F18 で直す。
- **I-2 / Important**: 読み込みの時間が Interaction の期限に含まれるので、読み込みの遅いページでは、動くボタンが NOT_VERIFIABLE になる。
  - 判断: Interaction の期限は、読み込みと初期描画が終わってから数え始める。読み込みには、設定のナビゲーションの期限を使う（設計書 4.4.1）。F18 で直す。
- **M-1**: 1回だけ遅れて起きる変化（hover の600ms後、読み込みの1秒後、画面に入った700ms後）で、VERIFIED になりうる。
  - 判断: 制約として、設計書 4.4.4 に明記する。
- **M-2**: 属性の単位で比べているので、タイマーが別の class の名前を切り替えていると、トグルが NOT_VERIFIABLE になる。
  - 判断: class は、名前ごとに安定しているかを判定し、名前ごとに比べる。F18 で直す。
- **M-3**: LRM、RLM、ALM、孤立したサロゲートが、理由に残る。
  - 判断: F18 で取り除く。
- **M-4**: 文書と記録がずれている。また、`<details>` が開いたのか閉じたのかが Evidence に残らない。
  - 判断: 文書は設計者が直す。`<details>` の開閉の前後の値は、F18 で Evidence に残す。

## 収束のための方針（設計者）

- F18 の後の確認のレビューでは、Blocker として扱うものを次の2つに限る。
  - 設計書の方針に反する、明確な欠陥
  - 実際のサイトでよく起きる、偽の VERIFIED
- 本質的に見分けられない、まれな場合は、設計書 4.4.4 に制約として記録して受け入れる。
- 理由: 偽の NOT_VERIFIABLE は、正直な結果（確かめられなかった）である。偽の VERIFIED は、偽の完了にあたる。そこで、偽の VERIFIED を防ぐことを優先し、まれに残る偽の NOT_VERIFIABLE は受け入れる。
