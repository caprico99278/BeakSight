# RT12f 実装報告（要約。設計者が保存）

## 結論

I1・M1・M2 の修正とテストを終えた。どれも、修正前に RED、修正後に GREEN になった。layout の3つのテストファイルで、91件が PASS した。規模のテストは 140 ms と 243 ms だった。

`npm run verify` は、build の段階で失敗した。原因は、並行して作業中の P14a の途中の状態である。P14a は、`evidence-types.ts` の CC-014 と Ledger の型を変えている途中だった。

## 主な変更

- 見切れの判定で、上下と左右を片側ずつ比べるようにした。合計はしない。
- 見えない要素の中のテキストを、判定から除いた。見えるかどうかは、既存の `visibilityOptions`（`VISIBILITY_CHECK_OPTIONS`）で決める。
- 文書の左か上の外に置かれた子孫を、描画された子孫として数えないようにした。
- 1行の見出しの誤検知が直ったことを、fixture で確かめた。
  - Chromium の CDP で、見出しが Meiryo-Bold で描かれていることを確かめた。
  - 修正前は、上下の合計が行の高さの4分の1を超えるため、誤って報告される形である。

## 設計者の判断

- RT12f の指示書には、「単独で実行する」と書いた。しかし実際には、設計者が後から P14a を並行で起動した。これは、設計者の段取りの誤りである。
- verify は、P14a が終わった後に、設計者が実行し直して確かめる。
