## とくに確かめること

1. **リダイレクトを止める処理（C18g）**
   - Response stage の横取りを加えても、既存の判定が変わらないこと。
     - 許可 Origin、メソッド、リダイレクトの対応付け、`expectedCdpFailures`、凍結の後の `INTERACTION_FROZEN`
   - 応答の段階の判定の順と、fail-closed の分岐が、適切であること。
     - 解析できない `Location`、`failRequest` の失敗、`continueRequest` の失敗
   - 別のプロセスの iframe（OOPIF）と popup のページでも、横取りが働くこと。可能な範囲で確かめてください。
2. **main frame の違反を緩めた処理（C18g の A）**
   - 緩めた範囲が、Guard 自身が止めたリクエストの失敗だけに限られていること。
   - ほかの main frame の配送の失敗は、違反のままであること。
   - 照合の近似（同じ page、同じメソッドと URL、`net::ERR_BLOCKED_BY_CLIENT`、1回の消費、1秒の期限）で、本物の失敗を誤って見逃す経路がないこと。
3. **違反の後は監査を続けないこと（C18f）**
   - 違反の後に、新しいページ、ビューポート、幅、候補、再試行、metadata の取得のどれも、始まらないこと。
   - 対象のサイトへの新しいリクエストが、起きないこと。
   - 実際に確かめてください。例えば、違反を起こすページを複数持つ fixture のサイトで、headed を注入した Run を行う。
   - 始めなかったものの記録が、正直であること。
   - Run Status を決めるのが、`deriveRunStatus` だけであること。
4. **DEF-013（C18h）**
   - 遅いリダイレクト（1.5秒）で、偽の違反が出ないこと。
   - 対応付けの本当の欠落は、今までどおり違反になること。
   - 登録が無制限に増えないこと。
   - 期限の数え方を変えたことで、別の偽の違反や、見逃しが生まれていないこと。
5. **全体**
   - すべての Gate（S、A、ARCH、UI）が PASS すること。
   - 設計書 4.2.1 の表（止められる経路と、止められない経路）が、実装と合っていること。
